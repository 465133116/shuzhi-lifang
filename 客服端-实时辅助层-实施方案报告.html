1.3 核心设计原则

① 规则优先，渐进增强
V1 纯规则引擎（正则+关键词），V2 引入 NLP，V3 接入 LLM。规则引擎始终兜底。
② 无侵入集成
实时辅助层独立模块文件（realtime-assist.js），通过 BroadcastChannel 与客服端通信，不修改已有核心逻辑。
③ 降级安全
引擎不可用时→弹窗层静默关闭→客服照常工作。所有推荐均为"建议"而非"强制"。

#9 承诺意向判定 ▸ P0 催收闭环

承诺可信度评分模型

业主表达缴费意向
→ 多因子加权计算
维度权重评分规则
历史承诺兑现率35%兑现次数/总承诺次数×100
时间具体性25%"15号之前"=90分·"月底"=60分·"尽快"=30分
金额确定性15%"先交5000"=90分·"全部交清"=50分（无具体数）
当前情绪分15%平静=+15·激动=-10·愤怒=-25
画像匹配度10%C类"观望"→可信度×0.7·A类→×1.0

判定结果与动作

可信度标签系统动作
≥80高可信正常记录·7天查账·不移交
50-79需跟进标记"承诺待验"·客服备注具体日期
30-49低可信标记"可能失约"·建议约定更具体时间
<30敷衍不记录为有效承诺·继续推进

// ===== realtime-assist.js 核心结构 =====

class RealTimeAssist {
  constructor(ownerData) {
    this.owner = ownerData;         // D.o[oid]
    this.transcript = [];           // 语音转写文本序列
    this.emotionHistory = [];       // 情绪轨迹
    this.alerts = [];               // 已触发弹窗（去重用）
    this.timer = new CallTimer();      // 计时器
    this.judgers = [];              // 注册的7个判断模块
  }

  // 注册判断模块
  register(jugder) { this.judgers.push(jugder); }

  // 处理新语音片段（V1：文本输入）
  ingest(segment) {
    this.transcript.push({ t: Date.now(), text: segment });
    this.judgers.forEach(j => {
      const result = j.analyze(segment, this.owner, this.transcript);
      if (result?.alert) this.fireAlert(result);
    });
  }

  fireAlert(result) {
    // 去重检查（同类型15秒内不重复弹）
    if (this.alerts.some(a => a.type === result.type
      && Date.now() - a.time < 15000)) return;
    this.alerts.push({ type: result.type, time: Date.now() });
    AlertOverlay.show(result); // 弹出弹窗
  }

  finalize() {
    // 通话结束：回写日志+更新业主数据
    const summary = {
      duration: this.timer.elapsed(),
      emotionTrack: this.emotionHistory,
      alerts: this.alerts,
      topics: this.judgers.find(j=>j.name==='multiTopic')?.topics
    };
    this.writeBackToApp(summary);
    return summary;
  }
}

// ===== 判断器接口 =====
// 每个判断器实现：
//   { name, analyze(segment, ownerData, fullTranscript) → { alert?, result } }

const riskWarningJudger = {
  name: 'riskWarning',
  analyze(seg, owner, transcript) {
    const hits = KEYWORD_BANK.risk.filter(kw => seg.includes(kw.word));
    if (hits.length === 0) return null;
    const score = calculateRiskScore(hits, owner);
    if (score >= 50) {
      return {
        alert: true,
        type: 'risk',
        level: score >= 80 ? 'high' : 'medium',
        score,
        hits,
        suggestion: score >= 80
          ? '暂停催缴·转主管处理'
          : '谨慎沟通·保持录音'
      };
    }
    return null;
  }
};

七、风险与降级策略

风险影响降级策略
引擎崩溃/JS异常 中 try-catch包裹所有判断器；引擎失败→弹窗层关闭·客服正常通话不受影响
正则误判（假阳性） 低 弹窗均为"建议"非强制；客服可忽略；记录采纳/拒绝日志用于后续调优
关键词漏检（假阴性） 低 对话全文始终保留；通话结束后可回溯分析；V2 NLP升级自然降低漏检率
弹窗过多造成干扰 中 去重机制（同类型15秒内不重复弹）；同一通话同一模块最多弹窗3次
未引入真实语音转写 高 V1阶段使用文本输入框模拟转写；对接真实语音ASR列入V2计划

八、总结

P0 安全与合规底线
#6 风险预警 + #9 承诺判定 + #10 敏感词检测 是三条安全底线。不装好不上线。
三者如有遗漏 → 诉讼风险 · 失信滋长 · 舆情失控。
P1 效率与质量
#7 话术推荐 + #8 情绪识别 决定客服日均产能和沟通质量。
话术采纳率>60% → 新人也能快速上手。
P2 体验优化
#11 时长预警 + #12 多议题跟踪 提升通话效率和业主体验。
不阻塞核心流程，可后置上线。
📐 关键设计决策
1.V1纯规则引擎驱动（正则+关键词），不依赖外部NLP服务。零延迟、离线可用、成本为零。
2.弹窗是"建议"不是"命令"——客服始终有最终决策权。系统只辅助、不替代人。
3.V1语音转写用文本输入框模拟——待真实ASR方案确定后替换为WebSocket流式转写接口。
4.所有判定结果写回D.lg和D.o，不依赖外部服务——即使断网系统仍可运行。
5.引擎独立模块化——每个判断器实现统一接口，可独立测试、独立升级、按需启用。
6.承诺可信度评分同时影响业主分类（9号模块输出→反馈到A-F标签置信度微调）。
