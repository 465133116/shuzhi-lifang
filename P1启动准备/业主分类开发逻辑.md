# P1 业主分类开发逻辑

> **版本：** V4.0 | **编制：** 2026-06-26
> **核心变化：** 从单一分类改为"主分类+辅助维度"，解决业主身上同时存在多种信号的复杂场景。

---

## 一、分类结构

每个业主不是贴一个标签，而是挂一组信号：

```
业主 = 主分类（1个） + 辅助维度（0~3个） + 历史轨迹
```

| 层级 | 作用 | 决定什么 |
|------|------|------|
| **主分类** | 当前最该处理的事 | 客服策略方向（先解决问题还是先协商） |
| **辅助维度** | 完整画像 | 客服话术调整（态度软还是硬） |
| **历史轨迹** | 行为趋势 | 判断是变好还是变坏 |

---

## 二、六类信号定义

六类不是互斥的。一个业主可以同时产生多种信号。

| 信号 | 含义 | 怎么产生 |
|:--:|------|------|
| **A** | 有具体争议 | 小程序提交报修/投诉 或 客服建报修草稿 |
| **B** | 经济困难 | 通话中表达困难 |
| **C** | 未触达/已解决 | C·未触达=默认；C·已解决=A消除后等待反馈 |
| **D** | 承诺不兑现 | 多次通话说交但无行动 |
| **E** | 对抗态度 | 拒接>=3次 / 攻击性投诉 / 明确拒缴 |
| **F** | 情况特殊 | lb含"已搬家""产权变更""出租" |

---

## 三、主分类判定

**原则：取当前最该处理的信号作为主分类。**

### 判定表

| 有F信号 | 有其他信号 | 主分类 | 理由 |
|:--:|:--:|:--:|------|
| ✓ | 任意 | **F** | 情况特殊，先单独拎出来，其他信号暂挂 |
| ✗ | E | **E** | 对抗态度优先处理，不解决态度问题其他无从谈起 |
| ✗ | A | **A** | 有具体问题先解决问题，解决问题本身就是最好的催收 |
| ✗ | B+D | **B** | 困难+惯性并存 → 先协商，协商失败再走约束 |
| ✗ | B | **B** | — |
| ✗ | D | **D** | — |
| ✗ | 无 + 无A消除历史 | **C·未触达** | 兜底 |
| ✗ | 无 + 有A消除历史 | **C·已解决** | 问题已解决，等待反馈 |

**一句话：F > E > A > B > D > C·未触达。C·已解决是过渡态，优先级低于D但高于C·未触达。**

---

## 四、辅助维度

辅助维度 = 业主身上所有被检测到的信号，排除掉已经作为主分类的那个。

### 举例

| 场景 | 主分类 | 辅助维度 | 客服解读 |
|------|:--:|------|------|
| 业主报修水管 + 通话中说没钱 | A | B | "先解决水管问题，同时知道他经济困难，修完后协商分期" |
| 业主报修多次 + 承诺交但从未兑现 | A | D | "先解决问题，但要留痕——这人说过交但没交过" |
| 业主拒接3次 + 通话中说没钱 | E | B | "对抗为主，但知道他困难——话术可以带一句协商选项探探口风" |
| 业主什么信号都有：报修+困难+承诺不兑现 | A | B, D | "解决水管优先，经济困难和承诺不兑现都记着，问题解决后一起处理" |
| 业主已搬家 + 报修 | F | A | "情况特殊优先，报修信号暂挂——先搞清楚产权关系" |
| 业主无任何信号 | C·未触达 | — | "什么都没发生，观望" |
| A消除后无其他信号 | C·已解决 | — | "问题已解决，等待缴费反馈" |

### 辅助维度的作用

- **不决定主策略**——主策略只看主分类
- **调整话术软硬**——有E辅助时话术偏硬，有B辅助时偏软
- **信号积累**——B+D 积累到一定程度，主分类可能从A变为B（问题解决后）

## 五、信号开关规则

### 5.1 A信号：产生与消除

A信号代表"有具体问题要解决"。消除不是看评分，是看问题是否真正解决。

| 工单闭环结果 | A信号 | 理由 |
|------|:--:|------|
| 问题解决 + 满意度≥4星 | **消除** | 问题解决且业主满意 |
| 问题解决 + 满意度3星 | **消除** | 3星=一般，问题本身解决了，不算争议 |
| 差评1-2星·原因=问题没解决 | **保持** | 工单自动重开，A信号不消除 |
| 差评1-2星·原因=态度不好/太慢/其他 | **消除** | 问题解决了，过程不满意不改变A信号 |

**差评非"问题没解决"时**，A消除但产生一条负面记录：
- 态度不好 → 累计3次态度类差评 → 触发E信号
- 处理太慢 → D信号计数+1（承诺处理但延迟=另一种失约）

### 5.2 A消除后归属

A信号消除后重走判定流水线。业主归属取决于他身上还剩什么：

| A消除前状态 | A消除后主分类 | 逻辑 |
|------|:--:|------|
| 只有A，无其他信号 | **C·已解决** | 问题解决，等待后续行为反馈 |
| A + B（困难）| **B** | 问题解决但经济困难仍在 |
| A + D（惯性）| **D** | 问题解决但承诺未兑现记录还在 |
| A + B + D | **B** | B优先于D，先协商 |

### 5.3 C类拆分

原来的C（观望拖延）拆成两种：

| 细分 | 含义 | 触发 |
|------|------|------|
| **C·未触达** | 从未有过任何行为信号，纯默认 | 初始状态；无工单+无通话+无标签 |
| **C·已解决** | 之前A类争议已闭环≥3星，等待缴费反馈 | A消除后无B/D/E/F信号时 |

区分价值：C·已解决的业主刚经历过正面体验，客服话术应该跟C·未触达不同——"上次水管修好了吧？"vs"您好我们是XX小区物业"。

### 5.4 全部信号开关

| 信号 | 产生条件 | 消除条件 |
|------|------|------|
| A | 有未闭环的报修/投诉工单 | 问题解决（修后照片+处理结果）+满意度≥3星，或工单重开超3次升级业委会 |
| B | 最近一次通话 nt 含困难关键词 | 最近一次通话 nt 不含困难关键词（新通话覆盖旧） |
| C·未触达 | 无其他任何信号 | 出现任何其他信号 |
| C·已解决 | A消除且无B/D/E/F信号 | 出现新信号或超过60天无新行为 |
| D | 通话 rs=无争议 累计≥2次 | 业主小程序登录（li=true）→D消除（行为信号覆盖承诺信号） |
| E | 拒接≥3次/攻击性投诉/明确拒缴/态度差评≥3次 | 拒接：接通一次归零。攻击/拒缴：工单闭环后消除。态度：近30天<3次 |
| F | lb含"已搬家""产权变更""出租""继承" | lb被清除或修改 |

### 5.5 D信号衰减

D信号不是永久的。自D产生起：每7天无新通话→D降为辅助（可被A/B/E覆盖但不独立做主分类）。连续21天无变化→D消除。

### 5.6 信号独立开关

A信号消除不代表D信号消除。业主问题解决了（A消）但仍不缴费（D留）→主分类从A变为D。E信号消除不代表A信号消除。

## 六、重算时机

每次以下事件发生后，重新走一遍判定表：

| 事件 | 影响什么信号 |
|------|------|
| 业主提交小程序工单 | A 产生 / E 可能产生（攻击性投诉） |
| 客服建草稿 | A 产生（仅当无小程序工单时） |
| 客服打完电话写记录 | B 产生或消除 / D 计数累加 / E 计数累加 |
| 工单闭环+满意度>=4星 | A 消除 |
| 客服接通之前拒接的业主 | E 拒接计数归零 |
| 客服修改 lb | F 产生或消除 |

重算 = 重新检查所有信号 → 重新判定主分类 → 更新辅助维度。

## 八、实际场景走一遍

### 场景：一个业主的完整轨迹

```
Day 1  业主报修水管漏水
       → A信号产生，主分类=A，辅助=无
       客服看到：A·合理争议，先处理问题

Day 3  客服打电话，业主说"最近手头紧"
       → B信号产生。主分类仍是A（A>B），辅助=B
       客服看到：主=A，辅=B。解决问题同时心里有数

Day 7  水管修好，业主给5星
       → A信号消除。还剩B信号。主分类变为B。
       客服看到：主=B·现实困难。该协商分期了
       （如果此时无B信号→归C·已解决，等待缴费反馈）

Day 14 客服又打电话，业主说"下个月交"
       → B信号消除（新通话覆盖），D计数=1

Day 30 客服再打电话，业主又说"下个月交"
       → D计数=2，触发D信号。无B信号。主分类=D。
       客服看到：主=D·惯性失约。开始留痕约束。

Day 45 业主投诉"楼道垃圾没人管"（非攻击性）
       → A信号产生。主分类=A（A>D），辅助=D
       客服看到：主=A，辅=D。先解决垃圾问题，但知道这人惯性失约

Day 52 垃圾问题解决，4星
       → A消除。D仍存在。主分类=D。
```

**这就是多维分类的价值：业主在不同阶段主分类自动切换，但辅助维度保留完整画像，不会因为切换丢失信息。**

## 九、神经网络式细分（加权评分模型）

### 9.1 为什么需要加权

当前规则 F>E>A>B>D>C 在简单场景够用，但遇到这些情况就粗糙了：

- 业主报了1次修（A信号=是）vs 报了8次修（A信号还是=是）——同样归A，但紧急度完全不同
- 拒接2次（E信号=否）vs 拒接3次（E信号=是）——差1次就从C跳到E，一刀切
- 同时有B和D：当前规则 B+D→B。但B信号弱（通话中随口提了一句困难）和B信号强（提供了失业证明）应该不同

**解决思路：不是二值信号（是/否），而是连续分值（0~100）。每个分类独立打分，最高分当选，分差表示置信度。**

### 9.2 特征层：从原始数据提取12个特征

| 编号 | 特征 | 含义 | 来源 | 取值 |
|:--:|------|------|------|------|
| f1 | 报修工单数 | 有多少个报修工单 | 小程序工单+客服草稿 tp=baoxiu | 0~N |
| f2 | 投诉工单数 | 有多少个投诉工单 | 小程序工单 tp=tousu | 0~N |
| f3 | 未闭环工单数 | 还有多少工单没解决 | 工单 st≠done | 0~N |
| f4 | 工单满意度 | 已闭环工单的平均分 | 工单 rt 字段 | 0~5 |
| f5 | 攻击性投诉数 | 投诉描述含攻击关键词的次数 | 工单 de 文本匹配 | 0~N |
| f6 | 通话总次数 | 客服打了几次电话 | 沟通记录 tp=外呼 | 0~N |
| f7 | 拒接次数 | 打了不接的次数 | 沟通记录 rs=拒接 | 0~N |
| f8 | 无争议承诺次数 | 通话中说会交但不行动的 | 沟通记录 rs=无争议 | 0~N |
| f9 | 困难表达次数 | 通话中表达经济困难的 | 沟通记录 nt 文本匹配 | 0~N |
| f10 | 明确拒缴次数 | 通话中明确说不交的 | 沟通记录 nt 文本匹配 | 0~N |
| f11 | 小程序登录 | 是否登录过 | li 字段 | 0/1 |
| f12 | 特殊标签 | 有无F类标签 | lb 字段匹配 | 0/1 |

### 9.3 时间衰减

越久远的数据越不重要。每个特征值乘以衰减因子：

```
衰减因子 = e^(-天数/衰减周期)

衰减周期：
- 工单类（f1~f5）：30天——一个月前的报修不如上周的报修
- 通话类（f6~f10）：14天——两周前的态度不如昨天的态度
- 状态类（f11~f12）：不衰减
```

### 9.4 六类得分公式

每类满分100。权重设计原则：核心特征权重高，辅助特征权重低。

**A·合理争议 得分：**

```
Score_A = min(100, f3×40 + f1×15 + f2×20 - f4×10)

解释：
- 未闭环工单多→争议强（每个+40，2个未闭环=80分）
- 报修多→有需求（每个+15）
- 投诉多→争议烈度高（每个+20）
- 满意度高→争议在减弱（4星-40，5星-50）
- 上限100
```

**B·现实困难 得分：**

```
Score_B = min(100, f9×35 + (1-f11)×15)

解释：
- 困难表达次数是最强信号（每次+35）
- 从未登录小程序→触达能力差，困难可能性+15
```

**C·观望拖延 得分：**

```
Score_C = 100 - max(Score_A, Score_B, Score_D, Score_E)
if f12==1: Score_C = 0

解释：
- C是"剩余分"——其他分越高C越低
- 有F标签则C归零
- 最小值0
```

**D·惯性失约 得分：**

```
Score_D = min(100, f8×30 + (1-f11)×20 + 时间衰减加成)

解释：
- 无争议承诺次数是核心（每次+30）
- 不登录+20
- 时间衰减加成：上次通话距今越久，惯性越强（+0~20）
```

**E·对抗失信 得分：**

```
Score_E = min(100, f5×35 + f7×25 + f10×30)

解释：
- 攻击性投诉（每次+35）
- 拒接（每次+25，3次=75分）
- 明确拒缴（每次+30）
```

**F·历史复杂 得分：**

```
Score_F = f12×100

解释：
- 二值：有标签=100，无标签=0。F是独立通道，不和A-E竞争
```

### 9.5 分类输出

```
主分类 = argmax(Score_A, Score_B, Score_C, Score_D, Score_E, Score_F)
置信度 = 最高分 - 第二高分
```

| 置信度 | 含义 | 客服建议 |
|:--:|------|------|
| ≥30 | 高置信 | 按主分类策略执行 |
| 10~29 | 中置信 | 主分类策略+看一眼第二分类的话术提示 |
| <10 | 低置信 | 两类都有可能，优先选影响大的策略 |

### 9.6 细分等级

在同一主分类内，按得分再分三级：

| 等级 | 条件 | 含义 |
|:--:|------|------|
| **轻度** | 得分 1~40 | 信号刚出现，先观察 |
| **中度** | 得分 41~70 | 信号明确，需要行动 |
| **重度** | 得分 71~100 | 信号强烈，优先处理 |

### 9.7 示例对比

**业主甲**：报修3次、2次未闭环、满意度4.5

| 类别 | 得分 | 计算 |
|:--:|:--:|------|
| A | 2×40+3×15+0×20-4.5×10 = 80 | 未闭环2个=80分 |
| C | 100-80 = 20 | |
| 结果 | **A·重度争议** 置信30 | |

**业主乙**：报修1次已闭环5星、通话中随口说了一次困难

| 类别 | 得分 | 计算 |
|:--:|:--:|------|
| A | 0×40+1×15-5×10 = 0 | 没有未闭环，满意度高→0分 |
| B | 1×35+0 = 35 | |
| C | 100-35 = 65 | |
| 结果 | **C·观望** 置信30 | |

**旧规则会把业主乙归B（因为有困难信号），新规则归C——因为1次随口困难不足以构成B。这就是加权比二值信号精确的地方。**

### 9.8 规则vs加权：什么时候用哪个

| 阶段 | 推荐 | 原因 |
|------|------|------|
| P1 原型验证 | 规则模式（F>E>A>B>D>C） | 数据量小，规则够用，调权重是过度设计 |
| P1 后期（20+业主、100+工单） | 加权模式 | 需要区分"报了1次修"和"报了8次修" |
| P2 催收阶段 | 加权模式 | 分类直接关联催收策略，精度要求高 |

**当前实现建议**：规则模式做主干，加权模式做预留。`sigs()`返回二值信号，`score()`返回0~100分值。前端先用`sigs()`+`mcls()`，后端预留`score()`接口。

## 十、深层分析：分类问题的真实复杂度

### 10.1 我们到底在分什么

表面上在分"这个业主属于A-F哪一类"。但A-F本质上是对「为什么不缴费」的归因。而P1阶段系统**拿不到缴费数据**——所以实际上我们在做一件更困难的事：

**从行为信号推断缴费意图，再从意图映射到分类。**

```
可观测层              隐藏层               输出层
(有数据)             (无数据·需推断)       (策略)
                    
报修次数  ──→        满意度        ──→
投诉内容  ──→        缴费意愿      ──→     A-F分类 → 客服策略
通话态度  ──→        缴费能力      ──→
登录行为  ──→        信任度        ──→
拒接次数  ──→        沟通开放度    ──→
```

**问题在于：同一行为可以映射到完全不同的隐藏状态。**

| 行为 | 可能是 | 也可能是 |
|------|------|------|
| 提交报修 | 满意度低，希望物业改进（→A） | 用报修当借口拖延缴费（→D） |
| 说"会交" | 真的打算交（→C→已解决） | 每次都说但从不行动（→D） |
| 拒接电话 | 对抗物业（→E） | 没钱、不好意思接（→B） |
| 攻击性投诉 | 长期不满爆发（→E） | 刚经历了一次恶劣服务（→A，解决后就好了） |
| 什么都不做 | 观望中（→C） | 已经搬家了但系统不知道（→F） |

**这意味着：所有基于行为信号的分类都有推断错误的可能。当前规则和加权模型都没有量化这种不确定性。**

### 10.2 隐藏状态才是真正的分类维度

A-F不是独立存在的——它们是五个隐藏状态的不同组合模式：

| 隐藏状态 | 含义 | 怎么影响A-F |
|------|------|------|
| **满意度 S** | 对物业服务的满意程度（0~1） | S低→A或E；S高→C或D |
| **缴费意愿 W** | 主观上愿不愿意交（0~1） | W低→D或E；W高→A或B或C |
| **缴费能力 A** | 客观上有没有钱交（0~1） | A低→B；A高→C或D或E |
| **信任度 T** | 对平台/物业的信任（0~1） | T低→拒接、E；T高→通话畅通 |
| **沟通开放度 O** | 愿不愿意接电话/回应（0~1） | O低→拒接、未登录；O高→有通话记录 |

**A-F在这五个维度上的位置：**

```
        S(满意度)  W(意愿)  A(能力)  T(信任)  O(开放)
A·争议    ↓低      →中      —        →中      ↑高
B·困难    —        ↑高      ↓低      —        ↑高
C·观望    →中      →中      —        —        ↓低
D·惯性    →中      ↓低      ↑有      ↓低      ↓低
E·对抗    ↓低      ↓低      ↑有      ↓低      →中(拒接)
F·特殊    —        —        —        —        —
```

**C类的特殊性**：C不是"五个维度都中等"——C是"信息不足以判断"。C类业主可能是因为真的在观望，也可能是因为数据太少。这跟A/B/D/E有本质区别——后四类是有明确信号的推断，C是无信号的默认。

### 10.3 时间维度：轨迹比快照重要

只看到当前时刻的信号是不够的。两个业主当前都是A类，但：

| 业主 | 轨迹 | 含义 |
|------|------|------|
| C→A | 之前观望→突然报修 | 刚出问题，解决后大概率回C或变B |
| E→A | 对抗→转为报修 | 态度软化，是好事。解决后可能回E也可能好转 |
| D→A | 惯性失约→报修 | 可能是真有问题，也可能找新借口 |
| 一直是A | 持续争议 | 老问题没解决或新问题不断 |

**轨迹决定了同一个A类业主的预测方向完全不同。**

### 10.4 群体效应：邻居影响

一个业主的分类不应该孤立看待：

- 同楼栋3户以上是A类 → 可能是楼栋级的问题（电梯坏了、水管老化）→ 这3户应该合并处理
- 同楼栋出现1户E类 → 需要关注是否会传染。历史上E类业主在群里抱怨会导致C类向D/E迁移
- 同小区A类突然减少 → 可能是物业改善的正面信号，也可能只是A类转成了D/E

### 10.5 分类应该输出什么

基于以上分析，分类不应该只输出一个A-F标签。应该输出一个**分类报告**：

```
业主张建国的分类报告：

┌─ 当前分类 ────────────────────────┐
│ 主分类：A·合理争议（置信度：高）     │
│ 细分等级：中度（Score_A=55）        │
│ 第二可能：C·观望（Score_C=45）      │
│ 风险：低——有向C迁移趋势             │
└──────────────────────────────────┘

┌─ 隐藏状态估计 ────────────────────┐
│ 满意度 S：0.3（低·有未解决报修）     │
│ 缴费意愿 W：0.5（中·通话态度中性）   │
│ 缴费能力 A：0.7（高·无困难信号）     │
│ 信任度 T：0.6（中·接通率正常）       │
│ 沟通开放度 O：0.8（高·已登录已通话） │
└──────────────────────────────────┘

┌─ 轨迹分析 ────────────────────────┐
│ 近3次分类：C→C→A                  │
│ 趋势：突然恶化（想修东西）           │
│ 预测：问题解决后→C（85%）或B（15%） │
│ 邻居参考：同楼栋无其他A类            │
└──────────────────────────────────┘

┌─ 推荐策略 ────────────────────────┐
│ 优先级：2/5（中等）                 │
│ 方向：先解决问题（#1006水管漏水）     │
│ 话术：中性偏友好。问题解决后试探缴费意向│
│ 时效：3天内跟进工单进度              │
│ 如果3天后无进展→升级优先级至4/5      │
└──────────────────────────────────┘
```

### 10.6 实施路径

当前P1做不到完整的隐藏状态推断——数据量和计算能力都不够。但架构上应该分层设计：

```
Layer 1: 信号检测层（已实现）
  输入：原始数据（工单、通话、标签）
  输出：12个特征值 + 二值信号
  → 当前 sigs() 函数

Layer 2: 状态推断层（P1后期）
  输入：特征值 + 历史轨迹 + 时间衰减
  输出：五个隐藏状态估值 + A-F得分
  → 新增 infer() 函数

Layer 3: 策略推荐层（P2）
  输入：隐藏状态 + A-F分类 + 置信度 + 群体数据
  输出：优先级 + 话术方向 + 时效建议
  → 新增 recommend() 函数
```

**P1现在做Layer 1就够了。** Layer 2和3留接口，等数据积累到50+业主、200+工单后再激活。但文档里把三层都写清楚，开发的时候数据结构预留好——比如owner对象预留 `s_score` `w_score` `a_score` `t_score` `o_score` 五个字段，先填null，等Layer 2上线后计算填入。
