# 业主画像开发逻辑

> **版本：** V7.0 | **编制：** 2026-06-26
> **来源：** 八轮圆桌会议共识 + 真实业主反馈 + 合规审查
> **适用范围：** P1 纯工单阶段

---

## 一、客服工作定义

**数治理方客服在P1只做四件事，不介入工单处理过程，不涉及催收。**

| 动作 | 说明 |
|------|------|
| 引流 | 引导业主使用小程序，了解平台功能 |
| 确认需求 | 听业主诉求，判断投诉/建议/报修，确认具体内容 |
| 提交草稿 | 选标签→补描述→推送业主确认→生成正式工单 |
| 回访 | 物业提交结果后联系业主验收、打分、挖掘新需求 |

客服在两个节点介入：起点（外呼建草稿）和终点（回访验收）。工单提交后系统自动接单并计时，物业处理期间客服不介入。

---

## 二、画像结构

```
业主画像 = 摘要（列表·5字段） + 详情（弹窗·全展开）

摘要 → 客服扫一眼决定先打给谁、说什么
详情 → 点进去看完整推断过程
```

### 2.1 三层数据

| 层级 | 含义 | 举例 |
|:--:|------|------|
| 事实层 | 原始数据，不加工不推断 | 报修3次、满意度4.2、通话5次 |
| 推断层 | 从事实计算，带置信度 | A·报修型（置信85%）、优先级75 |
| 策略层 | 从推断映射到动作，P1后期 | 话术方向、时效建议 |

### 2.2 画像聚合

| 层级 | 对象 | 谁用 |
|:--:|------|------|
| 单户画像 | 一个业主 | 客服打电话 |
| 楼栋画像 | 一栋楼汇总 | 管家+经理找共性问题 |
| 小区画像 | 整个小区趋势 | 经理+业委会决策 |

## 三、分类与优先级分离

**A-F管话术方向，优先级分管拨打顺序。**

```
优先级分 = 紧急度 + 恶化风险 + 影响力（三项各自封顶）

紧急度   = min(40, 未闭环数×15 + 超时数×20)
恶化风险 = min(35, 超SLA×50% +15 + 攻击信号+15 + 轨迹下降+10 - 好评抵消-10)
影响力   = min(25, 群活跃+15 + 公区投诉+10)
```

列表默认按优先级分降序。分变化时标记"↓已降低"，不自动跳位置，客服手动刷新后重排。

## 四、第零层 · 身份确认

任何分类之前先确认角色。角色错了，画像全错。

| 字段 | 取值 | 来源 |
|------|------|------|
| role | 业主/家属/租客/未知 | AI判断+客服标注+管家反馈 |
| decision_power | 直接/间接/无 | 角色推导 |
| influence_scope | 楼栋级/小区级/个体 | 管家反馈+客服标注 |

**角色决定画像路径：**
- 业主 → 完整画像（A-F+四层）
- 家属 → 简化画像（只记行为，追问房主联系方式）
- 租客 → 居住者画像（不催费，只记报修体验）
- 未知 → 不分类，打确认电话核实身份

## 五、A-F六类

F > E > A > B > D > C。每个信号独立开关，独立时间衰减（工单类30天、通话类14天半衰期）。

### 5.1 总表

| 分类 | 含义 | 子类型 |
|:--:|------|------|
| **A** | 有具体争议 | 报修型 / 投诉型 / 混合型 / 反复型 |
| **B** | 经济困难 | B1自述(仅辅助) / B2反复 / B3可验证 |
| **C** | 无明确信号 | 未触达 / 已解决 / 沉睡(>30天) |
| **D** | 承诺不兑现 | — |
| **E** | 对抗态度 | — |
| **F** | 无法服务 | 号码无效 / 未覆盖 / lb含特殊关键词 |

### 5.2 A类子类型（按工单结构）

| 工单结构 | 子类型 | 策略 |
|------|:--:|------|
| 报修≥1，投诉=0 | A·报修型 | 等待物业处理，待验收时联系业主回访 |
| 投诉≥1，报修=0 | A·投诉型 | 联系业主了解投诉内容 |
| 报修≥1，投诉≥1 | A·混合型 | 确认投诉内容后等物业处理，待验收时回访 |
| 同问题≥3次 | A·反复型 | 回访时重点询问是否彻底解决，记录反复原因 |
| 建议≥1，报修=投诉=0 | 不归A | 归C·已解决+标记积极参与 |

### 5.3 B类分层

| 等级 | 证据 | 独立做主分类 |
|:--:|------|:--:|
| B1·自述 | 通话中说过一次困难 | 否，仅辅助 |
| B2·反复 | ≥2次困难表达 | 是 |
| B3·可验证 | 提供证明文件 | 是 |

### 5.4 C类细分

| 细分 | 触发 | >30天 |
|:--:|------|:--:|
| C·未触达 | 无任何信号 | →C·沉睡，触发确认电话 |
| C·已解决 | A消除后无其他信号 | — |

### 5.5 A类消除条件

| 工单闭环 | A信号 | 副作用 |
|------|:--:|------|
| 修后照片+结果+满意度≥3 | 消除 | — |
| 差评·问题没解决 | 保持，工单重开 | — |
| 差评·态度不好 | 消除 | 态度差评+1，累计3→E |
| 差评·太慢 | 消除 | D计数+1 |
| 修后照片缺失 | 保持 | 证据不完整 |

### 5.6 E类降级路径

| 路径 | 条件 |
|------|------|
| 时间驱动 | 连续60天无新攻击+拒接归零→C·沉睡 |
| 行为驱动 | 接通+态度软化→A或C / 提交非攻击性报修→A·报修型 / 登录小程序→C·已解决 |
| 客服手动 | 通话后判断态度软化→手动覆盖 |

### 5.7 辅助维度

非主分类信号保留为辅助，灰色展示。不决定主策略，调整话术软硬。客服手动覆盖的分类系统不自动覆盖。

## 六、信号系统

### 6.1 六信号检测

A=有未闭环报修/投诉工单。B=通话含困难关键词。C=无其他信号时的默认。D=无争议承诺≥2次。E=拒接≥3次/攻击投诉/明确拒缴/态度差评≥3次。F=第零层不通过或lb含特殊关键词。

**拒接修正：** 拒接有效计数 = 拒接次数 - min(拒接次数, 小程序工单数)。有工单行为→拒接不完全算对抗。

### 6.2 特殊信号

| 信号 | 触发 | 含义 |
|------|------|------|
| 信心流失 | 满意度5→4→3连续下降 | A·反复型风险 |
| 渠道不一致 | 电话温和+小程序攻击 | A·混合型 |
| 承载力超限 | A类超过物业维修上限 | 超时不归责物业（P2） |

## 七、分类验证

客服每次通话后弹侧边浮层：

```
系统分类：A·报修型
○ 确认  ○ 质疑（实际是___）  ○ 跳过
```

质疑→置信度降低+自动重算。连续3次质疑→人工复核。准确率=确认/(确认+质疑)，<70%调整规则权重。

---

## 八、辅助信息来源

**管家反馈：** 客服端侧边栏三选一录入——[异常事件]/[业主动态]/[风险预警]，一句话+来源。归入沟通记录表，分类系统读取关键词。

**小区基线：** 每个小区独立算均值+标准差。凌晨预计算，白天缓存。P1直接做。

**合同履约对照：** 系统比对合同SLA与实际履约，业委会端展示达标率（P2）。

## 九、摘要五字段（列表展示）

```
┌────────────────────────────────────────────┐
│ 张建国 先生  3-1502         优先级 85 [拨号] │
│ A·报修型  紧急·2单未闭环  06-25水管漏水      │
│ → 等待物业处理结果，待验收时回访                  │
│ +B困难 · 报修3次 · 通话3次                   │
└────────────────────────────────────────────┘
```

| 字段 | 说明 |
|------|------|
| priority | 优先级分，列表按此降序 |
| main_class+sub_type | 主分类+子类型，决定话术方向 |
| urgent_flag | 触发条件：未闭环≥2 或 超时 或 恶化中 |
| last_event | 最近影响分类的事件 |
| suggested_action | 一行建议 |

辅助行（灰色）：辅助维度+统计。

**suggested_action 按工单状态动态生成：**

| 工单状态 | 建议动作 |
|------|------|
| 待处理/处理中 | 等待物业处理，待验收时回访 |
| 待验收 | 联系业主通知验收、引导打分 |
| 已完成 | 无待处理事项 |

## 十二、技术约束

| 约束 | 方案 |
|------|------|
| 事件触发重算 | 后台异步→前端增量更新单行，不重绘整页 |
| 优先级排序 | 惰性排序，变化标记不自动跳位 |
| 小区基线 | 凌晨预计算+缓存 |
| 数据一致性 | 业主端物业端同源，每项可追溯工单号 |
