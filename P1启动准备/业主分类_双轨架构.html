📊 业主分类 · 双轨架构

小程序轨道 + 客服轨道 → 独立计算 → 统一输出
小程序 看业主做了什么
工单行为 · 登录行为 · 满意度
数据源：小程序埋点 + 工单系统
衰减周期：30天半衰
客服 看业主说了什么
通话态度 · 承诺行为 · 关键词检测
数据源：客服通话记录 + 文本分析
衰减周期：14天半衰

📱 示例
业主在小程序提交了"水管漏水"报修 (tp=baoxiu, st=pending) → A信号产生

→ 子类型关键词（OR匹配，任意命中）

🎧 示例
客服外呼，业主说"最近手头紧，失业了" → nt含困难关键词 → B信号产生
下次通话业主说"下个月一定交" → rs=无争议 → D计数+1，新通话覆盖旧nt → B消除
再下次拒接 → rs=拒接，累计→ E计数+1
▼ ▼ ▼
两条轨道各自算出信号后，信号合并（取OR逻辑，任一轨道产生=信号on）
⚙️ 统一分类引擎：信号合并 → 主分类判定 → 完整画像输出
▸ 第一步：信号合并（两轨道取OR）
信号小程序可产生客服可产生合并逻辑
F — lb含特殊关键词 仅客服轨道。独立通道，有则直接主分类=F
E 攻击性投诉工单 / 态度差评≥3 拒接≥3 / 明确拒缴 / 攻击通话 OR：任一轨道触发即E=on
小程序攻击投诉→E2；客服攻击通话→E2
合并后按E1~E4细分规则归类
A 未闭环报修/投诉工单 客服建草稿(当无小程序工单时) OR：任一轨道有未闭环即A=on
小程序工单优先，客服草稿补充
B — nt含困难关键词 仅客服轨道。新通话覆盖旧通话
D — rs=无争议，有效计数≥2 仅客服轨道。但小程序登录(li=true)可消除D
C1 — nt含从众关键词 仅客服轨道。语音检测匹配
C2 — nt含拖延关键词 仅客服轨道。语音检测匹配
C3 — nt含对比关键词 仅客服轨道。语音检测匹配
C4 历史rt<3 且 无tousu nt含不满关键词 且 无投诉工单 OR：任一轨道触发即C4
但都要求"无正式投诉工单"(小程序验证)
C5 A消除后自动产生 — 仅小程序轨道触发
C6 两轨道均无任何信号 → 兜底默认 无信号时的最终兜底
▸ 第二步：主分类判定（合并后的信号走流水线）
F > E > A > B > D > C
命中即停。取最高优先级有信号者为主分类，其余转为辅助信号
▸ 第三步：计算信号强度（两轨道各自贡献加权）
信号小程序贡献客服贡献合并强度 = 小程序分 + 客服分（各自衰减后相加，上限100）
A强度未闭环数×40 + 报修数×15 + 投诉数×20 − 满意度×10客服草稿数×20（权重低于小程序工单）
B强度—困难表达次数×35 + (1−li)×15
D强度—有效计数×30 + (1−li)×20
E强度攻击投诉×35 + 态度差评×20拒接×25 + 明确拒缴×30 + 攻击通话×35

📱 小程序轨道：报修水管漏水(st=pending) → A=on · 登录过(li=true) · 历史满意度4.5
🎧 客服轨道：通话中表达困难("手头紧") → B=on · 无拒接 · 无无争议承诺

→ 信号合并：{A:on, B:on, ...}
→ 主分类判定：A > B → A·报修型（主），B（辅）
→ 交叉模式：争议+困难 — 提示客服"先修水管，再协商费用"
→ 响应级别：R2·常规（A仅1个未闭环，不紧急）

——此例中A来自小程序，B来自客服，两条轨道互不干扰但共同构成完整画像。 如果只看小程序会漏掉"业主经济困难"这个关键信息； 如果只看客服会漏掉"业主有未解决工单"这个更紧急的问题。 双轨合并才能看到全貌。
