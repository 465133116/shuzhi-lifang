# 业主标签体系 V9.0 · 开发规格书

> 数治理方 P1 · 2026-08-05
> 核心设计：六类大标签 = AI根据沟通内容综合分类。每个标签内含两个完全独立的维度分数。
> AI评分只回答"能不能还"——接了看沟通，没接看拒接模式。客服感受分是纯人的判断。

---

## 一、体系总览

| 维度 | 说明 | 取值 | 关系 |
|------|------|:--:|------|
| 大标签 | AI根据小程序工单+客服通话内容，综合分析后分类 | F/E/A/B/D/C | — |
| AI评分 | 系统计算，只看接没接：接了分析沟通内容，没接看拒接模式 | 1-100 | 与感受分**完全独立** |
| 客服感受分 | 每次通话结束客服手动选纯数字，捕捉沟通情绪 | 1-5 | 与AI评分**完全独立** |

**三个维度关系：** 大标签回答"处于什么状态"，AI评分回答"还款可能性多大"，客服感受分回答"沟通氛围如何"。**AI评分和客服感受分互不影响、各自计算。**

---

## 二、数据模型

### 2.1 业主标签结构

```
业主标签 = {
  大标签: "F"|"E"|"A"|"B"|"D"|"C",   // AI根据沟通内容综合判定
  AI评分: 1-100,                        // 接了→分析沟通内容; 没接→看拒接模式
  客服感受分: 1-5|null,                 // 纯主观，与AI评分完全独立
  分类依据: string,                     // AI分类时提取的关键信息摘要
  最近更新: DateTime
}
```

## 三、大标签分类机制（AI驱动）

### 3.1 核心原则

大标签不使用硬编码事件规则，由AI根据业主的沟通内容综合判断：

- **数据输入**：小程序工单数据 + 客服通话记录（rs/nt）
- **A类特殊**：同时受小程序工单状态影响——存在未闭环工单即可触发A类判定
- **F/E/B/D/C**：主要通过客服通话中AI分析沟通内容来分类

### 3.2 六类标签定义

| 标签 | 名称 | AI识别模式 | 数据源 |
|:--:|------|-----------|--------|
| F | 历史复杂型 | 号码无效、已搬家、出租、失联、产权纠纷——客观上无法触达或无缴费主体 | 客服(lb标注) |
| E | 对抗失信型 | 明确拒绝沟通/缴费，辱骂、威胁、反复拒接——主观对抗 | 客服(nt/rs) |
| A | 合理争议型 | 存在未闭环报修/投诉工单——因服务问题未解决而不缴费 | 小程序(st/tp) + 客服(nt) |
| B | 现实困难型 | 自述经济困难（失业/生病/低保等）——非恶意，能力问题 | 客服(nt) |
| D | 惯性失约型 | 沟通中答应但不履约，无实质争议但反复拖延——态度配合但行为不一致 | 客服(rs/nt) |
| C | 观望拖延型 | 无明确抗拒也无明确困难，从众等待——信息不足或态度不明 | 客服(nt) |

### 3.3 分类流程

```
通话结束 / 小程序工单状态变更
  ↓
AI读取：通话记录(rs, nt) + 小程序工单(st, tp) + lb标签
  ↓
AI综合分析沟通内容 → 判定大标签 F/E/A/B/D/C
  ↓
AI评分计算（独立通道）        客服手动录入感受分（独立通道）
  ↓                              ↓
接了→分析nt内容              纯数字1-5
没接→看拒接模式              存入D.s[].cs_feel
  ↓
输出：{ 大标签, AI评分, 客服感受分, 分类依据 }
```

## 四、维度一：AI评分（1-100）—— 仅已接通时评分

> AI评分的前提：**必须接通**。AI分析通话内容（nt），判断还款倾向。没接通不评分。

### 4.1 评分条件

| 通话结果 | AI评分 | 说明 |
|---------|:-----:|------|
| 已接通 | **1-100** | AI分析nt内容，判断还款倾向 |
| 拒接/未接 | **不评分** | 无沟通内容，AI不猜测 |

### 4.2 已接通时AI分析维度

AI分析 nt（通话备注/语音转文字）内容，从以下维度综合判断：

| 维度 | 低分信号（还款可能性低） | 高分信号（还款可能性高） |
|------|----------------------|----------------------|
| 还款态度 | "不交""随便""再说" | "我会交""怎么交""分期可以吗" |
| 问题性质 | 无理由拒缴 | 自述困难/有具体争议 |
| 沟通配合度 | 敷衍、挂断倾向 | 主动提供信息、询问解决方案 |
| 历史验证 | 多次答应未履约 | 有工单闭环记录+好评 |

**评分逻辑（AI自主判断，非硬编码）：**

```
已接通 → AI分析nt内容 → 综合判断还款倾向 → 输出1-100
```

基准分50。AI根据对话中捕捉到的信号自主加权，不设固定加减分表。

nt内容过短/信息不足时：保持基准分50，标记"信息不足，需再次触达"。

### 4.3 重算触发

- 每次接通后 → AI评分重新计算
- 工单状态变更 → 影响"历史验证"维度
- 未接通 → 不触发重算

### 4.4 分数区间与还款倾向对照

| 区间 | 还款倾向 | 释义 |
|:---:|----------|------|
| 81-100 | 极大概率还款 | 沟通中表现出积极意愿，有履约历史 |
| 61-80 | 较大概率还款 | 无明显负面信号，态度中性偏正面 |
| 41-60 | 还款倾向不明 | 信息不足或信号混合 |
| 21-40 | 还款可能性低 | 沟通中表现消极，回避还款话题 |
| 1-20 | 几乎不可能还款 | 明确拒缴、对抗态度 |

## 五、维度二：客服感受分（1-5）

### 5.1 与AI评分的关系

**完全独立。两个分数各自计算，互不影响。**

| | AI评分 | 客服感受分 |
|------|--------|----------|
| 谁算 | 系统 | 客服 |
| 看什么 | 接没接+沟通内容/拒接模式 | 通话中的主观感受 |
| 回答什么 | 还款可能性多大 | 沟通氛围如何 |
| 互相影响 | — | — |

**为什么分开：** AI看的是"逻辑"——拒接几次、说了什么。客服感受到的是"温度"——语气、态度、话外之音。两者可能矛盾（态度好但一直拒接、态度差但数据好），分开记录才能让下一个客服看到完整画面。

### 5.2 五档定义（纯数字，无文字描述）

| 分值 | 典型表现 |
|:---:|---------|
| 1 | 辱骂、威胁、直接挂断、"再打报警" |
| 2 | 冷淡、敷衍、"再说吧""不方便" |
| 3 | 愿意听但无态度、"嗯""你继续说" |
| 4 | 提供信息、接受建议、"好的我看看" |
| 5 | 主动配合、表达谢意、"谢谢你提醒" |

### 5.3 采集流程

```
通话结束 → 客服选rs → 弹窗"本次沟通感受？[1][2][3][4][5]" → 必选 → 存入D.s[].cs_feel
```

- 必选不可跳过
- 默认不预设
- 当日24:00前可修改
- 历史感受分随通话记录永久保留
- **不对AI评分产生任何影响**
