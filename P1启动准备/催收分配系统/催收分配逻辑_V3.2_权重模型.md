# 催收分配逻辑 V3.2 · 权重分配模型

> 版本：V3.2 ｜ 日期：2026-08-25 ｜ 状态：定稿待开发（六轮圆桌会议37项决议已并入）
> 适用范围：个信催收端 · 每周债权分配
> 模型结构：**二维——金额分档定配额，档内六因子加性权重定顺序**

---

## 一、模型总览

```
第一维（层间）：金额分档 → 决定每档火力配额（大额档配额大）
第二维（档内）：六因子加性 score → 决定同档内谁先打
```

**设计哲学**：金额决定上哪张桌，权重决定桌上谁先动筷子。
标签、AI 评价、感受分等因子在档内充分竞争，不再与金额硬拼——金额跨度 35 万倍会把乘性模型下的其他因子全部稀释。

---

## 二、第一维 · 金额分档（定配额）

按金额分位数切 4 档，配额比例沿用 V9 设计（30:40:35:20 → 24:32:28:16）：

| 档 | 定义 | 金额范围(真实数据) | 每周配额/人 | 5人合计/周 |
|----|------|-------------------|------------|-----------|
| 档1 超大额 | top 10% | ≥ 10,613 | 62 | 310 |
| 档2 大额 | top 11-30% | 3,816 ~ 10,613 | 83 | 415 |
| 档3 中额 | top 31-55% | 1,493 ~ 3,816 | 73 | 365 |
| 档4 小额 | bottom 45% | < 1,493 | 42 | 210 |
| **合计** | | | **260** | **1300** |

- 总池配额 260/人 = 每人周配额 300 − 新数据 40 − 正向跟单 X（X=0 时）
- **档级补位**：档1 不足 → 缺额下传档2 → 档3 → 档4 → 门槛池(<500)

**门槛池说明**（金额 <500 元的债权等待区）：
- 不进正常四档，单独存放；档1-4 全部打完后，按金额从大到小补位
- 设 500 元门槛的依据（真实数据 6413 笔）：

| | 笔数 | 金额 | 占总金额 |
|---|------|------|---------|
| ≥500 元 | 6047 | ¥32,543,547 | 99.6% |
| <500 元（门槛池） | 366 | ¥132,596 | 0.4% |

- 平均每笔 ¥362——与 14 万大户抢配额不划算；门槛池不是放弃，是排队到最后（总池 4.65 周全覆盖后轮到）
- 档切点每月用最新数据重标定一次

## 三、第二维 · 档内六因子加性权重

$$score = 0.30 \times AI评价分 + 0.20 \times 标签分 + 0.10 \times 感受分 + 0.15 \times 数据新鲜度分 + 0.20 \times 探索分 + 0.05 \times 等待分$$

| 因子 | 权重 | 分数映射 | 未接通时缺省 |
|------|------|---------|-------------|
| AI 评价分 | **30%** | 0-100 直接使用（AI 预测本次通话回款概率） | 50（中性） |
| 标签分 | 20% | B=100 / D=72 / C=60 / 无标签=60 / A=40 / E=20 / F不参与 | — |
| 感受分 | 10% | 1=20 / 2=40 / 3=60 / 4=80 / 5=100 | 50（中性） |
| 数据新鲜度分 | 15% | ≤7天=100 / 8-14天=80 / 15-21天=60 / 22-28天=40 / 29-60天=28 / >60天=20（基准=上传时间；账龄因子留接口） | — |
| 探索分 | 20% | 本月人工未接通 0次=100 / 1次=50 / 2次=25 / ≥3次=0（仅人工·不含外呼；每月1日清零） | — |
| 等待分 | 5% | 回流>14天起每天+5，34天封顶100 | 0 |

## 四、各因子详解

### 4.1 AI 评价分（权重 30%，最高）

- **评分维度（五维度，各 0-20 分合成 1-100）**：还款态度 / 沟通配合度 / 困难真实性 / 承诺可信度 / 争议严重度（争议大反向计分）
- **评分依据**：nt 通话转写，维度打分附证据（关键词摘录），可审计

- **定义**：客服与业主通话后，AI 分析双方对话，给出"本次通话最终回款概率"的预测，0-100 分
- **产生时机**：每次客服通话结束（ASR 完成 + AI 分析完成）
- **多次通话**：取最近一次的评价分
- **外呼接通**：不产生（外呼为单轮播报，信息量不足）
- **未接通**：无评价分，排序时用缺省 50 中性分
- **权重逻辑**：AI 评价是回款概率的直接预测器，比标签（静态画像）更实时、更个性化——同档内，"AI 说这人会还钱"的信号优先级最高

### 4.2 标签分（权重 20%）

| 标签 | 分数 | 依据 |
|------|------|------|
| B 现实困难 | 100 | 回款概率最高：有沟通意愿+分期通道 |
| D 惯性失约 | 72 | 承诺过但敏感度低 |
| C 观望拖延 | 60 | 基准值 |
| 无标签 | 60 | 基准值（未触达，靠探索分驱动） |
| A 合理争议 | 40 | 争议未解决，回款打折，不放弃 |
| E 对抗失信 | 20 | 基本搁置，仅回归参考 |
| F 历史遗留 | 不参与 | 已出列 |

### 4.3 感受分（权重 10%）

- **定义**：客服对本次通话的主观评价，1-5 分
- **映射**：感受分 × 20 → 20/40/60/80/100
- **独立性**：感受分与 AI 评价分独立存储、独立计算，不互相影响
- **权重逻辑**：客服在场，能捕捉 AI 文本分析捕捉不到的语气、态度信号——占 10% 是对"人"的判断的尊重，但不喧宾夺主

### 4.4 数据新鲜度分（权重 15%，原"时效分"）

| 上传距今 | 分数 | 逻辑 |
|---------|------|------|
| ≤7 天 | 100 | 黄金窗口，优先清理新数据 |
| 8-30 天 | 90 | 热度尚在 |
| 31-90 天 | 75 | 开始降温 |
| >90 天 | 60 | 陈年老账，靠其他因子救 |

### 4.5 探索分（权重 20%）

| 未接通次数 | 分数 | 逻辑 |
|-----------|------|------|
| 0（未触达） | 100 | 没打过的最优先——保证首轮全覆盖 |
| 1 次 | 50 | 试过一轮无果，热度减半 |
| 2 次 | 25 | 再减半 |
| ≥3 次 | 0 | 多次无响应，让位 |

**加性设计**：探索分是"加分"不是"倍率"——640 元的小户和 14.2 万的大户同样 +20 分，保证小额户也享受覆盖保护，不被金额放大效应淹没。

### 4.6 等待分（权重 5%）

- **场景**：回流户（已触达未接通）的等待时间
- **规则**：等待 >14 天起，每天 +5 分，34 天封顶 100 分
- **局限**：基准是上传时间（数据导入时间），不是欠费账龄——衡量"数据新鲜度"而非"账龄新鲜度"；账龄因子字段到位后作为第七因子加入（接口已预留）
- **逻辑**：解决回流饿死——等待越久越靠前，2 周后平滑插队，不需要硬编码插队规则

## 五、缺省值处理

| 场景 | AI 评价分 | 感受分 | 其他 |
|------|----------|--------|------|
| 未接通/拒接 | 50（中性） | 50（中性） | 探索分按未接通次数计 |
| 首次触达前 | 50 | 50 | 探索分 100（未触达） |
| 外呼接通 | 50 | 50 | 标签不判定（走线索），探索分照常 |
| 客服通话后 | 实际值 | 实际值 | 全部实际值 |

**原则**：缺省值取中性 50，让缺失的因子"不偏不倚"，其余因子照常驱动排序。

| # | 债权 | 计算过程 | score |
|---|------|---------|-------|
| 1 | B类 · AI=85 · 感受5 · 10天 · 未触达 | 25.5+20+10+12+20+0 | **87.5** |
| 2 | C类 · AI=40 · 感受2 · 10天 · 未触达 | 12+12+4+12+20+0 | **60.0** |

| 4 | 无标签 · 5天 · 未触达 | 15+12+5+15+20+0 | **67.0** |

## 七、排序与分配流程（每周一指定项目 · 周池重建 · 进度跨周记忆）

**排序键（三键）**：

```
档内排序键 = (豁免标志 ASC, call_count ASC, score DESC)
  第0键 豁免标志：promise_due 在未来3天内 → 排最前（承诺时点优先，错过承诺=言而无信）
  第一键 call_count：本月人工沟通记录数（仅客服人工，不含外呼）——没人工打过的硬性优先（0 > 1 > 2）
  第二键 score：同为 N 次内部，六因子决定谁先打
```

**承诺豁免分两类型（业主承诺回款时间无统一定义）**：
```
类型1 明确缴费时间（"下周二发工资就交"）
    → 记录 promise_due 具体时间 → 前3天排本档最前（promise_count<3 才生效）
    → 到期当日 08:00 未回款：①豁免撤销 ②promise_count+1（内部数据字段·D类素材·不做业主信用加减分）③call_count重置1
类型2 口头答应缴费（"好的我会交"·无具体时间）
    → 不记录 promise_due，不触发豁免
    → 仅入 nt 通话记录，AI评分"承诺可信度"维度自然体现（含糊=低分）
```

**周池机制**：
- 每周一管理员指定项目集 → 生成周池（每周重建）
- call_count 来自人工通话记录表按月聚合（不含外呼记录），天然跨周保留——池重建不丢覆盖进度
- 通话记录按月聚合，新月自动从 0 开始；分档切点月初重标定、月内固定
- 池不足配额时：按 (call_count, score) 取全库回流户补足

```
步骤0  周池生成（管理员指定项目集 → 债权入池）
步骤1  标签预处理（F/E 出列，A 正常通道）
步骤2  正向跟单名单确认（本月接通 + AI≥61 + 感受分≥4）
步骤3  配额计算：正向X + 新数据40 + 总池260-X
步骤4  新数据分配：金额蛇形 5 份 × 40（档内不叠加新鲜度分·避免双重计数）
步骤5  总池分配：
        档1 按 (豁免, call_count, score) 排序 → 蛇形分 62/人
        档2 → 83/人  档3 → 73/人  档4 → 42/人（档级补位）
        池不足 → 全库回流户补足
步骤6  均衡校验（5人总额偏差 >10% → 档内交换微调）
步骤7  落库（通话记录由通话事件自动累计）
步骤8  周三轮换：个人池全回收（意向池不动）→ 重复 2-7
客服界面顺序：档1 → 档2 → 档3 → 档4，档内按 (call_count, score)
```

**轮换间隙**（通话事件）：AI 评价分/感受分/标签更新 → 该债权 score 重算 → 个人池内排序实时刷新（只动顺序，不换人）。

## 八、与乘性 EV（V3.0）的对比

| | 乘性 EV（V3.0） | 二维加性（V3.2） |
|---|---|---|
| 公式 | 金额 × 权重积 | 档间金额定配额 + 档内权重加和 |
| 金额作用 | 直接乘入，主导一切 | 只在分档时作用，档内不参与 |
| 标签话语权 | 被 35 万倍金额差稀释 | 档内 20% 权重，真实有效 |
| 探索机制 | 乘性倍率，被金额放大 | 加性分数，人人平等 |
| 调参 | 一因子动全局 | 因子独立，各自调 |
| 解释性 | 需解释 EV 是什么 | "档位+打分"直观 |
