## 一、总则

### 1.1 目标

用最少的人力轮次，覆盖最高的回款价值。三个子目标：

1. **价值优先**：大金额 × 高回款概率 × 新鲜债权优先触达
2. **首轮全覆盖**：月内所有正常债权至少触达一次（历史遗留、对抗除外）
3. **人不失衡**：5 人分配金额/笔数偏差 ≤ 10%

### 1.2 核心思想

**回款为主，覆盖为基，标签决定去向，score 决定顺序，配额决定节奏。**

- 一切规则服务于回款；覆盖保护是回款的保障机制——没打过的户永远打不到，回款为零
- 标签（六类）决定债权进哪个池、走哪条路
- 六因子 score 决定同档内谁先打
- 配额结构决定每周火力分配

### 1.3 术语表

| 术语 | 含义 |
|------|------|
| 主池 | 全部未分配债权（含回流），按金额分档+档内 score 排序 |
| 个人池 | 客服本周持有名单（300 户/人） |
| 意向池 | 客服自建留人名单（≤50 户/人，不回收） |
| 历史遗留池 | F 类历史遗留，建档核实，不占催收配额 |
| 搁置池 | E 类对抗，本月不安排人工（外呼机器人按正常催收流程通知），跨月恢复 |
| 门槛池 | 金额 <500 元的债权等待区：不进正常四档，档1-4 打完后按金额从大到小补位（真实数据 366 笔仅占总金额 0.4%） |
| 正向跟单 | 本月接通 + 行为正向（AI≥61 + 感受分≥4）的持续跟进名单 |
| score | 档内六因子加权排序分（AI评价/标签/感受/数据新鲜度/探索/等待） |
| call_count | 本月人工沟通记录数（仅客服人工通话记录，不含 AI 外呼；排序第一键，按月聚合天然生效） |
| 周池 | 每周一由管理员指定项目集生成的分配池（每周重建，进度不丢） |

## 二、标签体系（V10 定义 · 分配方向盘）

| 标签 | 定义 | 分配去向 | 催收策略 |
|------|------|---------|---------|
| F 历史遗留型 | 前期物业、产权变更、开发遗留、资料缺失等复杂背景；号码失联亦归此类 | → 历史遗留池（不占配额） | 客服自行反馈到物业微信群核实 |
| E 对抗失信型 | 将拒缴作为施压手段，长期无理扩大争议，破坏公共秩序 | → 搁置池（本月不安排人工） | 不刺激，外呼机器人按正常催收流程通知，跨月回主池重评 |
| A 合理争议型 | 对服务质量、收费边界、历史问题存在**可核验**争议 | 正常通道 · 标签分40 | **缴费与争议分开**：记录争议转物业 + 继续催缴 |
| B 现实困难型 | 短期支付困难、突发家庭变故、阶段性现金流问题 | 正常通道 · 标签分100 | 不施压，分期协商 |
| D 惯性失约型 | 长期拖欠，形成失约惯性，对提醒协商敏感度低 | 正常通道 · 标签分72 | 承诺机制，按正常催收阶段流程走（不另安排） |
| C 观望拖延型 | 并无明确抗辩理由，受他人影响长期拖延，试图搭便车 | 正常通道 · 标签分60 | **主战场**：制度压力 + 共识教育 |
| 无标签 | 未触达，无任何数据 | 正常通道 · 标签分60 + 探索分100 | 首次触达重点了解 |

## 三、五池架构

```
主池（全部未分配 · 金额四档 + 档内五键排序）
   │
   ├── 每次轮换前·标签预处理：
   │     F → 历史遗留池（客服自行反馈到物业微信群，不占配额）
   │     E → 搁置池（本月不安排人工，外呼机器人按正常催收流程通知）
   │     A → 正常通道（缴费与争议分开：记录争议反馈物业微信群，催收不停）
   │
   ├── 正常通道分配（每人每周 300）：
   │     正向跟单 X + 新数据 40 + 总池(300−40−X)
   │
   ▼
个人池（300 户/人 · 蛇形均衡）
   │
   ├── 接通 + 正向 → 正向跟单（月内定向原人）
   ├── 客服拉入 → 意向池（≤50 户 · 唯一留人通道 · 满额提醒客服自选剔除 · 不回收）
   ├── 未接通 → 回流主池（五键重排，等待加分）
   ├── E 判定 → 搁置池（本月不安排人工）
   └── 回款（物业报数）→ 终止

门槛池（金额 <500 元）：不进正常四档；档1-4 全打完后按金额从大到小补位
```

## 四、权重分配模型（二维 · V3.2）

> 详见《催收分配逻辑_V3.2_权重模型.md》。摘要：

**第一维 · 金额分档定配额**（4 档，档级补位）：

| 档 | 定义 | 配额/人/周 |
|----|------|-----------|
| 档1 超大额 | top 10% | 62 |
| 档2 大额 | top 11-30% | 83 |
| 档3 中额 | top 31-55% | 73 |
| 档4 小额 | bottom 45% | 42 |

**第二维 · 档内六因子加性排序**：

$$score = 0.30 \times AI评价分 + 0.20 \times 标签分 + 0.10 \times 感受分 + 0.15 \times 数据新鲜度分 + 0.20 \times 探索分 + 0.05 \times 等待分$$

| 因子 | 权重 | 映射 | 缺省 |
|------|------|------|------|
| AI 评价分 | 30% | 0-100 直接 | 50 |
| 标签分 | 20% | B=100 D=72 C=60 无标签=60 A=40 E=20 | — |
| 感受分 | 10% | ×20（1→20 … 5→100） | 50 |
| 数据新鲜度分 | 15% | ≤7天=100 / 8-14天=80 / 15-21天=60 / 22-28天=40 / 29-60天=28 / >60天=20（基准=上传时间·账龄因子留接口） | — |
| 探索分 | 20% | 本月人工未接通：0次=100 / 1次=50 / 2次=25 / ≥3次=0（仅人工·不含外呼；每月1日清零） | — |
| 等待分 | 5% | >14天每天+5，34天封顶100 | 0 |

## 五、分配主流程（每周一指定项目 · 周池重建 · 进度跨周记忆）

轮换时点：**周一 8:30**、**周三 12:00**，同一套规则。

**周池机制（关键）**：

```
每周一由管理员指定项目集 → 生成周池（成员 = 项目集内 status∈(pool,retry) 的债权）
周池每周重建，但每笔债权的 call_count（本月人工沟通记录数）来自人工通话记录表，天然跨周保留
→ 池重建不丢覆盖进度：排序第一键是 call_count，打过的户自动让位给没打过的
按月聚合：上月通话记录不跨月累计，新月自动从 0 开始
分档切点：月初重标定一次，月内固定（周池重建不重切分档）
```

```
步骤0  周池生成（管理员指定项目集 → 债权入池）
步骤1  标签预处理（标签引擎最新输出）
        F→历史遗留池  E→搁置池  A→正常通道(缴费与争议分开)
步骤2  正向跟单名单确认
        本月接通 + AI≥61 + 感受分≥4 → 定向原人，上限 100/人
步骤3  配额计算
        每人：正向 X + 新数据 40 + 总池 (300−40−X)
        总池按四档配额 62/83/73/42（X=0 时）
步骤4  新数据分配
        最新上传批次 ≥500 按金额取前 200 → 金额蛇形 5 份 × 40
        （新数据档内不再叠加数据新鲜度分——独立配额已是优先，避免双重计数）
步骤5  总池分配（档级补位）
        档1 取 310（不足→档2 补→档3 补→档4 补→门槛池）
        档内排序 = (call_count ASC, score DESC) → 蛇形轮流
        池不足配额时：按同样排序键取全库回流户补足（先覆盖新池，再补打回流）
步骤6  均衡校验
        5 人总额偏差 >10% → 档内交换微调
步骤7  落库（通话记录数由通话事件自动累计，无需额外维护）
步骤8  周三轮换附加
        个人池全回收（意向池不动）→ 重复步骤 2-7
```

### 5.1 档级补位规则

```
档1 配额 62/人（周 310）→ 档1 不足时，缺额由档2 承接
档2 配额 83/人（周 415）→ 档2 不足时，缺额由档3 承接
档3 配额 73/人（周 365）→ 档3 不足时，缺额由档4 承接
档4 配额 42/人（周 210）→ 档4 不足时，由 <500 门槛池按金额补位
```

### 5.2 排序键（承诺豁免 + 覆盖保护 + 价值排序）

```
档内排序键 = (豁免标志 ASC, call_count ASC, score DESC, 金额 DESC, debt_id ASC)
  第0键 豁免标志：promise_due 在未来3天内的户 → 豁免，排最前（承诺时点优先）
  第一键 call_count：本月人工沟通记录数，0 > 1 > 2……
      → 没打过的硬性优先，打过回流的让位
  第二键 score：同为 N 次的户内部，六因子决定谁先打
  第三键 金额 DESC：同分时大额优先
  第四键 debt_id ASC：最终兜底，保证排序确定可复现
```

**承诺豁免规则**：业主承诺还款并给出时间（promise_due）后，到期前 3 天内该户无视 call_count 排到本档最前——错过承诺时点等于言而无信，豁免保证客服在约定窗口内打回访。

**承诺豁免分两类型**（业主承诺回款时间无统一定义）：
```
类型1 明确缴费时间（如"下周二发工资就交"）
    → 记录 promise_due 具体时间
    → 到期前3天排本档最前（仅 promise_count < 3 生效；≥3次不再豁免）
    → 到期当日 08:00 未回款：①豁免撤销 ②promise_count+1（内部数据字段·D类素材·不做业主信用加减分）③call_count重置1
类型2 口头答应缴费（如"好的我会交"·无具体时间）
    → 不记录 promise_due，不触发豁免
    → 仅入 nt 通话记录，AI评分"承诺可信度"维度自然体现（含糊=低分）
```

### 5.3 蛇形轮流

档内按排序键排好的队列：第 1 笔→A，第 2 笔→B，第 3 笔→C，第 4 笔→D，第 5 笔→E，第 6 笔→A…循环。
真实数据实测：5 人金额偏差 2.7%~4.5%（<10% 阈值）。

## 六、正向跟单（迭代后的口径）

| 项 | 规则 |
|----|------|
| 入选条件 | **本月接通** + **AI 评分≥61** + **感受分≥4**（行为口径，不再用 B/C/D 标签） |
| 安排方式 | 每周轮换时定向原客服，占配额第 1 优先级 |
| 上限 | 100 户/人/周，超出按 score 取前 100 |
| 退出 | 回款 / 拉入意向池 / 跨月清点（未回款且本月无新接通 → 转回主池） |
| 与意向池区别 | 意向池=手动·长期锁定；正向跟单=自动·月度窗口 |

**迭代说明**：原口径为"标签 B/C/D"。新标签定义下 C 为搭便车（非正向语义），故改为行为评分口径——AI 评分与感受分才是"还款意向"的直接信号。

## 七、标签使用约束

1. 标签体系为**六类单级**：F/E/A/B/D/C，不开发子级标签（无 C1/C2、D1-D3）。
2. D 类失约计数（promise_count）作为**数据字段**保留，用于判定与策略；函告等动作按正常催收阶段流程走（系统已有阶段流程，不另安排），不做分级展示。
3. C 类的从众信号（nt 含"别人也没交/大家都"）作为标签引擎的**判定线索**之一，不单独成级。
4. 六类标签的催收策略在标签开发文档中定义，分配引擎只消费标签结果。

## 八、外呼通道判定规则

**外呼接通 ≠ 客服通话。六类标签只在人工客服通话中判定内容类；行为类不分通道。**

| 标签 | 外呼接通 | 处理 |
|------|---------|------|
| F 历史遗留 | ✓ 判定 | 号码状态是客观事实，不分通道 |
| E 对抗失信 | ✓ 判定 | 拒接行为不分通道（拒的不管是客服还是机器人） |
| A/B/D/C | ✗ 不判定 | 外呼是单轮播报，无法追问核验——转为 pending_signal 待确认线索 |

外呼接通处理流程：
```
外呼接通 → ① 行为类照常判定（E/F）
           ② ASR 照常分析 → 内容信号转 pending_signal（不改标签）
           ③ last_result = 外呼接通
         → 进入客服回拨队列（高优先级）
         → 客服回拨 → 双向对话 → 结合线索正式判定六类标签
         （客服界面弹出提示："上次外呼中业主提到没钱，请确认"）
```

AI 评分同口径：外呼接通不给正式 AI 评分，只有客服通话才产生 1-100 评分。

## 九、边界规则

| 场景 | 处理 |
|------|------|
| 意向池 | 客服挂断后手动拉入，≤50 户/人，只数催收中/暂停/部分还款三态；周三不回收；回款自动移出；满额时系统提醒，客服自行选择剔除一户回主池（系统不自动剔除） |
| 回款口径 | **全额=终止**；部分还款=意向池三态（进度信号单独记录，不算回款终止）；回款以物业报数为准 |
| 一致性抽查 | 感受分 vs AI 评分差 ≥2 档（如 5分 vs 1-20分）→ 管理员复核；抽查率 ≥10% |
| 模型退化检测 | 月回款率环比波动 >20% → 触发模型复核流程 |
| E 类搁置到期 | 跨月自动回主池，按 C 标签分参与排序；重新接通后按新标签重评 |
| A 类催收 | **缴费与争议分开**：记录争议转物业（争议线），继续催缴（缴费线）；话术不施压，以解决问题+引导缴费为主；标签分 40。**反馈工单化**：客服录入 → 管理员每日汇总发物业群 → 状态回写；争议 7 天无回应 → 客服端弹提醒 |
| F 类解除 | 人工审核解除（唯一人工标签环节）→ 重新分类回主池 |
| <500 门槛池 | 不进正常分档；档4 不足时按金额从大到小补位。**依据**：真实数据 366 笔 <500 仅占总金额 0.4%（平均每笔 ¥362），催收火力优先给大中额 |
| 紧急叠加 | 管理员手动触发，300 之外额外分配 |
| 新数据 > 配额 | 超量部分入主池按分档+score 排队（新→旧时间序自然靠前） |
| 周池小于配额 | 按 (call_count, score) 取全库回流户补足——先覆盖新池，再补打回流 |
| 正向跟单挤压 | X=25/人时总池配额 260→235，全池覆盖 5→5.5 周——"回款为主"的合理代价，明示接受 |
| 档1 配额预期 | 档1 约 1.9 周打透，之后配额自动下传（档1 数字名存实亡属正常，客服界面显示实际分配结构） |
| **外呼频次上限** | **每户每周 ≤2 次 AI 外呼**；超限自动跳过该户，本周不再呼叫 |
| **外呼时段窗口** | **工作日 9:00-12:00、14:00-20:00；周末及法定节假日 10:00-18:00**；窗口外不呼 |
| **录音留存期限** | **全部通话录音（含 AI 外呼）留存 ≥6 个月；A 类争议户录音留存至争议解决后 12 个月** |
