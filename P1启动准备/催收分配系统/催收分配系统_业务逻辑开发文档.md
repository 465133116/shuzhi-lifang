## 2. 系统概述

### 2.1 系统定位

催收分配系统（独立系统，未与数治理方平台对接）用于物业服务费欠费的催收债权分配管理。核心目标：**把有限的催收火力（5 名客服，每人每周 300 户）分配到最可能回款的债权上，同时保证池内债权不饿死**。

### 2.2 设计原则

> **回款为主，覆盖为基，标签决定去向，五键决定顺序，配额决定节奏。**

- **回款为主**：一切规则服务于回款结果；覆盖保护是回款的保障机制——没打过的户永远打不到，回款为零。
- **覆盖为基**：月内保证池内每笔债权至少被人工分配一次（未接通的除外，其重新排队）。
- **标签决定去向**：六类标签决定债权进哪个池、走哪条路。
- **五键决定顺序**：档内排序由五个比较键依次决定。
- **配额决定节奏**：金额四档配额控制每周火力分配比例。

### 2.3 整体流程一览

```
每周一 08:30：管理员指定项目集 → 生成周池 → 标签预处理 → 正向跟单确认
             → 配额计算 → 新数据分配 → 总池分配（档级补位+五键+蛇形）
             → 均衡校验 → 落库（个人池）
周一至周四：客服拨号（列表冻结）→ 通话 → 感受分必选 → 可拉意向池
周三 12:00：个人池回收重分（意向池、承诺豁免户不回收）
每月 1 日：call_count/探索分清零 + 分档切点重标定 + 权重参数复核
           + 正向跟单跨月清点 + E 类跨月复查
```

## 3. 名词定义

### 3.1 对象类名词

| 名词 | 定义 |
|------|------|
| 债权 | 一条欠费记录，最小催收单位。字段：项目、小区、房号、欠费金额、上传时间、债权ID（debt_id）等 |
| 业主 | 债权的归属人。同一业主可有多笔债权（多项目欠费），**分配时绑定**（见 5.4.5） |
| 项目集 | 每周一管理员指定的催收项目集合，决定当周池的成员范围 |
| 周池 | 每周一按项目集生成的分配池；每周重建，但覆盖进度（call_count）记在债权上跨周保留 |
| 门槛池 | 金额低于 500 元的债权等待区；不进正常四档，档 1-4 打完后按金额从大到小补位 |

### 3.2 池与状态

| 名词 | 状态值 | 定义 |
|------|--------|------|
| 主池 | pool / retry | 全部未分配债权。pool=从未分配；retry=分配过但未接通回流 |
| 个人池 | assigned | 轮换选中、归属客服名下的债权（300 户/人/周） |
| 意向池 | intent | 客服手动锁定 ≤50 户/人的高意向债权 |
| 历史遗留池 | legacy | F 类债权（不催收） |
| 搁置池 | shelf | E 类债权（本月不安排人工） |
| 终止 | done | 回款全额（物业报数），流程结束 |

状态迁移仅允许三个入口：**分配引擎、标签引擎、客服手动操作**。

### 3.3 排序与权重名词

| 名词 | 定义 |
|------|------|
| score | 档内六因子加性排序分，满值 100 |
| 五键排序 | 档内排序的比较键序列：(豁免标志, call_count, score, 金额DESC, debt_id) |
| call_count | 本月人工沟通记录数（仅客服人工通话，不含 AI 外呼），按月聚合，排序第一键 |
| 豁免标志 | 承诺到期前 3 天且失信<3 次的标记，排序第零键（最优先） |
| 档级补位 | 档内新户（豁免+未打过）不足配额时，缺额下传下一档（B 版） |
| 蛇形轮流 | 排序队列按 1→2→3→4→5 客服循环分配 |
| 均衡校验 | 5 人金额偏差>10% 时触发档内交换微调 |
| 影子模式 | 上线前 1 个月照算照排但不干预实际分配的回测阶段 |

### 3.4 标签名词

| 名词 | 定义 |
|------|------|
| 六类标签 | A 合理争议 / B 现实困难 / C 观望拖延 / D 惯性失约 / E 对抗失信 / F 历史遗留（单级，无子级） |
| 无标签（NULL） | 首次触达前的零数据状态，**不是 C** |
| pending_signal | 外呼产生的待确认内容类标签线索 |
| 回拨队列 | 外呼接通户的客服回拨清单（高优先级） |
| promise_due | 承诺还款到期时间（仅类型 1 承诺记录） |
| promise_count | 承诺失信累计次数（内部数据字段，不做业主信用加减分） |

### 3.5 因子名词（六因子）

| 名词 | 权重 | 定义 |
|------|------|------|
| AI 评价分 | 30% | AI 对通话回款概率的预测（0-100），五维度合成 |
| 标签分 | 20% | 六类标签映射的排序分 |
| 感受分 | 10% | 客服对通话的评价（1-5，×20 映射） |
| 数据新鲜度分 | 15% | 按上传时间衡量的数据新鲜度（非账龄） |
| 探索分 | 20% | 本月未接通次数反向分 |
| 等待分 | 5% | 回流户等待时间的补偿分 |

### 3.6 机制名词

| 名词 | 定义 |
|------|------|
| 正向跟单 | 本月接通 + AI≥61 + 感受≥4 的户，月内定向原客服跟进（上限 100/人/周） |
| 承诺豁免 | 类型 1 承诺（明确时间）到期前 3 天排本档最前的机制 |
| 一致性抽查 | 感受分与 AI 评分差 ≥2 档 → 管理员复核（抽查率 ≥10%） |
| 模型退化检测 | 月回款率环比波动 >20% → 触发模型复核 |
| 状态守恒 | 各池户数 + 终止 = 总户数，每次迁移后校验 |

## 4. 标签业务逻辑

### 4.1 判定总则

- 标签由 **AI 全自动判定**，客服零标注。
- 判定数据源：通话转写（nt）、通话结果（rs）、标签记录（lb）。
- **未接通/拒接不产生标签**（AI 不猜测）；拒接累计 3 次才判 E。
- 首次触达前 = 无标签 NULL（不是 C）；首次通话无明确信号才兜底 C。

### 4.2 双通道判定规则

| 通道 | 判定能力 | 说明 |
|------|---------|------|
| 客服人工通话 | 全判定（A/B/C/D/E/F） | 可追问、可核验 |
| AI 外呼 | 仅判定行为类（E 拒接累计、F 号码失联） | 内容类（A/B/C/D）信号转 pending_signal 线索 |
| 外呼接通户 | 不直接判定内容类 | 进客服回拨队列，由客服回拨后正式判定 |
| 外呼评分 | 不产生正式 AI 评分 | — |

### 4.3 六类标签判定规则

| 标签 | 触发信号 | 去向 | 策略 |
|------|---------|------|------|
| F 历史遗留 | lb 号码无效/已搬家/产权变更/开发遗留/资料缺失 | 历史遗留池 | 不催收；客服自行反馈物业微信群；人工审核解除后回主池 |
| E 对抗失信 | 2 周内拒接≥3 次（号码有效），或 nt 对抗词 | 搁置池 | 本月不安排人工；外呼机器人按正常催收流程通知；跨月回主池重评 |
| A 合理争议 | nt 服务不满词 + 可核验具体事件 | 正常通道 | 缴费与争议分开：记录争议反馈物业微信群 + 继续催缴 |
| B 现实困难 | nt 困难词（失业/生病/没钱等） | 正常通道 | 不施压，引导分期 |
| D 惯性失约 | rs 无争议 + nt 承诺词 + 历史未兑现≥2 次 | 正常通道 | 承诺机制；按正常催收阶段流程走（不另安排动作） |
| C 观望拖延 | 五类均不命中（兜底）；从众词强化 | 正常通道 | 制度压力教育 |

### 4.4 标签变化规则

- **冲突优先级**：F > E > A > B > D > C（一次判定取最高命中，低优先级信号写入对话记录）。
- **生效时机**：内容类（A/B/C/D）变化**延迟到下次轮换生效**（防排序震荡）；行为类（E/F）**即时生效**（安全需要）。
- **B 类滞回**：转出 B 需连续 2 次通话无困难词；转回 B 需 1 次强困难词。
- **D 类衰减**：28 天无新承诺阶梯衰减 → C（催收系统未对接数治理方，无小程序行为数据）。
- **E 类跨月**：搁置期满（跨月）自动回主池，按 C 标签分重评。
- 标签变化触发 score 重算（下次轮换生效）。

## 5. 分配业务逻辑

### 5.1 金额分档（第一维）

- 切点算法：金额分位数法，top10% / top11-30% / top31-55% / bottom45%。
- 重标定时机：**每月 1 日**（事务内执行，结果存表可查），月内固定。
- 真实数据基准（6047 笔）：档1=604 笔（金额 51.9%）、档2=1210（25.9%）、档3=1511（12.2%）、档4=2722（10.0%）。

### 5.2 六因子 score 计算（第二维）

```
score = 0.30×AI评价 + 0.20×标签 + 0.10×感受 + 0.15×数据新鲜度 + 0.20×探索 + 0.05×等待
```

各因子映射规则：

| 因子 | 映射 | 缺省/特殊 |
|------|------|----------|
| AI 评价分 | 五维度各 0-20 合成 1-100（还款态度/沟通配合度/困难真实性/承诺可信度/争议严重度·反向） | 未接通缺省 50（首月临时，影子模式后替换为分布中位数） |
| 标签分 | B=100 / D=72 / C=60 / 无标签=60 / A=40 / E=20 | F 不参与（出列） |
| 感受分 | 1-5 ×20 = 20/40/60/80/100 | 通话结束必选；NULL 标记待补录不进缺省 |
| 数据新鲜度分 | ≤7天=100 / 8-14天=80 / 15-21天=60 / 22-28天=40 / 29-60天=28 / >60天=20 | 基准=上传时间；新数据通道内不叠加 |
| 探索分 | 本月人工未接通 0次=100 / 1次=50 / 2次=25 / ≥3次=0（仅人工·不含外呼） | 每月 1 日清零 |
| 等待分 | 回流>14 天起每天+5，34 天封顶 100 | 缺省 0 |

### 5.3 五键排序（档内）

排序键依优先级依次比较，前一键相同才比较后一键：

```
第0键 豁免标志 ASC：承诺到期前3天且失信<3次 → 排本档最前
第1键 call_count ASC：本月人工沟通记录数，0 > 1 > 2（覆盖保护）
第2键 score DESC：六因子分（价值排序）
第3键 金额 DESC：同分大额优先
第4键 debt_id ASC：确定性兜底（排序可复现）
```

### 5.4 周池分配主流程（步骤 0-8）

**步骤 0 周池生成**
- 触发：周一 08:30 管理员指定项目集（支持批量选择、一键沿用上周）。
- 动作：项目集内 status∈(pool, retry) 的债权组成周池；债权上 call_count、探索分等跨周字段保持不变。
- 结果：周池成员确定；池重建不丢覆盖进度。

**步骤 1 标签预处理**
- 动作：按最新标签分流——F→历史遗留池；E→搁置池；A/B/C/D/无标签→正常通道排队。
- 结果：池内仅剩正常通道债权参与分配。

**步骤 2 正向跟单名单确认**
- 条件：本月接通 + AI≥61 + 感受分≥4。
- 动作：生成正向跟单名单，定向原客服（跟人走）；承诺豁免户优先安排。
- 上限：100 户/人/周；超出按 score 取前 100，其余顺延下周。

**步骤 3 配额计算**
- 公式：每人 = 正向 X + 新数据 40 + 总池(300−40−X)。
- 说明：正向跟单挤压总池时，覆盖周期从 5 周拉长至约 5.5 周（回款为主的合理代价，属预期行为）。

**步骤 4 新数据分配**
- 动作：最新上传批次（≥500）按金额取前 200 → 金额蛇形 5 份 ×40/人。
- 规则：新数据在档内**不叠加数据新鲜度分**（独立配额已是优先，避免双重计数）。
- 超量：入主池按分档+五键排队。

**步骤 5 总池分配（核心）**
- 档级补位（B 版）：每档只取"豁免户 + call=0 新户"，不足部分缺额下传下一档（档1→档2→档3→档4→门槛池）。
- 档内排序：五键。
- 分配方式：蛇形轮流（第 1 笔→A，2→B，…，5→E，6→A 循环）。
- 池不足配额：按同键取全库回流户补足（先覆盖新池，再补打回流）。
- 模拟验证：B 版 5 周 100% 覆盖（A 版不下传仅 72.3%）。

**步骤 6 均衡校验**
- 规则：5 人总额偏差 =（最大−最小）/均值 >10% → 档内交换微调。
- 实测：真实数据偏差 4.03%-4.37%，未触发微调。

**步骤 7 落库**
- 动作：选中户 status→assigned，current_agent 写入；通话记录自动累计（call_count 无需手动维护）。
- 客服界面：档序+五键序展示；**拨打期间列表冻结**（打开时快照，会话内不重排）。

**步骤 8 周三轮换**
- 触发：周三 12:00。
- 动作：个人池全回收重分（重复步骤 2-7）。
- 例外：**意向池不回收**；**承诺豁免户不回收**（跟人走，保证承诺时点不因换人丢失）。
- 评分时序：AI 评分异步落地（30 秒内）；轮换前 10 分钟锁定评分快照。

### 5.5 同业主绑定分配

- 规则：同一业主的多笔债权**整组分配**给同一客服（同周同批），一次通话催多笔。
- 目的：防止同一业主一周内被多个客服重复拨打电话。

### 5.6 承诺豁免逻辑（两类型）

**类型判定**：
- **类型 1 明确缴费时间**（业主给出具体日期，如"下周二发工资就交"）→ 记录 promise_due → 进入豁免机制。
- **类型 2 口头答应**（无具体时间，如"好的我会交"）→ 不记录 promise_due、不触发豁免；仅入通话记录，由 AI 评分"承诺可信度"维度自然体现（含糊=低分）。

**类型 1 豁免生命周期**：

| 阶段 | 条件 | 动作 |
|------|------|------|
| 生效 | promise_due 前 3 天 且 promise_count < 3 | 排本档最前（无视 call_count） |
| 到期检查 | promise_due 当日 08:00 未回款 | ①豁免撤销 ②promise_count+1（内部字段）③call_count 重置为 1 |
| 硬条件 | promise_count ≥ 3 | 不再豁免（承诺失去可信度，按正常催收阶段流程走） |

**配套规则**：
- 豁免户周三不回收（跟人走）；换人时客服界面显示承诺备注（原客服+约定内容+到期时间）。
- 回款（物业报数）→ 直接终止。
- promise_count 仅作内部数据字段（D 类判定素材），**不做业主信用加减分**。

### 5.7 正向跟单逻辑

- 入选：三条件同时满足（本月接通 + AI≥61 + 感受≥4）。
- 安排：每次轮换定向原客服；占配额第一优先级。
- 上限：100/人/周，超出按 score 取前 100。
- 退出：回款→done；拉意向池→intent；判 E/F/A→对应池；跨月清点（pos_month≠本月 且本月无新接通）→回主池。

### 5.8 意向池逻辑

- 拉入：客服挂断后手动拉入（无门槛）。
- 上限：50 户/人，只数三态（催收中/暂停/部分还款）；无"保留名额"概念。
- **满额拉新**：系统提醒客服已满，**客服自行选择**剔除一户回主池（系统不自动剔除）。
- 三态：催收中 / 暂停（管理员、物业触发，期间不拨打）/ 部分还款（还 1 分也算）。
- 全局锁定：其他客服看不到也不能分走；周三不回收、跟人走；排序按金额降序。
- 移出：回款（物业报数）→ 自动移出终止；客服手动移出（判断无望）→ 回主池（下次流转给他人）；结案终止→管理员操作；投诉→仅物业/管理员可暂停。
- 其他：池内户后续被判 E/F 继续预留，不自动移出；离职回收后重新分派；取消管理员标记可超 50。

### 5.9 A 类争议反馈逻辑（工单化）

- 录入：客服记录争议（哪栋哪户什么事）→ dispute_ref 字段。
- 汇总：管理员每日汇总发物业微信群。
- 跟进：物业群内回应 → 管理员回写状态；**7 天无回应 → 客服端弹提醒 + 管理员任务**；14 天无回应升级告警。
- 并行：缴费线不停（继续催缴）；争议解决（物业反馈/业主确认）→ 标签重评，分数自然恢复。

## 6. 定时任务逻辑

| 时点 | 任务 | 规则 |
|------|------|------|

| 每日 08:00 | 一致性抽查 | 感受分 vs AI 评分差≥2 档 → 标记管理员复核 |

| 周三 12:00 | 轮换回收重分 | 步骤 8 |

## 7. 回款口径

- **全额 = 终止**（done）。
- **部分还款 = 意向池三态**（进度信号，单独记录，不算回款终止；还 1 分也算部分还款）。
- **报数来源**：以物业公司报数为准；报数当天系统自动终止。
- **拨打前校验**：客服拨打前校验"今日已报数清单"（缓存 10 分钟），防止报数延迟导致已回款户被重复催收。
- 金额依合同，不写死。

## 8. 边界与降级逻辑

| 场景 | 规则 |
|------|------|
| 周池 <500 户 | 不分档，全按五键排序分配 |
| 周池 >15000 户 | 告警 + 覆盖周期自动延长（管理者确认） |
| 新数据 >200/周 | 超量入主池排队 |
| 新数据 <200/周 | 配额回填总池 |
| 周池小于配额 | 按同键取全库回流户补足 |
| 轮换中途失败 | 全事务回滚，重试 3 次 |
| 标签引擎宕机 | 使用缓存标签 + 告警 |
| 感受分未选 | NULL 标记待补录（不进缺省），界面锁定下一户 |
| 状态守恒校验失败 | 回滚 + 告警（上线硬门槛） |

## 11. 数据一致性要求（铁律）

1. **状态守恒**：任意时刻 各池户数之和 + 终止数 = 总债权数。每次状态迁移后校验，失败回滚+告警。
2. **金额守恒**：原始总额 = 输出总额（精确到分），主动逐笔校准。
3. **合并守恒**：合并分配时每子行金额必累加不漏。
4. **排序确定性**：五键排序结果可复现（debt_id 兜底）。
5. **快照冻结**：客服拨打期间列表冻结；轮换前 10 分钟锁定评分快照。
