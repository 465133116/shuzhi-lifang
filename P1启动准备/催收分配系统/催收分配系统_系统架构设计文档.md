## 1. 架构目标与约束

### 1.1 目标

1. **正确性优先**：分配结果可复现、状态守恒可校验——错误分配比慢分配代价高得多。
2. **可回测**：同一引擎既能跑线上分配，也能跑历史回测和影子模式对照（P0 的架构前提）。
3. **渐进交付**：P0 最小架构即可产出价值（影子回测报告），不要求一步到位。
4. **合规内建**：录音留存、外呼频次/时段、审计日志从第一天就进入架构，不事后补。

### 1.2 规模约束（决定架构取舍）

| 指标 | 量级 | 架构含义 |
|------|------|---------|
| 债权总量 | 6,000-15,000 笔 | 单机数据库绰绰有余 |
| 客服 | 5 人 + 1-2 管理员 | 并发极低（<10 在线） |
| 通话量 | ~625 通/天 | ASR 调用量小，外部 API 可行 |
| 录音存储 | 625 通/天 × 留存 6 个月 | **存储规划是大头**（见 9.3） |
| 分配计算 | 每周 1 次全量 + 周三 1 次 | 性能无压力，毫秒级 |

**结论：单体架构 + 模块化内核。** 不为 5 人系统引入微服务的运维复杂度；但内核模块（分配引擎/标签引擎）保持纯函数边界，为将来拆分留余地。

## 2. 总体架构

### 2.1 分层视图

```
┌────────────────────────────────────────────────────────┐
│ 接入层                                                  │
│  客服工作台(Web)  管理员后台(Web)  看板(Web)             │
│  —— 移动端适配（客服可能用手机拨号场景）                  │
├────────────────────────────────────────────────────────┤
│ 应用服务层（模块化单体）                                  │
│  ①债权管理  ②分配引擎★ ③标签引擎  ④AI评分服务            │
│  ⑤外呼机器人 ⑥通话记录  ⑦留存服务  ⑧争议工单             │
│  ⑨回款服务  ⑩定时调度  ⑪参数中心  ⑫治理监控             │
├────────────────────────────────────────────────────────┤
│ 数据访问层                                               │
│  ORM + 迁移脚本 + 快照服务（分配前状态快照）               │
├────────────────────────────────────────────────────────┤
│ 数据层                                                   │
│  主库（业务表）  影子库/表（P0对照）  审计日志             │
│  文件存储（录音文件，独立存储规划）                        │
├────────────────────────────────────────────────────────┤
│ 集成层                                                   │
│  大模型API(ASR+评分+标签)  外呼平台API  物业报数通道       │
│  （数治理方平台——预留接口，当前不接通）                    │
└────────────────────────────────────────────────────────┘
```

### 2.2 模块间依赖规则

```
分配引擎 ← 读取 ← 标签引擎、通话记录、债权管理、参数中心
分配引擎 → 写入 → 分配表、审计日志（不直接写状态——见 2.3）
标签引擎 ← 读取 ← 通话记录（nt/rs）、AI评分
AI评分 ← 依赖 ← ASR 转写结果
留存服务 → 监听 ← 通话事件、回款事件（事件驱动）
```

**核心依赖方向**：所有引擎只读"事实数据"（债权/通话/参数），结果写入"结果表+审计日志"。任何引擎不得直接修改另一个引擎的数据——保证可回放。

### 2.3 状态变更的唯一通道

```
状态迁移白名单（业务逻辑文档 §3.2）：
  status 字段只能被以下三处修改：
    ① 分配引擎（pool/retry → assigned；assigned → pool/retry）
    ② 标签引擎（→ legacy/shelf；shelf → pool）
    ③ 客服/管理员手动操作（→ intent；intent → done/pool）
  其余任何服务写 status 一律拒绝（数据库触发器或应用层断言）
每次变更写迁移日志：谁、何时、从哪到哪、依据（哪个引擎/哪个操作）
```

## 3. 核心模块设计

### 3.1 分配引擎（系统心脏）

| 项 | 设计 |
|----|------|
| 定位 | **纯函数模块**：输入快照 → 输出分配结果，无副作用 |
| 输入 | 周池债权快照（含 call_count/标签/score 因子/豁免状态）+ 参数版本 + 项目集 |
| 输出 | 5 人分配清单 + 档级补位轨迹 + 均衡校验结果 |
| 确定性 | 五键排序（debt_id 兜底）+ 固定参数版本 → 同输入必同输出 |
| 运行模式 | ① 正式模式（写实际分配表）② 影子模式（写 shadow 表）③ 回测模式（历史快照重放） |
| 可测试性 | 纯函数可单测；模拟脚本已用真实数据验证（5 周 100% 覆盖、偏差 4.37%） |

**影子模式实现（P0 核心）**：

```
每周轮换时：
  快照 → [分配引擎] → 影子结果（新规则）→ shadow_assign 表
                     → 实际结果（旧规则）→ 实际分配表
月末：
  两组结果 × 回款数据 → 回测报告（回款对比/AI评分方差/因子相关矩阵）
```

### 3.2 标签引擎

| 项 | 设计 |
|----|------|
| 输入 | 通话事件（nt/rs/lb）+ 外呼结果 + AI 评分 |
| 处理 | 双通道判定（人工全判/外呼仅行为类）→ 冲突优先级 F>E>A>B>D>C → 写入标签 |
| 生效机制 | 内容类标签延迟到下次轮换生效（待生效标签区）；行为类即时 |
| 外呼线索 | 内容类信号 → pending_signal 表 → 回拨队列 → 客服回拨后正式判定 |
| 变化规则 | B 类滞回（连续2次/1次强信号）、D 类衰减（28天）、E 类跨月 |

### 3.3 AI 评分服务

| 项 | 设计 |
|----|------|
| 流程 | 录音文件 → ASR 转写 → 五维度打分（各 0-20）→ 合成 1-100 |
| 证据 | 每个维度打分附 nt 关键词摘录（可审计——一致性抽查的依据） |
| 异步性 | 通话结束 30 秒内落地；轮换前 10 分钟锁定评分快照 |
| 缺省 | 未接通不评分（缺省 50，影子后换分布中位数） |
| P3 扩展 | 回款结果回传 → AI 评分个体校准 |

### 3.4 外呼机器人服务

| 项 | 设计 |
|----|------|
| 流程 | 8 节点推进（预分配通知→…→告知函），每节点最多 3 次、间隔 1-2 天 |
| 合规内建 | 频次（≤2/户/周）、时段窗口（工作日 9-12/14-20、节假日 10-18）在**发起前硬校验** |
| 回调 | 接通/未接通/拒接结果回调 → 通话记录表 → 拒接累计（E 类判定素材） |
| 与标签引擎协作 | 仅行为类可判；内容类信号转 pending_signal |
| 录音 | 外呼录音同样留存 ≥6 个月 |

### 3.5 通话记录服务

| 项 | 设计 |
|----|------|
| 核心 | 人工通话记录表（call_count 的数据源，按月聚合查询） |
| 感受分 | 通话结束**必选**才能拨下一户；NULL 标记待补录（不进缺省） |
| 快照 | 轮换前 10 分钟锁定评分快照；拨打期间列表冻结 |

### 3.6 留存服务（意向池/正向跟单/承诺豁免）

| 子模块 | 关键设计 |
|--------|---------|
| 意向池 | ≤50 三态计数；满额提醒（不自动剔除）；全局锁定；周三不回收 |
| 正向跟单 | 月度窗口（pos_month）；三条件入选；跨月清点 |
| 承诺豁免 | 两类型分流（类型1记 promise_due/类型2不记）；生命周期状态机（生效→到期检查→撤销）；豁免户周三不回收 |

### 3.7 定时调度

| 任务 | 设计要点 |
|------|---------|
| 每日 4 任务 | 豁免到期检查/一致性抽查/争议跟进/外呼合规——独立事务，互不影响 |
| 周一 08:30 轮换 | 全流程单事务（步骤0-7），失败整体回滚重试 3 次 |
| 周三 12:00 回收 | 同周一事务模式 |
| 每月 1 日五合一 | **单事务+失败全回滚**（五动作必须原子：清点/清零/切点/权重复核/E类复查） |
| 每月 2 日退化检测 | 只读分析，产出告警不写业务数据 |

### 3.8 参数中心

| 项 | 设计 |
|----|------|
| 参数版本化 | 每次调整生成新版本号，历史可查——分配结果记录所用参数版本（可回放） |
| 月度锁定 | 调整仅每月 1 日生效；月中拒绝写入 |
| 参数项 | 15 项（见业务逻辑文档 §10）：权重/标签分/切点/阈值等 |

### 3.9 治理监控

| 项 | 设计 |
|----|------|
| 状态守恒 | 每日对账：各池户数+终止=总数；失败告警 |
| 退化检测 | 月回款率环比>20% 告警 |
| 一致性抽查 | 感受分 vs AI 评分差≥2 档 → 复核队列 |
| 六指标看板 | 覆盖率/回款率/每触达回款额/均衡度/投诉率/模型健康度 |

## 4. 数据架构

### 4.1 核心表清单（12 张）

| 表 | 关键字段 | 说明 |
|----|---------|------|
| debt（债权） | debt_id, owner_id, project, amount, upload_time, status, layer, call_count, no_pick, label, ai_score, feel_score, promise_due, promise_count, shelf_month, current_agent | 核心主表，字段见开发文档 04数据模型 |
| call_log（通话记录） | debt_id, channel(人工/外呼), result, nt, ai_score, feel, call_time | call_count 的数据源 |
| assign（分配记录） | debt_id, agent, week, layer, sort_position, param_version | 每次轮换一份 |
| intent_pool（意向池） | debt_id, agent, state(催收中/暂停/部分还款), join_time | — |
| positive（正向跟单） | debt_id, agent, pos_month, last_call_month | — |
| dispute（争议工单） | debt_id, content, feedback_time, status, remind_count | A 类工单化 |
| repayment（回款） | debt_id, amount, report_time, type(全额/部分) | 物业报数 |
| param_version（参数） | version, params_json, effective_month | 月度锁定 |
| status_log（迁移日志） | debt_id, from, to, source(引擎/操作), time | 状态白名单审计 |
| shadow_assign（影子分配） | 同 assign + shadow_week | P0 专用 |
| pending_signal（外呼线索） | debt_id, signal_type, source_call, status | 回拨队列 |
| audit_log（审计） | actor, action, object, detail, time | 全部管理操作 |

### 4.2 数据一致性设计

- 迁移日志 + 每日对账（守恒校验）
- 金额字段 DECIMAL(12,2)，全程不转浮点
- 排序结果存 sort_position（重算可对比，防漂移）

## 5. 集成架构

```
┌─────────┐   ASR+评分+标签    ┌──────────────┐
│ 本系统  │ ─────────────────→ │ 大模型 API    │
│         │ ←───────────────── │ (通用接口层)  │
└─────────┘   转写+五维分+证据  └──────────────┘
     │  ▲
     │  │ 发起呼叫/回调/录音拉取
     ▼  │
┌──────────────┐         ┌────────────────┐
│ 外呼平台 API  │         │ 物业报数通道    │
│ (第三方语音)  │         │ 初期:人工录入   │
└──────────────┘         │ 后期:API预留    │
                         └────────────────┘
数治理方平台：仅预留接口（当前不接通——无小程序行为数据）
```

**集成原则**：所有外部依赖走**适配器层**——大模型换供应商、外呼换平台，只改适配器不改业务逻辑。

## 6. 安全与合规架构

| 层 | 设计 |
|----|------|
| 认证授权 | 三角色：客服（只看自己的池）/管理员（全局+参数）/物业（报数）；最小权限 |
| 审计 | 全部管理操作入 audit_log；参数修改、手动调池、状态人工迁移必须留痕 |
| 录音 | 加密存储 + 访问审计 + 留存期自动清理（≥6个月/A类12个月） |
| 外呼合规 | 发起前硬校验（频次/时段）；校验失败拒绝呼叫并告警 |
| 数据脱敏 | 导出/看板按角色脱敏（业主号码仅客服拨打时可见） |

## 9. 分期架构路径

### P0 影子模式（最小架构，2-4 周）

**影子模式待验证项（运行一个月后用回款数据裁决）**：
1. 探索分是否砍掉"0次=100"档（消除与 call_count 共线）
2. 等待分是否取消（5% 杯水车薪）——取消后权重并入探索分或 AI 评分
3. 数据新鲜度分是否降权 15%→10%（数据管道属性 vs 业务属性）
4. 备选权重方案：AI 35% + 标签 20% + 感受 10% + 新鲜度 10% + 探索 25%（5 因子版）



```
债权导入(CSV/Excel) + 分配引擎(纯函数) + 影子双轨 + 通话记录采集
产出：回测报告 → 验证六因子权重
不需要：客服工作台（客服继续用现有方式）
```

### P1 核心分配（4-8 周）

```
+ 客服工作台（拨号/感受分/意向池） + 管理员后台（项目指定/周池）
+ 标签引擎 + AI评分 + 定时调度 + 治理监控 + 状态机白名单
交付门槛：状态守恒校验通过；均衡偏差<10%；五键排序可复现
```

### P2 留存机制（4-6 周）

```
+ 正向跟单 + 承诺豁免生命周期 + 争议工单化 + 回款服务（报数+终止）
交付门槛：跨月清点跑通；豁免两类型正确
```

### P3 自更新（持续）

```
+ 参数自校准 + AI评分个体校准 + 外呼全接入 + 数治理方预留接口激活（若对接）
```
