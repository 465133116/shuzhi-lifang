# 客服端 · 业主分类逻辑

> 数治理方 P1 · 2026-06-30
> 本文档描述仅基于客服通话数据的业主分类判定逻辑。
> 客服端独立运行，不依赖小程序工单数据（但可以读取工单结果）。

---

## 一、客服端能拿到什么数据

客服端通过每次外呼/呼入通话收集数据，核心是通话备注文本。

| 数据项 | 含义 | 取值 | 来源 |
|--------|------|------|------|
| rs | 通话结果 | 已接通 / 拒接 / 无争议 / 有争议 | 客服挂断后选择 |
| nt | 通话备注文本 | 自由文本（客服手动录入 + 语音识别转写） | 客服录入 |
| t | 通话时间 | 日期 | 系统记录 |

此外，客服端可以**读取**但**不修改**以下小程序端数据：
- li（业主是否登录过小程序）
- 工单列表（类型、状态、满意度）
- lb（特殊标签）

---

## 二、客服端能判断什么、不能判断什么

| 信号 | 客服端能判断吗 | 说明 |
|:----:|:---------------:|------|
| **F** | ✓ 能 | lb 标签由客服标注，客服端是 F 信号的唯一产生源 |
| **E** | ✓ 部分能 | 能判断拒接（E1）、攻击通话（E2）、拒缴（E3）。不能判断差评累积（E4，需要工单数据） |
| **A** | ✗ 不能 | A 信号来自工单状态，客服端不直接产生。但客服创建草稿后可以触发 A |
| **B** | ✓ 能 | 核心能力。基于通话备注中的困难关键词 |
| **D** | ✓ 能 | 核心能力。基于通话结果中的"无争议"承诺 |
| **C1~C3** | ✓ 能 | 核心能力。基于通话备注中的从众/拖延/对比关键词 |
| **C4** | △ 部分能 | 可以检测通话中的不满表述，但需小程序端验证"是否存在投诉工单" |
| **C5** | ✗ 不能 | C5 由 A 消除事件触发，A 消除发生在小程序端 |
| **C6** | ✗ 不能 | C6 是"无任何信号"的兜底，需要小程序端数据确认 |

## 三、客服端可独立检测的信号

### 信号一：F 信号（无法服务）

**客服端是 F 信号的唯一产生源。**

判断逻辑：
- 客服在业主资料中标注了 lb 标签
- lb 包含以下关键词之一：
  "已搬家"、"产权变更"、"已出售"、"新业主"、"继承"、"遗产"、"过户中"、
  "出租"、"租客"、"不在这住"
- → F = 有

或：
- 客服确认号码为空号/停机/错号 → F = 有
- 客服确认该业主不在服务范围 → F = 有

F 信号一旦产生，该业主直接归入 F 类，不参与后续 A-E 判定。

---

### 信号二：B 信号（经济困难）

**客服端是 B 信号的唯一产生源。**

判断逻辑：
- 取该业主**最近一次通话**的通话备注文本（nt）
- 如果文本包含以下任意一个困难关键词：
  "手头紧"、"失业"、"困难"、"没钱"、"交不起"、"实在困难"、
  "经济紧张"、"最近不容易"、"收入少"、"没工作"、"低保"、"吃不起"
- → B = 有
- 否则 → B = 无

**重要：B 信号只看最近一次通话。新通话覆盖旧通话。**

B 信号等级（客服端自行判定）：
- 历史上困难表达仅 1 次（含本次）→ B1·自述。**不能独立做主分类，仅辅助。**
- 历史上困难表达 ≥ 2 次 → B2·反复。**可以做主分类。**
- 业主提供了困难证明文件（失业证/低保证/医疗单据等）→ B3·可验证。**可以做主分类。**

---

### 信号三：D 信号（惯性失约）

**客服端是 D 信号的唯一产生源。**

判断逻辑：
- 统计所有通话中，通话结果（rs）为"无争议"的次数
  - "无争议"含义：业主在通话中口头表示会缴费/会上线/会行动，但实际未行动
- 对统计结果应用衰减规则（见下方）得到有效计数
- 有效计数 ≥ 2 → D = 有
- 有效计数 < 2 → D = 无

**D 衰减规则（客服端执行）：**
- 距上次"无争议"通话每满 7 天 → 有效计数自动减 1
- 例：3 次无争议，最近一次距今 8 天 → 有效计数 = 3 − 1 = 2
- 例：3 次无争议，最近一次距今 22 天 → 有效计数 = 3 − 3 = 0 → D 消除
- **例外：** 如果业主登录了小程序（li=true，从小程序端读取）→ D 直接消除，无论计数多少

D 信号强度分级：
| 有效计数 | 子类型 |
|:--------:|:------:|
| 1~2 | D1·轻度惯性 |
| 3~4 | D2·中度惯性 |
| ≥ 5 | D3·重度惯性 |
| ≥ D2 且近 14 天拒接 ≥ 2 | D4·沉默型 |

---

### 信号四：E 信号（对抗态度·拒接型/拒缴型/攻击型）

**客服端可独立判断 E1/E2/E3，不能判断 E4。**

**子规则一：拒接累积检测 → E1·拒接型**
- 统计通话结果（rs）为"拒接"的次数
- 有效拒接 = 拒接次数 − 小程序工单数（从小程序端读取，最小为 0）
  - 含义：如果业主拒接电话但在小程序上有工单行为，说明只是不想接电话而非真的对抗
- 有效拒接 ≥ 3 → E1 = 有

**子规则二：明确拒缴检测 → E3·拒缴型**
- 最近一次通话备注（nt）包含以下关键词：
  "不交"、"死也不交"、"绝对不交"、"别想了"、"不可能交"、"一分不交"
- → E3 = 有

**子规则三：攻击性通话检测 → E2·攻击型**
- 最近一次通话备注（nt）包含攻击性关键词（辱骂、威胁等）
- → E2 = 有

**E 信号子类型优先级（客服端）：** E2 > E3 > E1

---

### 信号五：C1 信号（从众观望）

判断逻辑：
- 最近一次通话备注（nt）包含以下任意关键字：
  "别人交我就交"、"大家都交了吗"、"交的人多吗"、"有多少人交了"、
  "别人也没交"、"都拖着呢"、"等别人先交"、"邻居交了我就交"、"随大流"、
  "别人用我就用"、"大家都用了吗"、"有人用吗"
- → C1 = 有

---

### 信号六：C2 信号（拖延观望）

判断逻辑：
- 最近一次通话备注（nt）包含以下任意关键字：
  "不急"、"再看吧"、"到时候再说"、"过段时间"、"再说"、
  "不急这一时"、"不着急"、"等等看"、"观望一下"
- → C2 = 有

---

### 信号七：C3 信号（对比观望）

判断逻辑：
- 最近一次通话备注（nt）包含以下任意关键字：
  "隔壁小区"、"人家那边"、"凭什么我们"、"别的小区"、
  "人家小区"、"别的地方"、"我们小区不如"、"看看人家"
- → C3 = 有

---

### 信号八：C4 信号（信任缺失·客服端补充）

判断逻辑：
- 最近一次通话备注（nt）包含以下不满关键词：
  "物业不管"、"服务差"、"以前"、"失望"、"不负责"、"总是拖"、"太差了"
- **并且**从小程序端读取：该业主不存在类型为"投诉"的正式工单
- → C4 = 有

## 四、客服端分类结果（不完整分类）

由于客服端只能看到通话数据，它给出的分类也是不完整的。

### 客服端主分类判定（简化版）

按以下顺序检查客服端能判断的信号：

| 步 | 检查 | 命中→主分类 | 说明 |
|:--:|------|:----------:|------|
| ① | F 信号 = 有？ | F | lb 标签或号码无效 |
| ② | E 信号 = 有？ | E | E1拒接 / E2攻击 / E3拒缴 |
| ③ | B 信号 = 有且 ≥ B2？ | B | 反复困难或可验证困难 |
| ④ | D 信号 = 有？ | D | 无争议承诺 ≥ 2 次 |
| ⑤ | 无 F/E/B/D → C 细分 | C | 走下方 C 类判定 |

**C 类判定（客服端）：**
| 步 | 检查 | 命中→子类型 |
|:--:|------|:----------:|
| 1 | C1 信号 = 有 | C1·从众观望 |
| 2 | C2 信号 = 有 | C2·拖延观望 |
| 3 | C3 信号 = 有 | C3·对比观望 |
| 4 | C4 信号 = 有 | C4·信任缺失 |
| 5 | 无任何信号 | **不输出 C6**（C6 需小程序端确认无工单） |

### 客服端无法判断的信号（标记为"未知"）

| 信号 | 原因 |
|:----:|------|
| A | 需要工单数据（从小程序端读取） |
| E4 | 需要工单差评累积数据（从小程序端读取） |
| C5 | 需要 A 消除事件（发生在小程序端） |
| C6 | 需要确认小程序端也无信号 |

## 六、客服端分类补充说明

### 6.1 B 信号的"覆盖"特性

B 信号只取决于**最近一次通话**。这是客服端独有的逻辑：
- 上次通话业主说困难 → B=有
- 这次通话业主没说困难 → B=无
- 新通话永远覆盖旧通话的 B 信号判断

这意味着 B 信号是一个**高度时效性**的信号。

### 6.2 D 信号的"累积+衰减"特性

D 信号是**累积**的（每次"无争议"通话都会增加计数），但会**衰减**（7 天减 1）。

客服每次挂断后选择通话结果时：
- 选"无争议" → D 计数 +1，然后检查是否 ≥ 2（触发 D 信号）
- 选"有争议" → 不增加 D 计数，可能影响 A/E

### 6.3 C1~C3 的"首次命中"特性

C1~C3 只看**最近一次通话**的关键词匹配（和 B 信号一样）：
- 最近一次通话含从众关键词 → C1
- 最近一次通话含拖延关键词 → C2
- 最近一次通话含对比关键词 → C3
- 如果同时包含多类关键词 → 按优先级 C1 > C2 > C3 取第一个

## 七、客服端能做的辅助计算

### 信号强度（仅客服端有数据的信号）

| 信号 | 得分计算 |
|:----:|------|
| F 得分 | 有 = 100，无 = 0（二值） |
| B 得分 | 困难表达次数 × 35 +（未登录 +15）（上限100） |
| D 得分 | 有效计数 × 30 +（未登录 +20）（上限100） |
| E 得分 | 攻击通话 × 35 + 有效拒接 × 25 + 拒缴 × 30（上限100） |

### 轨迹追踪（仅基于客服端分类历史）
- 近 3 次客服端分类
- 趋势（向好/稳定/向坏）

## 八、客服端与小程序端的关系

```
┌─────────────────┐     ┌─────────────────┐
│   客服端分类      │     │   小程序端分类    │
│                 │     │                 │
│  独立检测:       │     │  独立检测:       │
│  F ✓ (唯一源)   │     │  A ✓ (核心)     │
│  B ✓ (唯一源)   │     │  E2/E4 ✓       │
│  D ✓ (唯一源)   │     │  C4 ✓          │
│  E1/E2/E3 ✓    │     │  C5 ✓ (唯一源)   │
│  C1/C2/C3 ✓    │     │  C6 ✓ (兜底)    │
│                 │     │                 │
│  需读取:         │     │  需读取:         │
│  li, 工单数据    │     │  lb 标签        │
└────────┬────────┘     └────────┬────────┘
         │                       │
         └───────────┬───────────┘
                     ▼
         ┌─────────────────────┐
         │     合并引擎          │
         │   OR 逻辑合并        │
         │   完整六信号状态       │
         │   F>E>A>B>D>C 判定   │
         │   最终分类输出        │
         └─────────────────────┘
```

**关键理解：**
- 客服端是 B/D/E(拒接/拒缴/攻击)/C1~C3 的**唯一产生源**
- 小程序端是 A/C5 的**唯一产生源**
- E 信号和 C4 信号两轨道都能产生，取 OR
- 两端的分类各自不完整，但互补——合在一起才构成完整的六信号判断依据

---

> **关键要点：**
> 1. 客服端核心依赖通话备注文本（nt）做关键词匹配
> 2. B/D/C1~C3 这些"业主态度类"信号只能由客服端产生
> 3. 客服端不能判断 A/C5/C6，这些需要小程序端数据
> 4. 客服端可以读取小程序端的 li 和工单数据（用于 D 消除、E 拒接修正、C4 交叉验证）
> 5. 客服端给出的分类是"不完整分类"，需要与小程序端数据合并
