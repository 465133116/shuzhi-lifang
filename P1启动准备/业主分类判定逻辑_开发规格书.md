# 业主分类判定逻辑 · 开发规格书

> 数治理方 P1 · V8.0 · 2026-06-30
> 本文档描述业主分类的完整判定逻辑，供开发人员直接对照实现。
> 不含代码，纯逻辑规则。每一条规则都可独立验证。

---

## 一、客服工作对分类的影响

在 P1 阶段，客服只做三件事。这三件事直接参与分类判定：

| 客服动作 | 说明 | 对分类的影响 |
|----------|------|-------------|
| **引导上线** | 引导业主了解并使用小程序，完成首次登录 | 业主登录后：① D 信号立即消除 ② E 拒接计数修正 ③ 产生第一条行为数据，结束 C6 状态 |
| **创建草稿工单** | 通话中确认业主需求 → 选标签 → 补描述 → 推送业主确认 → 生成正式工单 | 草稿创建后：① 触发 A 信号（如果当前没有小程序工单）② 业主确认后正式工单生效，A 信号进入正常生命周期 |
| **回访** | 工单完成后联系业主验收、打分、挖掘新需求 | 回访后：① 满意度评分决定 A 信号是否消除 ② 差评原因触发副作用（态度差评+1 / D 计数+1）③ 可能发现新需求 → 创建新草稿 |

客服在两个节点介入分类生命周期：**起点**（外呼建草稿，触发 A 信号）和**终点**（回访验收，决定 A 消除或升级）。

## 二、数据输入

分类引擎接收一个业主对象，包含以下数据：

### 2.1 来自小程序轨道（📱）
| 数据项 | 含义 | 取值 | 来源 |
|--------|------|------|------|
| 业主是否登录过小程序 | li | 是 / 否 | 小程序埋点 |
| 历史工单列表 | 每条工单含以下字段 | — | 工单系统 |
| ——工单类型 | tp | 报修 / 投诉 / 建议 | 工单系统 |
| ——工单状态 | st | 待处理 / 处理中 / 待验收 / 已完成 | 工单系统 |
| ——满意度评分 | rt | 1~5 星（仅已完成工单有） | 客服回访时采集 |
| ——差评原因 | — | 问题没解决 / 态度不好 / 太慢 / 其他（仅1-2星时有） | 客服回访时采集 |
| ——工单描述文本 | de | 自由文本 | 业主提交或客服草稿 |
| ——工单来源 | sr | 业主自提 / 客服草稿 | 系统标记 |
| ——问题分类 | ca | 水管漏水 / 电梯故障 / … | 客服创建草稿时选定 |
| ——创建时间 | ct | 日期 | 系统记录 |
| 特殊标签 | lb | 自由文本（如"已搬家""出租"） | 客服标注 |

### 2.2 来自客服轨道（🎧）
| 数据项 | 含义 | 取值 | 来源 |
|--------|------|------|------|
| 历史通话记录列表 | 每条记录含以下字段 | — | 客服系统 |
| ——通话结果 | rs | 已接通 / 拒接 / 无争议 / 有争议 | 客服挂断后选择 |
| ——通话备注文本 | nt | 自由文本（客服录入 + 语音识别） | 客服录入 |
| ——通话时间 | t | 日期 | 系统记录 |

## 三、总体判定流程

```
第一步：两轨道各自独立检测信号（并行，互不干扰）
          📱小程序 → 检测 A / E(攻击/差评) / C4 / C5
          🎧客服   → 检测 B / D / E(拒接/拒缴/攻击) / C1 / C2 / C3

第二步：信号合并
          每个信号取两轨道 OR —— 任一轨道检测到 = 该信号为"有"

第三步：主分类判定
          按 F → E → A → B → D → C 顺序检查
          第一个"有"的信号 → 主分类
          其余"有"的信号 → 辅助维度

第四步：子类型判定
          在主分类内部，根据具体条件判定细分类型

第五步：辅助维度计算
          信号强度 / 交叉模式 / 响应级别 / 轨迹追踪
```

## 四、小程序轨道信号检测

### 规则 MP-1：检测 A 信号（有具体争议）

**客服动作关联：创建草稿工单**

判断逻辑：
- 遍历该业主所有工单
- 如果存在任意一条工单同时满足：
  - 工单类型 = "报修" 或 "投诉"
  - 工单状态 ≠ "已完成"
- → A 信号 = 有

补充规则：
- 客服草稿（来源=客服草稿）也计为工单，参与上述判断
- 但如果同一问题业主已自行提交了小程序工单，草稿不重复计入
- 建议类工单（类型=建议）不触发 A 信号
- **客服引导上线成功后**：业主可能自行提交工单 → 同样触发 A 信号

---

### 规则 MP-2：检测 E 信号（对抗态度·攻击型/差评累积型）

**客服动作关联：回访时采集差评原因**

判断逻辑（分两条子规则，任一命中即 E=有）：

**子规则 MP-2a：攻击性投诉检测**
- 遍历所有工单的描述文本
- 如果某条工单的描述包含攻击性关键词（辱骂、威胁等）→ E 信号 = 有，子类型 = E2·攻击型

**子规则 MP-2b：态度差评累积检测**
- 统计已完成工单中同时满足以下条件的数量：
  - 满意度 = 1 星或 2 星
  - 差评原因 = "态度不好"
- 如果数量 ≥ 3 → E 信号 = 有，子类型 = E4·差评累积型
- **注意：差评原因由客服在回访时采集，不是系统自动生成的**

---

### 规则 MP-3：检测 C4 信号（信任缺失）

判断逻辑：
- 同时满足以下三个条件 → C4 信号 = 有
  - 条件一：历史工单中存在满意度为 1 星或 2 星的记录
  - 条件二：不存在类型为"投诉"的正式工单（有不满但没正式投诉）
  - 条件三：当前无 A 信号（所有工单都已闭环）
- **客服动作关联：回访时发现的隐性不满（业主说"以前服务不好"但从未正式投诉）→ 客服可在通话备注中记录 → 由客服轨道 C4 检测补充**

---

### 规则 MP-4：检测 C5 信号（已解决过渡态）

**客服动作关联：回访后工单闭环**

判断逻辑：
- 同时满足 → C5 信号 = 有
  - 历史上曾有过 A 信号（即曾有过未闭环工单）
  - 当前 A / B / D / E / F 信号全部为无
- 这是客服回访后的典型过渡状态：工单修好了、业主满意、等待业主的后续行为反馈

---

### 规则 MP-5：A 信号消除条件

**客服动作关联：回访验收**

当客服完成回访、一条工单状态变为"已完成"时，按以下规则判定 A 信号是否消除：

| 回访结果 | A 信号 | 副作用 |
|----------|:------:|--------|
| 修后照片 ✓ + 处理结果 ✓ + 满意度 ≥ 3 星 | **消除** | 无 |
| 差评 1-2 星 · 原因 = "问题没解决" | **保持** | 工单自动重开 |
| 差评 1-2 星 · 原因 = "态度不好" | **消除** | 态度差评计数 +1，累计 3 次 → E4 |
| 差评 1-2 星 · 原因 = "太慢" | **消除** | D 计数 +1 |
| 差评 1-2 星 · 原因 = "其他" | **消除** | 无 |
| 修后照片缺失 | **保持** | 标记证据不完整，等待补全 |

## 五、客服轨道信号检测

### 规则 CS-1：检测 B 信号（经济困难）

**客服动作关联：引导上线或创建草稿时，通话中业主主动表达**

判断逻辑：
- 取该业主**最近一次通话**的通话备注文本
- 如果文本包含以下任意一个困难关键词：
  "手头紧"、"失业"、"困难"、"没钱"、"交不起"、"实在困难"、"经济紧张"、
  "最近不容易"、"收入少"、"没工作"、"低保"、"吃不起"
- → B 信号 = 有

重要规则：
- **只看最近一次通话**。新通话的备注覆盖旧通话，B 信号随之更新
- 如果最新通话备注不含困难关键词 → B 信号 = 无（即使历史上说过困难）

B 信号等级：
- 历史上困难表达仅 1 次（含本次）→ B1·自述（**不能做主分类，只能做辅助**）
- 历史上困难表达 ≥ 2 次 → B2·反复（**可以做主分类**）
- 业主提供困难证明文件（失业证/低保证/医疗单据等）→ B3·可验证（**可以做主分类**）

---

### 规则 CS-2：检测 D 信号（惯性失约）

**客服动作关联：引导上线时业主口头承诺但未行动**

判断逻辑：
- 统计所有通话中，通话结果为"无争议"的次数（业主口头承诺会缴费/会上线，但实际未行动）
- 应用衰减规则（见第八章）得到有效计数
- 如果有效计数 ≥ 2 → D 信号 = 有
- 否则 → D 信号 = 无

D 信号强度分级：
| 有效计数 | 子类型 | 含义 |
|:--------:|:------:|------|
| 1~2 | D1·轻度惯性 | 刚开始出现失约苗头 |
| 3~4 | D2·中度惯性 | 已形成模式 |
| ≥ 5 | D3·重度惯性 | 惯犯 |
| D≥D2 且 近14天拒接≥2 | D4·沉默型 | 承诺后失联 |

**关键规则：业主登录小程序 → D 信号直接消除。**
客服引导上线成功 = li 从 false 变 true → D 立即归零。这是客服工作对分类最直接的正向影响。

---

### 规则 CS-3：检测 E 信号（对抗态度）

**客服动作关联：外呼时遇到拒接/攻击/明确拒缴**

分三条子规则，任一命中即 E=有：

**子规则 CS-3a：拒接累积**
- 统计通话结果为"拒接"的次数
- 有效拒接 = 拒接次数 − 小程序工单数（最小为 0）
  - 含义：如果业主拒接电话但在小程序上提交过工单，说明他只是不想接电话而不是真的对抗
- 有效拒接 ≥ 3 → E 信号 = 有，子类型 = E1·拒接型

**子规则 CS-3b：明确拒缴**
- 最近一次通话备注含"不交"、"死也不交"、"绝对不交"等明确拒缴表述
- → E 信号 = 有，子类型 = E3·拒缴型

**子规则 CS-3c：攻击性通话**
- 最近一次通话备注含攻击性关键词（辱骂、威胁等）
- → E 信号 = 有，子类型 = E2·攻击型

---

### 规则 CS-4：检测 C1 信号（从众观望）

**客服动作关联：引导上线时业主表达"别人用了我再用"**

判断逻辑：
- 最近一次通话备注包含以下任意关键字：
  "别人交我就交"、"大家都交了吗"、"交的人多吗"、"有多少人交了"、
  "别人也没交"、"都拖着呢"、"等别人先交"、"邻居交了我就交"、"随大流"、
  "别人用我就用"、"大家都用了吗"、"有人用吗"
- → C1 信号 = 有

---

### 规则 CS-5：检测 C2 信号（拖延观望）

**客服动作关联：引导上线时业主表达"不急"**

判断逻辑：
- 最近一次通话备注包含以下任意关键字：
  "不急"、"再看吧"、"到时候再说"、"过段时间"、"再说"、
  "不急这一时"、"不着急"、"等等看"、"观望一下"
- → C2 信号 = 有

---

### 规则 CS-6：检测 C3 信号（对比观望）

**客服动作关联：引导上线时业主拿其他小区对比**

判断逻辑：
- 最近一次通话备注包含以下任意关键字：
  "隔壁小区"、"人家那边"、"凭什么我们"、"别的小区"、
  "人家小区"、"别的地方"、"我们小区不如"、"看看人家"
- → C3 信号 = 有

---

### 规则 CS-7：检测 C4 信号（信任缺失·客服轨道）

**客服动作关联：回访或引导上线时业主表达不满但未正式投诉**

判断逻辑：
- 同时满足 → C4 信号 = 有
  - 最近一次通话备注包含不满关键词（"物业不管"、"服务差"、"以前"、"失望"、"不负责"、"总是拖"）
  - 该业主不存在类型为"投诉"的正式工单（由小程序轨道验证）

---

## 六、客服引导上线的特殊规则

引导上线是客服的核心工作之一。以下规则专门处理"引导上线"对分类的影响：

### 规则 GL-1：引导上线成功

触发条件：业主 li 从 false 变为 true（首次登录小程序）

对分类的影响：
- D 信号 → 立即消除（登录行为被认为是最强的履约信号）
- E 拒接计数 → 有效拒接次数减 1（有工单行为，拒接不完全算对抗）
- C6 → 不再适用（有行为数据了，结束"信息不足"状态）
- 触发一次全量重算

### 规则 GL-2：引导上线失败

如果客服连续外呼 ≥ 3 次，业主未登录且未创建任何工单：
- 该业主的 C 类子类型如果为 C6·信息不足 → 保持不变
- 同时 E 类拒接计数正常累计（每次拒接 +1）
- 可能触发路径：C6 → 拒接累积 → E1

### 规则 GL-3：引导上线话术关键词（影响 C 类判定）

客服在引导上线过程中，业主的口头回应产生以下分类影响：

| 业主说的是 | 触发分类 | 含义 |
|-----------|:--------:|------|
| "别人用了我再用"、"有人用吗" | C1·从众观望 | 等待社会证明 |
| "不急"、"回头再说" | C2·拖延观望 | 无紧迫感 |
| "隔壁小区也没有" | C3·对比观望 | 对标其他小区 |
| "之前物业太差了"（但无投诉） | C4·信任缺失 | 隐性不满 |
| "好的我试试"并登录 | 正向转化 | D 消除 + 可能结束 C 状态 |

## 七、信号合并规则

对六个信号（F、E、A、B、D、C），分别：
- 取小程序轨道结果 和 客服轨道结果
- 任一为"有" → 合并后 = "有"
- 都为"无" → 合并后 = "无"

特殊情况：
- **F 信号**：仅客服轨道产生（lb 标签）。一旦为"有"，直接主分类 = F，跳过后续全部判定。
- **E 信号**：两轨道都能产生。合并时子类型优先级：E2 攻击型 > E3 拒缴型 > E1 拒接型 > E4 差评累积型。
- **C 信号**：不独立检测，由判定流水线推导。F/E/A/B/D 全部为"无"时走 C 类细分。

---

## 八、主分类判定流水线

按顺序检查，命中第一条即停止。

### 判定 1：是否为 F 类？

**条件：** F 信号 = 有（lb 含特殊关键词或号码无效）

**命中 → 主分类 = F。** 判定结束。

子类型：
- lb 含"已搬家"/"已出售"/"产权变更" → F·产权变更
- lb 含"继承"/"遗产"/"过户中" → F·继承纠纷
- lb 含"出租"/"租客"/"不在这住" → F·出租
- 号码空号/停机/错号 → F·号码无效
- 非服务范围 → F·未覆盖

---

### 判定 2：是否为 E 类？

**条件：** E 信号 = 有（且 F = 无）

**命中 → 主分类 = E。** 判定结束。

子类型（按优先级取最高）：
- 有攻击性投诉或攻击性通话 → E2·攻击型
- 通话中明确说"不交" → E3·拒缴型
- 有效拒接 ≥ 3 次 → E1·拒接型
- 态度差评 ≥ 3 次 → E4·差评累积型

**客服动作：** E 类业主的引导上线优先级降低。优先用短信引导，而非持续外呼。

---

### 判定 3：是否为 A 类？

**条件：** A 信号 = 有（且 F/E = 无）

**命中 → 主分类 = A。** 判定结束。

**客服动作：** A 类业主已有具体问题要解决。客服优先处理工单（草稿推送确认、跟进处理进度），回访验收时再顺便引导上线。

子类型：
- 报修 ≥ 1 且投诉 = 0 → A·报修型
- 投诉 ≥ 1 且报修 = 0 → A·投诉型
- 报修 ≥ 1 且投诉 ≥ 1 → A·混合型
- 同 ca 的工单 ≥ 3 次 → A·反复型
- 未闭环 ≥ 3 或超 SLA ≥ 7 天 → A·高优先级型（附加标记）
- 历史上无 A 消除记录 → A·首次型（附加标记）

---

### 判定 4：是否为 B 类？

**条件：** B 信号 = 有，且证据等级为 B2 或 B3（且 F/E/A = 无）

**命中 → 主分类 = B。** 判定结束。

**客服动作：** B 类业主经济困难。引导上线时侧重"有问题可以报修、不花钱"，不提缴费。

注意：B1·自述不能做主分类。此时 B 仅作为辅助维度，继续向下判定。

---

### 判定 5：是否为 D 类？

**条件：** D 信号 = 有（有效计数 ≥ 2），且 F/E/A/B = 无

**命中 → 主分类 = D。** 判定结束。

**客服动作：** D 类业主多次口头承诺但未行动。**引导上线是核心破局手段**——一旦引导成功（li=true），D 信号直接消除。

子类型：按有效计数分级（D1 轻度 / D2 中度 / D3 重度 / D4 沉默型）

---

### 判定 6：C 类细分判定

**条件：** F/E/A/B/D 全部为无。

C 类判定流水线（按顺序）：

1. **C5·已解决？** — 历史上曾有 A 消除记录且当前无任何信号 → 命中
2. **C1·从众观望？** — C1 信号 = 有 → 命中
3. **C2·拖延观望？** — C2 信号 = 有 → 命中
4. **C3·对比观望？** — C3 信号 = 有 → 命中
5. **C4·信任缺失？** — C4 信号 = 有 → 命中
6. **C6·信息不足？** — 以上全不命中 → 兜底

**客服动作：** C 类业主是引导上线的**最高优先级群体**。C1~C4 各有不同的引导角度，C6 是纯新业主需要首次破冰。

---

## 九、辅助维度

### 9.1 辅助信号
所有在判定流水线中"有"但未被选为主分类的信号 → 辅助信号。例如：主分类=A，B=有，D=有 → 辅助信号 = [B, D]。

### 9.2 信号强度（0~4）

每个信号独立计算得分，映射到五级：

| 得分 | 强度 | 图标 |
|:----:|:----:|:----:|
| 0 | 0·无 | ○ |
| 1-25 | 1·弱 | ◐ |
| 26-50 | 2·中 | ◑ |
| 51-75 | 3·强 | ● |
| 76-100 | 4·极强 | ⬤ |

得分公式：
- **A 得分** = 未闭环数 × 40 + 报修总数 × 15 + 投诉总数 × 20 − 平均满意度 × 10（上限 100）
- **B 得分** = 困难表达次数 × 35 +（未登录 +15）（上限 100）
- **D 得分** = 有效计数 × 30 +（未登录 +20）（上限 100）
- **E 得分** = 攻击次数 × 35 + 有效拒接 × 25 + 拒缴次数 × 30 + 差评次数 × 20（上限 100）

### 9.3 交叉模式（8 种）

| 交叉模式 | 条件 |
|----------|------|
| 争议+困难 | A=主 且 B 得分 ≥ 40 |
| 争议+惯性 | A=主 且 D 得分 ≥ 50 |
| 对抗+困难 | E=主 且 B 得分 ≥ 40 |
| 对抗+惯性 | E=主 且 D 得分 ≥ 50 |
| 困难+惯性 | B=主 且 D 得分 ≥ 50 |
| 恶化中 | 近 7 天主分类向差迁移 ≥ 1 级（C→A、C→E、A→E） |
| 好转中 | 近 7 天主分类向好迁移 ≥ 1 级（E→A、A→C、D→C） |
| 首次信号 | 当前主分类历史上首次出现 |

### 9.4 响应级别（R0~R4）

| 级别 | 触发条件 | 时效 | 优先级加成 |
|:----:|----------|:----:|:----------:|
| R0·紧急 | A+未闭环≥3 / E新触发(<7天) / 恶化中 | 24h | +20 |
| R1·优先 | 主分类得分≥70 / 交叉=争议+惯性或对抗+困难 | 48h | +10 |
| R2·常规 | 普通活跃信号，得分<70 | 本周 | 0 |
| R3·观察 | C类(除C5) / 得分<40 | 不限 | -5 |
| R4·静默 | C6沉睡>60天 / F类 / E1连续2月拒接 | 不主动 | -20 |

### 9.5 优先级分

最终优先级分 = 紧急度(上限40) + 恶化风险(上限35) + 影响力(上限25) + 响应加成(-20~+20)

### 9.6 轨迹追踪

- **近 3 次主分类：** ["C","C","A"]
- **趋势：** worsening / stable / improving
- **迁移速度：** 7天变化 ≥ 2级 = fast
- **新鲜度：** ≤24h=just_now / 1-3天=recent / 4-7天=this_week / >7天=stale

## 十、时间衰减规则

### 10.1 工单类（30天半衰）
适用于：A、E(攻击/差评)、C4、C5

衰减因子 = e^(-天数 / 30)。例如 30 天前的工单权重降为 37%。

### 10.2 通话类（14天半衰）
适用于：B、D、E(拒接/拒缴)、C1~C3

衰减因子 = e^(-天数 / 14)。例如 14 天前的通话权重降为 37%。

### 10.3 D 信号阶梯衰减
距上次无争议承诺每满 7 天，有效计数自动减 1：
- 例：3 次承诺，最近一次距今 8 天 → 有效计数 = 2
- 例：3 次承诺，最近一次距今 22 天 → 有效计数 = 0 → D 消除

### 10.4 E 信号降级
- 拒接计数：接通一次电话 → 立刻归零
- 有效拒接 = 原始拒接 − 小程序工单数（最小为 0）
- 连续 60 天无新攻击 + 无拒接 → E 降级为 C5

**客服动作关联：** 如果客服成功引导业主登录小程序，E 拒接计数自动减少（有工单行为=不完全对抗），可能促使 E 降级。

## 十一、重算触发条件

以下任一事件发生后，对该业主重新执行完整判定流程（第一步到第五步）：

| 事件 | 客服动作关联 | 可能影响的信号 |
|------|-------------|---------------|
| 业主提交新的小程序工单 | 引导上线成功后的自然行为 | A、E(攻击投诉) |
| 客服创建草稿工单 | **创建草稿工单** | A |
| 工单状态变为"已完成" | **回访验收** | A 消除、C5 产生 |
| 客服完成通话并录入记录 | **每次外呼后** | B/D/E/C1~C3 |
| 客服修改业主 lb 标签 | 业务标注 | F |
| 业主首次登录小程序 | **引导上线成功** | D 消除、E 修正、结束 C6 |

---

## 十二、信号独立性原则

各信号的产生和消除是独立的。一个信号消除不影响其他信号。

唯一例外（与客服工作直接相关）：
- **客服引导上线成功（li=true）→ D 信号直接消除**。登录行为被认为比口头承诺更可信。
- 小程序工单数影响 E 拒接修正：有工单行为 → 拒接不完全算对抗。
