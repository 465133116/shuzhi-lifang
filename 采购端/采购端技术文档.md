# 数治理方 · 采购端技术文档

> 版本：v17（localStorage 持久化版本号） · 更新日期：2026-09-09
> 适用范围：`采购端/采购端.html`（四角色源文件）+ 四个拆分文件（物业/业委会/社区/商家）+ `shuzhi_demo_pack.html`（三端演示包）
> 技术栈：纯前端单文件（HTML + 内嵌 CSS/JS，无外部依赖）；数据持久化 localStorage；跨文件联动 BroadcastChannel。

## 1. 系统概述

### 1.1 四端角色

| 端 | 文件 | 职责 | 核心权力 |
|----|------|------|---------|
| 物业 | 采购端_物业.html | 发起采购、比价推荐、履约申报、验收初验 | **推荐供应商**（无选定权） |
| 业委会 | 采购端_业委会.html | 审批、选定定标、验收最终确认 | **审批 + 选定定标** |
| 社区 | 采购端_社区.html | 全街道监督查阅、L3 备案接收 | **只读 + 备案接收** |
| 商家 | 采购端_商家.html | 入驻申请、询价响应、报价、履约上报 | 报价（12h 内可改） |

**治理红线**（代码强制，非文案）：
- 物业只能推荐，不能选定（`pickQuote` 对非 yw 角色 toast 拦截）
- 业委会选定即定标（选商+定标一体，不产生"待定标"）
- 社区零操作按钮，唯一动作 = L3 大额采购备案接收
- 商家预算保密：任何商家界面不得显示采购预算上限（显示"面议（预算保密）"）
- 采购角色（物业/业委会）不得出现商家入驻申请表单（T2 审批在业委会端为"入驻审批"模块，与商家端"入驻申请"是两个不同的东西）

### 1.2 数据存储

| 键 | 用途 |
|----|------|
| `sgzf_cg_state_v1` | 全部业务数据快照（版本字段 v=17） |
| `sgzf_login_wy/yw/sq/sj` | 四端登录状态（'1'=已登录） |

### 1.3 跨文件联动

- 通道：`BroadcastChannel('sgzf_cg_sync')` + `storage` 事件双通道
- 消息：`'upd'`（数据更新）、`'reset'`（复位）
- 接收守卫（任一命中则**静默同步不重绘**）：详情页打开 `_busyDetail` → 弹窗 `.ov` 存在 → `actMask` 显示 → 输入焦点在 INPUT/TEXTAREA/SELECT → `pointerdown` 600ms 内
- **活跃守卫目的**：不打断操作者（按钮在 mouseup 前被重建 = 点击丢失）

## 2. 登录体系

### 2.1 独立全屏登录页

- 打开文件 → 全屏登录页（`#loginPage`，不透明遮挡主界面，非弹窗）
- 账号密码**预填**（演示即点即进）
- 登录成功 → 移除登录页 + `localStorage.setItem('sgzf_login_<role>','1')`
- 刷新保持登录；🚪 顶栏按钮退出（三端 reload 回登录页；商家弹回登录页）

### 2.2 账号表

| 端 | 账号 | 密码 |
|----|------|------|
| 物业 | wy | 123456 |
| 业委会 | yw | 123456 |
| 社区 | sq | 123456 |
| 商家 | 下拉选商家名（通力电梯/金盾消防 + 动态新入驻商家） | 123456 |

### 2.3 商家登录特殊逻辑

- 罩层登录：`gateLogin` 商家分支 → 把罩层下拉值写入入口页 `lgSel` → `sjLogin()` → 关罩层（顺序不可反：先 close 会删 `lgP` 导致校验失败）

- 商家退出：`sjLogout` 清登录位 + 弹回登录页

## 4. 采购全流程状态机

### 4.1 状态枚举

```
待审批 → 比价中 → 已定标 → 合同(待签订) → 履约中 → 待初验/待验收
        → 待业委会确认 → 已验收 → 已公示
支线：已驳回（审批驳回） / 已拦截（拆单闸） / 待定标（兼容旧数据） / 待业主大会（超业委会权限金额）
```

### 4.2 分步流转规则

**① 发起采购（物业 / 业委会均可）**

| 发起方 | 金额 | 订单状态 | 询价行为 |
|--------|------|---------|---------|
| 物业 | >2000 | 待审批 | 勾选商家→定向询价**立即可报价**（并行）；未勾选→公开寻单挂"待审批"闸 |
| 物业 | ≤2000 | 已定标 | 定向询价立即进商家队列；未勾选→公开寻单直接上广场 |
| 任意角色 | >50000 | **待业主大会** | 超业委会权限上限（示例）→ 开启业主大会审议，通过后进比价 |
| 业委会 | 任意 | 比价中（免审批） | 同上分流，公开寻单免审批闸 |

**② 审批（业委会）**

- 批准 `approveOK`：订单→比价中；公开寻单 RFQ 待审批→待报价（上广场）
- 驳回 `approveNo`：订单→已驳回；RFQ 原地 splice 移除（保持 alias 引用）
- 审批依据：五道闸 + **已收报价详情**（审批与报价并行，审批卡显示每家报价的金额/工期/质保/信用/说明/附件）

**③ 比价与推荐/选定**

- 商家报价 → QUOTES[oid] 累计
- 物业：填理由 →「📝 推荐该供应商」→ `o.recommend` 留痕（状态不变）
- 业委会：填理由 →「✓ 选定该供应商」→ **直接已定标** + `o.vend=商家名` + `o.reason` 留痕
- 选定即生成合同 `makeContract`（自动编号 HT-2026-xx，状态"待签订"）

**④ 履约**

- 商家端「履约上报」：选订单 → 弹窗 → 四类证据上传 → 提交 → 订单"待验收"
- 商家证据同步到采购单 `sjFiles`（跨角色可见）

**⑤ 验收（双路径）**

- L1 自主单（path='—'）：物业直接验收闭环（无业委会环节）
- 业委会审批单（两级验收）：物业初验（核对商家证据+上传核验+评分+意见）→ 待业委会确认 → 业委会对查双方证据 → 确认闭环 或 退回
- 验收评分回传供应商池（更新商家信用）

**⑥ 公示与备案**

- 验收闭环 → 三级透明公示记录
- L3 大额单：社区端「备案接收」（社区唯一操作）→ 备案即公示

### 4.3 状态转换函数表

| 函数 | 转换 | 触发角色 |
|------|------|---------|
| submitPO | 发起 → 待审批/比价中/已定标 | 物业/业委会 |
| approveOK | 待审批 → 比价中 | 业委会 |
| approveNo | 待审批 → 已驳回 | 业委会 |
| recQuote | （无状态变化）写 recommend | 物业 |
| pickQuote | 比价中 → 已定标 | 业委会 |
| makeContract | 已定标 → 生成合同 | 自动 |
| submitPerf | 履约中 → 待验收 | 商家 |
| submitAccept | 待初验 → 待业委会确认 / 待验收 → 已验收 | 物业 |
| confirmAccept | 待业委会确认 → 已验收 | 业委会 |
| returnAcceptOv | 待业委会确认 → 退回待初验 | 业委会 |
| doAct | 备案接收/定标确认（兼容） | 社区/业委会 |

## 5. 五道闸（gatesCalc）

| 闸 | 判定 | 阈值 | 不通过后果 |
|----|------|------|-----------|
| 预算闸 | 金额 ≤ 年度预算余额 | 示例 ¥120,000 总额 | WARN 提示预算追加审议 |
| 审批闸 | 金额 >2000 → 提交业委会审批；金额 >50000 → 业主大会 | ¥2,000 / ¥50,000（合同可配） | 进待审批 / 转业主大会 |
| 比价闸 | 金额 >5000 → 三方比价 | ¥5,000（合同可配） | 否则两家询价留痕 |
| 拆单闸 | 近 7 天同类目采购合并检测 | 自动 | **拦截提交**（提交失败 toast） |
| 利益冲突闸 | 供应商与采购相关人无关联 | 自动 | 拦截 |

拆单闸是**硬拦截**（`gatesCalc` 返回 -1 → `submitPO` 直接 return），其余为提示/分流。

## 6. 询价体系

### 6.1 双轨制

| 类型 | 触发 | 报价方 | 截止 | 终止 |
|------|------|--------|------|------|
| 定向询价 | 发起时勾选候选供应商 | 仅被勾选商家（vpool） | 无 | 无 |
| 公开寻单 | 发起时未勾选供应商 | 全部在池商家 | deadline（3/7/15/30 天） | 物业/业委会可提前终止 |

### 6.2 可见性规则 `sjRfqVisible(x)`

```
公开任务(pub) → 所有商家可见
定向询价 → vpool 含自己 或 关联订单 vend===自己 才可见
```

### 6.3 状态闸（st）

| 场景 | st 值 | 商家可见？ |
|------|-------|-----------|
| 物业发起大额定向 | 待报价（并行报价） | ✓ 立即可报 |
| 物业发起大额公开 | 待审批 | ✗ 广场不可见 |
| 业委会批准公开单 | 待报价 | ✓ 上广场 |
| 物业发起小额（定向/公开） | 待报价 | ✓ |
| 定向询价被报价后 | 已报价 | 商家端从下拉消失 |

**铁律：广场/工作台/报价管理三处可见性过滤必须同时检查 `st==='待报价'`。**

### 6.4 公开寻单额外规则

- 多商家可报（不设"已报价"态）
- 截止后不可报价（`ddlLeft(deadline).over` 校验）
- 提前终止 `stopMarket` → status='已终止' → 广场移入"已截止/已终止"区，已收报价保留
- 广场显示：实时倒计时 + 已收报价数

## 7. 报价体系

### 7.1 报价入口

- **定向询价**：报价管理下拉 →「📝 填写报价」→ `quoteOv` 统一弹窗
- **公开寻单**：采购广场「参与报价」→ `pubQuoteOv` 弹窗

### 7.2 报价弹窗字段

| 字段 | 必填 | 说明 |
|------|------|------|
| 报价金额 | ✓ | |
| 工期 | 选 | |
| 质保/服务 | 选 | |
| 报价说明（textarea） | 选 | 5 行起步、100% 宽、min-height 110px、可拖拽 |
| 关联附件 | 选 | 图片(jpg/png/webp/gif)/文档(pdf/doc/xls) 多选，chips 显示可删 |

### 7.3 提交规则

- 防重：每商家对同一询价限报一次（`QUOTES[oid].some(name===SJ.name)`）
- 截止校验（公开寻单）
- 写入：`SJ_DEMO.quotes.unshift({name:SJ.name,...})` + `QUOTES[oid].push(...)`（有 oid 时）
- **12 小时修改窗口**：`ts` 首报时间戳，12h 内可修改（修改不刷新窗口），超时锁定 🔒
- 修改留痕：报价记录 note 追加

### 7.4 报价归属

- 全局池每条报价带 `name`（商家名）
- 商家端"我的报价记录"渲染：`filter(!q.name||q.name===SJ.name)`（老数据无 name 兼容显示）
- 新商家注册后报价记录为空表（看不到任何其他商家的报价）

## 10. 恢复手势与版本管理

- **复位**：顶栏小区选择器连点 5 次（pointerdown/click 双通道，间隔<800ms）
- 复位动作：清空全部 `sgzf_` 前缀 localStorage 键 → 广播 'reset' → reload
- **复位守卫**：`saveState` 开头检查 `window._resetting`，防止 reload 前 focus 等事件把旧数据写回
- **多文件同步复位**：storage 事件 `newValue===null` → 本页也置复位标志 + reload
- **版本号**：数据模型任何变更必须 bump v（当前 v17），旧快照 loadState 时 `s.v!==17` 直接忽略自愈

## 11. 跨文件同步细节

1. 操作者动作 → `render()` 结尾自动 `saveState()`（diff 去重 `_lastSaved`）
2. `saveState` → `localStorage.setItem` + `SYNC.postMessage('upd')`
3. 接收方 onmessage：loadState → 活跃守卫 → 空闲才 render
4. storage 事件兜底（跨 tab）
5. **COMM（小区选择）是本地 UI 状态，不跨文件同步**
6. **saveState 快照禁止含时间戳等易变字段**（曾引发死循环闪烁）
