# 数治理方 · 物业端 产品设计文档

> **全称：** 社区制度型信用治理系统平台 — 物业端
> **品牌：** 数治理方
> **端口定位：** 七端生态中的服务执行端
> **端口口号：** "如我在居 · 共享家"
> **端口形态：** PC 网页后台（含移动端适配）
> **角色用户：** 物业经理、物业管家、维修工、系统操作员、采购专员
> **依据文件：** 鄞社发〔2026〕6号 + 端口矩阵（调整稿）

---

## 一、端口概述

### 1.1 定位与角色

物业端是数治理方七端生态中的**服务执行端**，承载物业公司面向业主的全部履约行为。它是连接业主诉求与物业服务的桥梁，也是社区治理闭环中"执行—反馈—评价"的核心枢纽。

在七端生态中，物业端的定位是：

```
业主端（提诉求）→ 物业端（接单执行）→ 业委会端（监督评价）
                    ↑↓
        AI端（智能分派/审核） + 社区端（制度治理）
```

### 1.2 端口口号："如我在居 · 共享家"

"如我在居"体现物业从业者的服务伦理——把业主的房子当成自己家来维护；"共享家"呼应社区治理的终极目标：业主、物业、业委会三方共建共享美好家园。

### 1.3 端口用户矩阵

| 角色 | 职责范围 | 系统权限 |
|------|----------|----------|
| 物业经理 | 全端口管理、数据决策、信用管理 | 全部功能 + 数据导出 + 日志审计 |
| 物业管家 | 负责特定楼栋/片区的工单跟进、业主沟通 | 工单处理 + 业主信息（脱敏）+ 公告编辑 |
| 维修工 | 接单、维修、上传凭证 | 工单接单/处理/提交 + 维修金申报协助 |
| 系统操作员 | 费用台账、数据录入、审核辅助 | 费用管理 + 业主审核 + 公共收益管理 |
| 采购专员 | 供应商管理、近场采购、合同管理 | 近场采购模块 + 合同管理 |

### 1.4 技术形态

- **主界面：** PC 网页后台（响应式适配1920×1080为主）
- **移动端：** 微信小程序/企业微信内嵌 H5（管家/维修工外勤使用）
- **数据互通：** 通过生态系统共享数据桥（EcosystemBridge）与业主端、业委会端、AI端、社区端实时同步
- **AI 集成：** 工单智能分派、业主审核 AI 初审、SLA 超时预警、维修金材料 AI 匹配

## 二、工单处理中心

### 2.1 功能概述

工单处理中心是物业端的核心工作区，承载从**接收业主诉求 → AI分派 → 接单处理 → 结果反馈 → 业主评价**的完整闭环。

### 2.2 诉求接收

#### 2.2.1 诉求来源

| 渠道 | 说明 |
|------|------|
| 业主端小程序 | 业主自主提交报修/投诉/建议，自动写入工单池 |
| 客服端转派 | 客服外呼过程中记录的业主诉求，转为正式工单 |
| 社区端推送 | 社区/网格员发现的公共区域问题 |
| 物业自查 | 巡检中发现的设备故障/安全隐患，主动创建工单 |

#### 2.2.2 诉求分类

| 一级分类 | 二级分类 | AI 初判优先级 |
|----------|----------|:--:|
| 报修 | 水电类 / 公共设施 / 电梯 / 消防 / 安防 / 其他 | 紧急→普通 |
| 投诉 | 服务质量 / 人员态度 / 收费争议 / 环境卫生 / 噪音扰民 / 其他 | 优先→标准 |
| 建议 | 社区治理 / 设施改进 / 服务优化 / 其他 | 标准→普通 |
| 咨询 | 物业费 / 维修金 / 业主权益 / 办事流程 / 其他 | 标准 |

### 2.3 AI 智能分派与 SLA 计时

#### 2.3.1 分派逻辑

工单进入系统后，AI 端自动执行：

1. **OCR/关键词提取：** 解析诉求文本与图片附件
2. **紧急度判定：** 根据关键词（"漏水""漏电""电梯困人""消防"）自动标记紧急
3. **工种匹配：** 匹配对应工种的维修工人（水电工、泥瓦工、电梯维保等）
4. **负载均衡：** 考虑当前工单量、在岗状态、距离（外勤定位）进行分派
5. **归属路由：** 根据楼栋/片区自动匹配责任管家

**咨询类工单特殊说明：** 咨询工单由AI先尝试自动回复。AI无法回答的咨询自动转入物业端工单列表，由物业人员人工回复——回复内容回传业主端，AI的初次回复保留可见。物业回复后工单闭环。

#### 2.3.2 SLA 四级计时规则

**分派即计时**——工单一旦生成并分派，SLA 计时器立即启动。

| 等级 | 时限 | 适用场景 | 超时动作 |
|------|------|----------|----------|
| 紧急 | 2小时 | 漏水漏电、电梯困人、消防报警、门禁故障 | 超时即标红 + 推送经理 + 自动升级 |
| 优先 | 4小时 | 投诉类、公共区域重大故障 | 超时标红 + 推送管家组长 |
| 标准 | 24小时 | 一般报修、咨询 | 超时黄牌提醒 |
| 普通 | 72小时 | 建议类、非紧急维修 | 纳入周报统计 |

**逐级升级机制：**
- 超时15分钟 → 系统提醒操作员
- 超时30分钟 → 推送管家
- 超时60分钟 → 推送物业经理
- 超时120分钟 → 推送业委会端监管

### 2.4 工单处理状态机

```
┌──────────┐    AI分派    ┌──────────┐    接单    ┌──────────┐
│  待分派   │ ──────────→ │  待接单   │ ─────────→ │  处理中   │
└──────────┘              └──────────┘            └─────┬────┘
                                                        │ 提交结果
                                                        ↓
                                                 ┌──────────┐
                                                 │  待验收   │
                                                 └─────┬────┘
                                         业主确认  ↓     ↑  退回重做
                                                 ↓     │
                                    ┌──────────┐  │  ┌──────────┐
                                    │  已验收   │  └─ │  退回整改  │
                                    └──────────┘     └──────────┘
                                         │
                                    ┌────┴────┐
                                    ↓         ↓
                              业主评价   维修金申报
                              (好评/差评) (如涉及)
```

### 2.5 处理与反馈

#### 2.5.1 维修工操作

- **接单：** 查看工单详情、承诺到达时间
- **处理中：** 到达现场拍照、维修过程记录
- **提交结果：** 上传修后照片（必填）、填写处理说明、申报耗材

#### 2.5.2 结果反馈给业主

提交结果后系统自动：
1. 推送通知至业主端："您报修的XX问题已处理完成，请确认验收"
2. 展示修前/修后对比图
3. 提供评价入口（好评/中评/差评 + 文字评价）

### 2.6 工单看板

#### 2.6.1 看板视图

| 看板 | 内容 |
|------|------|
| 总览 | 全部工单卡片视图，按状态分列 |
| 待处理 | 待接单 + 处理中工单，按紧急度排序 |
| 超时预警 | 接近SLA时限/已超时的工单，红色高亮 |
| 疑难工单 | 多次退回、业主反复投诉的工单 |
| 已完成 | 已验收工单，按时间倒序 |

#### 2.6.2 统计指标

- 今日工单总量 / 处理率 / 超时率 / 满意度
- 诉求类型分布（报修/投诉/建议占比）
- 楼栋/片区对比排行
- 维修工效率排行

## 三、物业费管理

### 3.1 功能概述

物业费管理模块提供完整的费用台账与纠纷记录能力，帮助物业公司实现收费透明化、纠纷可追溯。

### 3.2 费用台账

#### 3.2.1 台账要素

| 字段 | 说明 |
|------|------|
| 房屋编号 | 关联业主端房屋信息 |
| 业主姓名 | 脱敏显示（王**） |
| 计费周期 | 年度/季度/月度 |
| 物业费标准 | 元/㎡·月 |
| 应缴金额 | 面积 × 标准 × 周期 |
| 已缴金额 | 实际缴费汇总 |
| 欠费金额 | 应缴 - 已缴 |
| 缴费方式 | 微信/支付宝/银行转账/现金/其他 |
| 最近缴费日期 | 最近一次缴费时间 |

#### 3.2.2 欠费六分类

系统根据业主欠费行为自动归类：

| 类别 | 特征 | 建议处置 |
|:--:|------|------|
| A·合理争议 | 因服务质量争议拒缴 | 先修东西，工单闭环后再协商 |
| B·现实困难 | 经济困难、重大变故 | 协商分期方案 |
| C·观望拖延 | 无明确理由，习惯性迟缴 | 温和提醒 + 截止日期提示 |
| D·惯性失约 | 多次承诺未兑现 | 书面留痕 + 信用扣分 |
| E·对抗失信 | 恶意拖欠、拒绝沟通 | 证据固化 + 法律途径 |
| F·历史复杂 | 前任物业遗留问题 | 拆因归责，跨期轨道处理 |

### 3.3 纠纷记录

| 功能 | 说明 |
|------|------|
| 纠纷登记 | 记录争议事项、涉及金额、业主诉求 |
| 证据上传 | 聊天截图/合同/照片/录音（合规脱敏） |
| 协商记录 | 每次协商的时间、参与方、结论 |
| 让利记录 | 统一让利/事件让利/叠加模式，记录让利金额与依据 |
| 客服介入标记 | 推送至客服端跟进，双方视角同步 |
| 法务流转 | 纠纷升级后的法务对接记录 |

### 3.4 双轨制收费

| 轨 | 对象 | 内容 |
|------|------|------|
| 在管轨 | 现任物业 | 现行服务期内的费用台账 |
| 退管轨 | 已退出物业 | 前任期间的历史欠费追缴 |

两类台账独立管理，跨期争议通过"跨期轨"联合复核。

## 四、公共收益管理

### 4.1 功能概述

依据《民法典》及《宁波市住宅小区物业管理条例》，物业公司需对公共收益（电梯广告、停车费、场地租金等）进行规范管理、定期公示。

### 4.2 收支记录

| 功能 | 说明 |
|------|------|
| 收入登记 | 按来源分类：电梯广告/地面停车/场地租赁/快递柜/通信基站/其他 |
| 支出登记 | 按用途分类：补充维修金/业主分红/公共设施改善/管理成本/其他 |
| 凭证上传 | 合同/发票/收据等原始凭证电子归档 |
| 周期结算 | 月度/季度/年度自动汇总 |

### 4.3 公共收益公示

| 公示内容 | 频率 | 推送目标 |
|----------|------|----------|
| 公共收益收支明细 | 每季度 | 业主端公告栏 + 业委会端 |
| 年度公共收益报告 | 每年 | 业主端 + 业委会端 + 社区端 |
| 单笔重大收支 | 发生时 | 业委会端审批提醒 |

### 4.4 数据看板

- 本季度收入趋势 / 同比
- 收入来源构成饼图
- 支出用途分布
- 结余余额实时展示
- 与维修金补充的联动统计

## 五、设施维修管理

### 5.1 功能概述

设施维修管理分为**日常维保**与**大修申报**两条线，前者保证设施正常运行，后者涉及维修资金使用。

### 5.2 日常维保

#### 5.2.1 维保计划

| 功能 | 说明 |
|------|------|
| 设施台账 | 电梯/消防/水泵/配电/门禁/监控等设施清单 |
| 维保日历 | 按周/月/季/年维保周期的自动排期 |
| 维保工单 | 日常巡检+保养的标准化流程工单 |
| 到期提醒 | 维保到期前自动提醒，超期未保养预警 |

#### 5.2.2 巡检管理

| 巡检类型 | 说明 | 工具 |
|----------|------|------|
| 设备巡检 | 电梯/消防/供水/供电等关键设备 | 巡检点打卡 + 照片上传 |
| 服务巡检 | 公共区域卫生/绿化/安保/停车秩序 | 评分表 + 异常上报 |

巡检异常自动生成工单，进入工单处理中心流转。

### 5.3 大修申报

大修申报指超出日常维保范围的重大维修/改造/更新项目，通常涉及维修资金使用。

#### 5.3.1 申报流程

```
物业提出 → 方案制定（含比价） → 业委会审议 → 业主表决 → 执行 → 验收 → 资金核销
   │            │                  │           │         │       │
   └─ 材料上传 ─┘                  └─ AI匹配审核 ─┘         └─ 凭证归档 ─┘
```

#### 5.3.2 申报材料清单

- 维修方案说明（问题描述、维修范围、技术方案）
- 工程预算（至少三家比价）
- 施工方资质证明
- 维修前照片/检测报告
- 业主表决结果（系统联动业主端投票）
- 施工合同草案

### 5.4 与维修金申报的联动

日常维保中发现需动用维修金的项目，一键发起维修金申报（详见第十章），自动带入设施信息与问题描述。

## 六、业主审核

### 6.1 功能概述

新业主/租户入驻时需进行身份认证审核。采用 **AI 初审 + 物业人工复核** 的双层审核机制，确保社区安全与数据真实性。

### 6.2 审核流程

```
业主提交认证材料 → AI 初审（OCR+人脸比对）
                         │
               ┌─────────┴─────────┐
               ↓                   ↓
           AI通过              AI不通过
               │                   │
               ↓                   ↓
          自动认证          物业人工复核
                               │
                      ┌────────┴────────┐
                      ↓                 ↓
                   复核通过           复核驳回
                      │                 │
                      ↓                 ↓
                   手动认证         退回业主（附原因）
```

### 6.3 AI 初审能力

| 能力项 | 说明 |
|--------|------|
| 证件 OCR | 自动识别身份证/户口本/房产证/租赁合同 |
| 人脸比对 | 业主自拍与证件照 AI 比对 |
| 房屋关联校验 | 验证申报房屋与产权/租赁的匹配关系 |
| 黑名单筛查 | 社区/公安重点人员数据库比对（合规） |

### 6.4 物业人工复核

| 场景 | 物业操作 |
|------|----------|
| AI 不通过 | 查看 AI 标注的不通过原因（照片模糊/证件不匹配等），人工判断 |
| AI 通过但存疑 | 物业可主动拉起人工复核 |
| 租户认证 | 需核实租赁合同真实性，联系业主确认 |

### 6.5 审核看板

- 待审核列表（按提交时间排序）
- AI 初判结果标记（通过/不通过/存疑）
- 审核历史记录（谁在什么时间通过/驳回了谁）
- 审核时效统计（平均审核时长、超时待审数量）

## 七、公告发布

### 7.1 功能概述

物业公司通过公告栏向业主发布各类通知、公告、提醒，支持定时发布与多端同步。

### 7.2 公告类型

| 类型 | 示例 | 目标端 |
|------|------|--------|
| 服务公告 | 停水停电通知、电梯维保计划、消杀通知 | 业主端 |
| 收费通知 | 物业费缴纳提醒、公共收益公示 | 业主端 + 业委会端 |
| 活动通知 | 社区活动、节日庆祝 | 业主端 |
| 安全提醒 | 防火防盗、防诈骗 | 业主端 + 社区端 |
| 制度公告 | 小区管理规约更新、业主大会通知 | 业主端 + 业委会端 |
| 整改通知 | 违规装修、占用消防通道 | 定向推送给相关业主 |

### 7.3 发布功能

| 功能 | 说明 |
|------|------|
| 富文本编辑 | 标题/正文/图片/附件 |
| 定时发布 | 设定未来时间自动发布 |
| 定向推送 | 按楼栋/单元/标签精准推送 |
| 置顶管理 | 重要公告在业主端首页置顶 |
| 已读统计 | 查看公告阅读人数/未读人数 |
| 撤销/修改 | 已发布公告可撤回或修订 |
| 同步业委会 | 涉及公共利益的公告同步推送业委会端备案 |

### 7.4 公告模板库

系统预置常用公告模板，物业可选择模板快速编辑发布：
- 停水/停电通知模板
- 缴费提醒模板
- 业主大会通知模板
- 节日祝福模板
- 安全提醒模板

## 八、履约考评查看

### 8.1 功能概述

物业公司通过本模块查看业主与业委会对物业履约服务的考评结果，主动了解自身服务水平与改进方向。

### 8.2 考评来源

| 评价方 | 评价内容 | 触发时机 |
|--------|----------|----------|
| 业主 | 单次服务评价（好评/差评+文字） | 工单验收后 |
| 业主 | 月度满意度评分 | 每月末推送评价邀请 |
| 业委会 | 季度履约评估 | 每季末业委会端发起 |
| 业委会 | 年度综合考评 | 年度业委会会议决议 |
| AI 系统 | SLA 履约率自动计算 | 实时/周期汇总 |

### 8.3 考评看板

| 指标 | 说明 |
|------|------|
| 综合评分 | 业主评分 + 业委会评分的加权平均 |
| 满意度趋势 | 近12个月满意度变化曲线 |
| 分项评分 | 报修响应/维修质量/服务态度/公共环境/安全管理 等维度 |
| 楼栋对比 | 不同楼栋/片区的满意度差异 |
| 差评工单列表 | 所有被差评的工单及原因 |

### 8.4 评分异议

若物业对考评结果有异议，可通过评分异议通道：
1. 在工单详情中发起"评分异议"
2. 提交异议理由与证据
3. 先反馈至业主端，请求业主重新评价
4. 若无法协商一致，提交业委会端复核仲裁

## 九、信用档案查看

### 9.1 功能概述

在数治理方的双向信用体系中，物业公司同样被纳入信用评价。本模块展示物业公司的**信用分、信用等级、加减分记录**。

### 9.2 信用评分维度

| 维度 | 权重 | 加分项 | 减分项 |
|------|:--:|------|------|
| 工单履约 | 35% | 按时完成、好评率高 | 超时、差评、多次退回 |
| 收费合规 | 20% | 收费透明、公共收益公示及时 | 收费争议、未公示 |
| 安全管理 | 20% | 零安全事故、安防演练 | 安全事故、安防漏洞 |
| 业主满意度 | 15% | 综合满意度≥90% | 综合满意度<70% |
| 制度合规 | 10% | 积极配合社区治理、制度落地 | 违规操作、拒不整改 |

### 9.3 信用档案内容

| 功能 | 说明 |
|------|------|
| 信用分与等级 | 当前信用分（0-1000）+ 等级（AAA/AA/A/B/C/D） |
| 加减分明细 | 每条记录关联具体工单号/事件，可追溯 |
| 趋势图 | 近12个月信用分变化曲线 |
| 预警阈值 | 信用分低于阈值时自动告警 |
| 信用报告下载 | 定期生成物业信用报告（PDF） |
| 同区域对比 | 在同区域/同城市物业公司中的排名（脱敏） |

### 9.4 双向信用逻辑

```
业主守约 → 物业敢投入 → 服务提升 → 业主更满意 → 收费更顺畅
    ↑                                                    │
    └────────── 信用驱动良性循环 ←──────────────────────────┘

物业违约 → 信用扣分 → 业委会关注 → 整改或更替 → 信用修复
```

## 十、维修金申报

### 10.1 功能概述

维修金（住宅专项维修资金）申报是物业端的重要资金管理模块。依据政策要求，**所有动用维修金的项目均需在系统中申报**，且实行**双轨制**管理。

### 10.2 申报材料清单

所有维修金申报均需提交以下材料：

| 序号 | 材料 | 要求 | 审核方式 |
|:--:|------|------|:--:|
| 1 | 维修方案说明 | 问题描述、维修范围、技术方案 | AI 关键词匹配 + 业委会审核 |
| 2 | 工程预算书 | 详细费用明细 | AI 价格合理性校验 |
| 3 | 比价记录 | 至少三家供应商报价对比 | 系统格式校验 |
| 4 | 施工方资质 | 营业执照、资质证书 | OCR 提取 + 合规库比对 |
| 5 | 维修前照片 | 现场实拍，带时间水印 | AI 图片去重检测 |
| 6 | 业主表决结果 | 双2/3以上业主同意 | 联动业主端投票数据 |
| 7 | 施工合同 | 标准合同模板或自定义合同 | AI 合规扫描 |
| 8 | 验收报告 | 维修完成后的验收文件 | 业委会 + 业主代表签字 |
| 9 | 发票/收据 | 实际支出凭证 | OCR 金额比对 |

### 10.3 双轨制管理

| 轨 | 适用场景 | 特点 |
|------|------|------|
| 在管轨 | 现任物业在管期间的维修金使用 | 正常申报流程，业委会全程监督 |
| 退管轨 | 前任物业遗留的维修金使用记录/未完结申报 | 历史追溯、责任界定、跨期协商 |

**跨期轨联动：** 当维修项目的责任归属不清（涉及前任与现任物业交替期），启动跨期轨联合复核，由业委会、在管物业、退管物业三方在系统中共同确认。

### 10.4 申报流程

```
物业发起申报 → 材料上传 → AI 智能初审（完整性+合规性）
                                    │
                         ┌──────────┴──────────┐
                         ↓                      ↓
                     材料齐全                材料不全
                         │                      │
                         ↓                      ↓
                  业委会端审核           退回补充（标注缺项）
                         │
              ┌──────────┴──────────┐
              ↓                      ↓
           审核通过               审核驳回
              │                      │
              ↓                      ↓
        进入业主表决           退回修改（附原因）
              │
              ↓
        表决通过 → 执行 → 验收 → 资金核销
```

### 10.5 AI 智能审核能力

| 能力 | 说明 |
|------|------|
| 材料完整性校验 | 自动检查必传材料是否齐全 |
| 价格合理性分析 | 对比历史项目/市场均价，异常标红 |
| 合同合规扫描 | 关键条款缺失/风险点标注 |
| 重复申报检测 | 同一项目/同一设备是否已申报过 |
| 资质自动校验 | 施工方资质有效期/经营范围匹配 |

### 10.6 维修金看板

- 申报中 / 审核中 / 表决中 / 执行中 / 已核销 / 被驳回 各状态统计
- 年度维修金使用总额与余额
- 申报趋势图
- 超期未完成申报预警

## 十一、近场采购

### 11.1 功能概述

近场采购模块为物业公司提供**供应商选择与管理**能力，支持日常物资采购与维修工程发包的在线化、透明化管理。

### 11.2 供应商管理

| 功能 | 说明 |
|------|------|
| 供应商库 | 物业公司自建供应商名录，分类管理（保洁/安保/绿化/维修/工程/耗材） |
| 资质管理 | 供应商营业执照、资质证书电子归档，到期提醒 |
| 评价记录 | 历史合作评价（质量/价格/时效/服务），影响后续选用优先级 |
| 黑名单 | 严重违约/质量问题供应商加入黑名单，禁止选用 |
| 平台推荐 | AI 根据物业需求智能推荐生态内优质供应商 |

### 11.3 采购流程

```
采购需求 → 询价比价 → 供应商选择 → 合同签订 → 履约跟踪 → 验收结算 → 供应商评价
    │           │           │           │           │           │
    └── 预算审批 ─┘    三级审批 ─┘  业委会备案 ─┘    └── 纳入公共收益/维修金核算
```

### 11.4 三级审批

| 金额区间 | 审批层级 |
|----------|----------|
| < 5,000元 | 物业经理直接审批 |
| 5,000 - 50,000元 | 物业经理 + 业委会备案 |
| > 50,000元 | 物业经理 + 业委会审批 + 业主大会表决 |

### 11.5 拆单检测

AI 自动检测是否存在将大额采购拆分为多笔小额以规避审批的行为，一旦发现自动标记并推送业委会端。

### 11.6 比价透明

- 每次采购至少录入三家供应商报价
- 报价单/合同电子归档
- 业委会端可实时查看采购明细与比价记录
- 业主端可查看公共收益相关的重大采购公示

### 11.7 与生态联动

| 联动端口 | 联动内容 |
|----------|----------|
| 业委会端 | 采购审批、比价监督、合同查阅 |
| 业主端 | 重大采购公示、供应商评价 |
| 运营端 | 供应链监管、异常交易预警 |
| AI 端 | 供应商推荐、价格合理性分析、拆单检测 |

### 12.3 生态协同场景

#### 场景一：报修闭环

```
业主端提交报修 → 写入共享数据桥
    → AI端自动分派给对应维修工
    → 物业端接单、处理、上传修后照片
    → 桥数据更新为"待验收"
    → 业主端收到推送、确认验收、评价
    → 信用系统自动更新业主+物业信用分
```

#### 场景二：维修金双轨协作

```
A类小区（物业已更替）：
    退管轨 → 前任欠费/争议在退管物业端处理
    在管轨 → 现任日常维修金申报在在管物业端处理
    跨期轨 → 业委会端牵头，双物业+社区联合复核
```

#### 场景三：采购透明化

```
物业端发起大额采购
    → 需业委会端审批
    → 采购完成后公示至业主端
    → 运营端监控异常交易
    → 供应商评价回流至物业端供应商库
```
