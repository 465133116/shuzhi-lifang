# 数治理方 · 社区端 产品设计文档

> **端口：** 社区端（PC端）
> **角色：** 社区书记 / 街道干部 / 网格员 / 社区工作者
> **定位：** 四端生态中的制度供给与治理监督端 —— 统筹小区治理、协调多方关系、监督制度落实
> **品牌主题：** "如我在居·共享家"
> **对应政策文件：** 鄞社发〔2026〕6号
> **版本：** V1.0 实装版
> **更新日期：** 2026年7月

---

## 一、端口概述

### 1.1 四端生态定位

社区端是"数治理方"四端生态中的**制度供给与治理监督端**，扮演整个社区治理体系的"顶层设计者"与"底线守护者"双重角色。社区端不直接服务业主，也不直接提供物业服务，而是：

- **制度供给：** 制定、发布、监督社区治理的各项制度规范
- **统筹协调：** 协调居委会、业委会、物业企业三方关系，化解矛盾
- **治理监督：** 监督业委会履职、物业履约，维护业主合法权益
- **资源调配：** 统筹社区公共资源，对接上级部门与外部服务力量

### 1.2 "如我在居·共享家"主题诠释

社区端以"如我在居"的理念站在居民视角审视治理问题，以"共享家"的目标推动社区共建共治共享。每一个功能设计都以"让社区更有序、让居民更满意、让治理更高效"为出发点。

### 1.3 端口关系矩阵

| 功能 | 业主端 | 物业端 | 业委会端 | 社区端 |
|------|:--:|:--:|:--:|:--:|
| 事项派单 | 提交诉求 | 处置工单 | 处置工单 | 统筹分派 |
| 矛盾调处 | 申请调解 | 涉事方 | 涉事方 | 分级调处 |
| 吹哨报到 | — | — | — | 发起+督办 |
| 投诉接收 | 提交方 | 被投诉方 | 被投诉方 | 接收+分派 |
| 考评管理 | 参与评价 | 被考评 | 被考评 | 数据聚合 |
| 信用档案 | — | 物业信用 | 业委会信用 | 管理+公示 |
| 态势大屏 | — | — | — | 数据汇聚展示 |

### 1.4 设计原则

1. **制度先行原则：** 用制度代替人情，所有治理行为有据可依、有迹可循
2. **闭环管理原则：** 事事有回音，件件有着落，全过程可追踪
3. **分级治理原则：** 楼栋→小区→街道三级联动，矛盾不上交或逐级上交
4. **数据驱动原则：** 以数据支撑决策，以指标衡量成效，以预警防范风险

## 二、事项派单 + 流程督办

### 2.1 功能概述

事项派单与流程督办是社区端的核心工作引擎，实现居民诉求的集中受理、智能分派、流程督办和闭环管理。社区端作为"总调度台"，将各类诉求统筹分派至物业、业委会或相关职能部门，并对处置全过程进行跟踪督办。

### 2.2 诉求汇聚

- **诉求来源：**
  - 业主端直接提交的投诉/建议/咨询（涉及公共事务类）
  - 业主投诉业委会的工单同步副本（工单列表中特别标注，可查看不可处理）
  - 业委会端上报的需社区介入事项
  - 网格员巡查发现上报的问题
  - 上级交办/转办的群众诉求
  - 12345热线转派事项
  - 社区窗口/电话受理的居民诉求
- **统一受理：** 所有渠道来源的诉求统一汇入社区端"事项池"
- **AI预分类：** AI自动识别诉求类型（投诉/建议/咨询/求助/举报）、紧急程度、涉及主体

### 2.3 智能分派

```
事项入池 → AI预分类 → 社区工作人员研判确认 → 
  ├─ 派往物业（物业服务类）
  ├─ 派往业委会（公共事务决策类）
  ├─ 社区自处理（社区职能类）
  ├─ 吹哨部门（需职能部门介入）
  └─ 退回/合并（重复/无效事项）
```

- **分派规则引擎：**
  - 按事项类型自动匹配处置主体
  - 按地理范围自动匹配对应网格员
  - 按紧急程度自动调整处置时限
- **退件处理：** 被派往方可在规定时间内退件并说明理由，社区端重新分派

### 2.4 流程督办

- **时限管理：** 每类事项设置SLA处置时限（紧急2h / 常规24h / 复杂72h / 重大7d）
- **进度跟踪：** 实时查看每件事项的处置进度（待接收→处理中→待审核→已办结）
- **超时预警：** 即将超时自动提醒（黄灯），已超时自动升级（红灯+抄送上级）
- **催办督办：** 对超时/处置不力的事项，社区端可手动发送督办通知
- **闭环验证：** 处置完成后须提交处置结果，社区端审核通过后方可办结

### 2.5 统计看板

- **实时概览：** 今日新增、处理中、已办结、超时件数
- **趋势分析：** 周/月/季度事项量趋势、类型分布、处置时效趋势
- **热点分析：** AI自动识别高频诉求类型和区域，辅助治理决策

## 三、三级矛盾调处

### 3.1 功能概述

三级矛盾调处模块构建"楼栋→小区→街道"三级线上调处网络，实现矛盾纠纷的分级受理、逐级调处和闭环化解，落实"小事不出楼栋、大事不出小区、难事不出街道"的治理目标。

### 3.2 网格员工作台（一级调处联动）

网格员是一级调处的执行主体，工作台直接对接三级调处网络：

- **待办调处工单**：网格员登录后首先看到分配给自己的调处任务——来源包括系统自动分派（AI定级为楼栋级）、社区管理员手动指派、上级转派
- **时限管理**：一级调处依合同约定时限内响应，超时自动标红+推送社区管理员
- **升级联动**：网格员调解失败或超时未处理→一键升级至二级社区调解，携带完整调处记录、各方陈述、网格员初步意见
- **调解记录**：现场调解时拍照/录音/文字记录上传，AI辅助生成调解摘要
- **台账统计**：个人调解数量、成功率、平均响应时间，纳入网格员考核
- **与事项派单的衔接**：网格员在事项派单中接收的一般性工单（非矛盾类），如涉及纠纷升级，可在工单详情中一键转为调处工单，进入三级调处流程

### 3.3 三级架构

| 层级 | 调处主体 | 受理范围 | 调处方式 |
|:---|:---|:---|:---|
| **第一级：楼栋** | 楼栋长/网格员 | 邻里纠纷、轻微投诉、物业服务小问题 | 线上沟通 + 现场调解 |
| **第二级：小区** | 社区调处员 + 业委会 + 物业 | 涉及多方利益的纠纷、物业服务争议 | 三方协商 + 在线调解 |
| **第三级：街道** | 街道调处中心 + 职能部门 | 重大矛盾纠纷、涉法涉诉问题 | 联合调解 + 司法确认 |

### 3.3 调处流程

**调解开始（四种触发方式）：**
- 业主在业主端主动提交调解申请 → AI定级 → 分派调处主体
- 工单处理中业主不满意达上限 → 系统自动转为调解工单
- 物业/业委会在处理纠纷时发起调解请求 → 推送社区端审核
- 网格员巡查发现纠纷苗头 → 主动创建调处工单

**调解过程：**
```
受理 → 调查核实 → 确定调解方式(线上/线下) → 
通过业主端议事厅发起调解会议 → 各方陈述 → 调解员提出方案 → 
协商/多轮调解 → 达成一致或调解失败
```

**调解结束（四种结果）：**
- **达成协议** → 在线签署调解协议 → 协议履行跟踪 → 闭环归档
- **调解失败** → 自动升级至上一级调处层级，携带完整记录
- **撤诉** → 申请人主动撤回 → 记录原因归档
- **转司法** → 涉法涉诉案件 → 一键对接司法确认流程

### 3.4 线上调处工具

- **在线调解室：** 集成音视频功能，各方可远程参与调解
- **调解记录：** AI辅助实时记录调解过程，自动生成调解笔录
- **协议模板：** 内置常见纠纷类型的调解协议模板，调处员可快速生成
- **电子签章：** 调解协议支持在线签署，具备法律效力
- **司法确认对接：** 重大调解协议可一键对接司法确认流程

### 3.5 矛盾分析

- **矛盾热力图：** 按小区/楼栋/类型可视化展示矛盾分布
- **重复矛盾预警：** 同一当事人/同一事项多次上报的自动预警
- **趋势研判：** AI分析矛盾演变趋势，辅助社区提前介入

## 四、社区吹哨 · 部门报到

### 4.1 功能概述

"社区吹哨·部门报到"机制落实鄞社发〔2026〕6号关于"基层吹哨、部门报到"的要求，打通社区与上级职能部门之间的响应通道。当社区遇到自身无法解决的问题时，可"一键吹哨"，相关职能部门限时响应处置。

### 4.2 吹哨发起

- **吹哨权限：** 社区书记/主任可发起吹哨
- **吹哨条件：**
  - 事项超出社区/物业/业委会职能范围
  - 需要行政执法力量介入（违建、群租、安全等）
  - 需要专业部门技术支持（消防、环保、规划等）
  - 需要多部门联合处置
- **吹哨内容：** 事项描述、现场情况、已采取措施、需要部门、期望时限
- **部门选择：** 系统内置职能部门名录（城管/消防/环保/规划/住建/市监/公安等），吹哨人可单选或多选

### 4.3 部门响应

- **接哨通知：** 吹哨发出后，被选部门实时接收通知
- **响应时限：** 紧急吹哨2h内响应，常规吹哨24h内响应
- **处置回传：** 部门处置完成后在线回传处置结果（文字+图片+文书）
- **延期申请：** 无法按时完成的须在线申请延期并说明理由

### 4.4 跟踪评价

- **处置跟踪：** 社区端实时查看部门响应和处置进度
- **超时预警：** 部门超时未响应/未处置的，系统自动预警并抄送上级
- **结果评价：** 社区对部门处置结果进行评价（满意/基本满意/不满意）
- **吹哨统计：** 自动统计吹哨频次、部门响应率、处置时效、满意度

## 五、投诉/建议接收

### 5.1 功能概述

社区端接收涉及社区公共事务的投诉与建议，与事项派单模块联动，实现投诉建议的受理、分派、处置、反馈、闭环全流程管理。

### 5.2 受理范围

- **社区职能类：** 社区环境卫生、公共秩序、民生服务等
- **物业监督类：** 物业服务质量、收费合理性、信息公开等
- **业委会监督类：** 业委会履职、公共收益使用、维修资金管理等
- **公共事务类：** 社区规划、公共设施建设、政策执行等

### 5.3 处理流程

```
投诉/建议接收 → 社区工作人员初审 → 
  ├─ 社区自处理（社区职能范围）
  ├─ 转派物业（物业职能范围）
  ├─ 转派业委会（业委会职能范围）
  ├─ 吹哨部门（需职能部门介入）
  └─ 退回并说明（不属于受理范围）
```

- **时限承诺：** 受理后2个工作日内反馈处理方案，15个工作日内反馈处理结果
- **满意度回访：** 办结后系统自动推送满意度评价给投诉人
- **不满意重办：** 评价不满意的，系统自动重新派单处理
- **不满意升级：** 社区/网格员处理结果被追加反馈>3次→自动升级至街道/区级

### 5.4 数据分析

- **投诉热点：** AI自动识别高频投诉主题和区域
- **满意度趋势：** 按月/季度统计投诉处置满意度变化
- **预警：** 同类投诉短时间内激增的自动预警

## 六、党员 + 志愿者管理

### 6.1 功能概述

党员与志愿者管理模块支撑社区端对辖区内党员和志愿者的统一管理，包括党员台账维护、志愿者注册审核、志愿服务活动发布、积分管理等，与业委会端党员管理形成数据互通。

### 6.2 党员台账

- **信息维护：** 辖区内党员基本信息（姓名、支部、入党时间、联系方式、特长）
- **组织关系：** 在职党员、退休党员、流动党员分类管理
- **报到管理：** 党员社区报到登记，与业委会端同步
- **活动记录：** 党员参与社区活动的全记录
- **评议考核：** 年度党员民主评议结果记录

### 6.3 志愿者管理

- **注册审核：** 居民申请成为志愿者，社区端在线审核
- **信息管理：** 志愿者基本信息、技能特长、可服务时段
- **队伍管理：** 按服务类型组建志愿者队伍（平安巡逻、环境维护、助老扶弱等）
- **活动发布：** 发布志愿服务活动，设置人数上限、时间地点、积分奖励
- **报名管理：** 在线查看报名情况，确认参与人员

### 6.4 积分管理（志愿者积分）

- **积分规则：** 按服务类型、时长、难度设置积分标准
- **积分记录：** 系统自动记录每次志愿服务的积分
- **积分兑换：** 对接积分商城/合作商户，志愿者可使用积分兑换服务或商品
- **积分排行：** 志愿者积分排名榜单，激励参与

### 6.5 微心愿管理

- **微心愿发布：** 居民通过业主端发布微心愿（如"希望有人帮忙修一下楼道灯""想要一本二手书"），社区端审核后发布
- **微心愿认领：** 党员、志愿者、热心居民在线认领微心愿，系统记录认领人和完成状态
- **微心愿分类：** 按类型（生活帮扶/设施维修/陪伴关怀/物品捐赠/其他）和难度（简单/一般/困难）分类管理
- **完成确认：** 认领人完成后上传照片/说明，发布人确认完成，双方互评
- **积分联动：** 认领并完成微心愿自动获得积分，纳入志愿者积分体系

## 七、居业物考评管理

### 7.1 功能概述

居业物考评管理模块支撑社区端对物业企业和业委会的考核评价，是社区端履行治理监督职责的核心工具。通过系统化、数据化的考评体系，推动物业服务质量和业委会履职水平双提升。

### 7.2 物业考评

- **考评维度：**
  - 工单数据（系统自动统计）：响应时效、完成率、返工率、满意度（权重35%）
  - 业主评价（业主端调查）：服务态度、服务质量、收费合理性（权重30%）
  - 业委会评价：履约情况、配合度、信息公开（权重20%）
  - 社区评价：制度遵守、整改响应、社会责任（权重15%）
- **考评周期：** 月度评估 + 季度考评 + 年度总评
- **考评结果：**
  - 自动生成物业考评报告
  - 评分排名（社区内/街道内）
  - 联动物业信用评分
  - 作为物业合同续签/解聘的参考依据

### 7.3 业委会履职评价

- **评价维度：**
  - 履职数据（系统自动统计）：会议出勤、决策参与、工单处理（权重30%）
  - 业主评价：满意度、信息透明度、回应及时性（权重30%）
  - 社区评价：制度遵守、协作配合、负面清单（权重25%）
  - 财务合规：公共收益管理、维修资金审批合规性（权重15%）
- **评价周期：** 季度评价 + 年度总评
- **评价结果：**
  - 自动生成业委会履职评价报告
  - 联动业委会信用档案
  - 作为换届选举和评优评先的参考依据

### 7.4 考评工具

- **考评仪表盘：** 可视化展示考评核心指标（雷达图 + 趋势图 + 排名表）
- **数据自动汇聚：** 考评所需数据从各端自动汇聚，减少人工填报
- **考评报告：** 一键生成考评报告（支持导出打印）
- **整改跟踪：** 考评发现的问题自动生成整改工单并跟踪

## 八、积分管理

### 8.1 功能概述

积分管理模块支撑社区端建立居民积分体系，以积分激励居民参与社区治理和公共事务，形成"参与→积分→兑换→激励→更多参与"的正向循环。

### 8.2 积分规则管理

- **规则配置：** 社区端自定义积分获取规则
  - 参与议事/投票 +N分
  - 志愿服务 +N分/小时
  - 垃圾分类达标 +N分
  - 邻里互助/好人好事 +N分
  - 提出被采纳的建议 +N分
  - 按时缴纳物业费 +N分
- **规则生效：** 支持规则草稿→公示→生效→废止的生命周期管理
- **动态调整：** 根据治理需要随时调整积分规则

### 8.3 积分记录与统计

- **自动记录：** 系统自动记录居民积分获取明细（来源、时间、分值）
- **积分查询：** 居民可在业主端查看个人积分和明细
- **积分排行：** 社区/楼栋积分排行榜
- **积分预警：** 异常积分变动自动预警（防刷分）

### 8.4 商户对接

- **商户入驻：** 社区端审核合作商户入驻积分商城
- **兑换商品/服务：** 商户上架可兑换的商品或服务，设定所需积分
- **兑换管理：** 居民在线兑换，商户确认核销
- **结算：** 社区端与商户定期结算（积分兑换对应的费用）
- **商户评价：** 居民对商户服务进行评价

## 九、公告发布

### 9.1 功能概述

公告发布模块支撑社区端向辖区居民发布政策通知、政务信息、公共事务公告等，实现公告的起草、审批、发布、查阅、归档全流程线上化。

### 9.2 公告类型

- **政策公示：** 上级政策文件的传达与解读
- **通知公告：** 社区活动通知、停水停电通知、防疫通知等
- **制度发布：** 社区治理制度的发布与更新
- **结果公示：** 考评结果、选举结果、征求意见结果等
- **紧急通知：** 突发事件预警、安全提醒

### 9.3 发布管理

- **起草：** 社区工作人员在线起草公告（富文本 + 附件）
- **审批：** 重要公告须经社区书记/主任审批后发布
- **定向发布：** 支持按小区/楼栋/人群定向发布（如仅某小区业主可见）
- **多渠道推送：** 业主端首页 + 消息推送 + 小区公告栏二维码
- **已读追踪：** 查看公告已读/未读人数与名单
- **置顶管理：** 重要公告置顶显示

### 9.4 公告归档

- **自动归档：** 到期公告自动归档
- **分类检索：** 按类型、时间、范围检索历史公告
- **公示证明：** 生成公告发布与已读情况证明

## 十、社区论坛

### 10.1 功能概述

社区论坛为社区端提供辖区内公共讨论空间的管理工具。社区端作为论坛的"总管理员"，负责论坛版块管理、内容审核、话题引导等。

### 10.2 版块管理

- **版块创建：** 按小区/主题创建论坛版块
- **版主设置：** 指定版主（可由业委会成员/热心业主担任）
- **版块排序：** 调整版块显示顺序
- **版块启停：** 启用/关闭特定版块

### 10.3 内容审核

- **全量审核队列：** 所有新发帖和回复进入审核队列
- **审核操作：** 通过 / 驳回（附原因）/ 屏蔽 / 删除
- **AI预审：** AI自动识别违规内容（敏感词、广告、攻击性言论），辅助人工审核
- **审核日志：** 所有审核操作留痕

### 10.4 论坛运营

- **话题引导：** 社区端可发布引导性话题，推动积极讨论
- **舆情监控：** AI自动分析论坛舆情热点和情感倾向
- **违规用户管理：** 对违规用户进行警告/禁言/封禁处理
- **数据统计：** 论坛活跃度、热门话题、用户参与度统计

## 十一、协同共治指数

### 11.1 功能概述

协同共治指数是本平台的核心治理成效评价体系，通过系统自动汇聚各端治理数据，生成多维度的治理成效指数，实现治理成效的可量化、可比较、可排名。

### 11.2 指数构成

| 一级指标 | 二级指标 | 数据来源 | 权重 |
|:---|:---|:---|:---:|
| **服务响应** | 工单响应时效、完成率、满意度 | 物业端+业主端 | 20% |
| **履约质量** | 物业履约评分、合同执行率 | 业委会端+AI | 20% |
| **财务健康** | 物业费收缴率、公共收益增长率 | 物业端+业委会端 | 15% |
| **参与活跃** | 议事参与率、投票参与率、志愿者活跃度 | 业主端+社区端 | 15% |
| **纠纷化解** | 矛盾调处成功率、投诉下降率 | 社区端 | 15% |
| **制度合规** | 业委会负面清单、物业违规记录 | 社区端+AI | 15% |

### 11.3 数据汇聚

- **自动汇聚：** 指数所需的原始数据从各端自动采集汇聚，无需人工填报
- **实时更新：** 指数数据按日/周/月频率自动更新
- **数据校验：** AI自动校验数据完整性和合理性，异常数据标记

### 11.4 排名与公示

- **排名维度：** 社区内各小区排名 / 街道内各社区排名 / 区内各街道排名
- **排名展示：** 排名榜单 + 趋势图 + 优劣势分析
- **公示：** 指数结果可选择性公示（对内/对外）
- **预警：** 指数连续下降自动预警

## 十二、众包任务

### 12.1 功能概述

众包任务模块支撑社区端发布面向居民的任务（社区清洁、活动组织、物资募集等），居民在业主端认领并完成。

- **发布主体**：社区端、业委会端
- **任务类型**：环境维护、文明劝导、活动协助、物资募集、邻里互助
- **任务要素**：标题、描述、时间地点、人数上限、积分奖励
- **认领与完成**：居民在业主端浏览认领→完成后上传凭证→发布方确认→积分自动发放
- **信用联动**：完成众包任务的居民获得积分，纳入志愿者积分体系

## 十三、信用档案管理

### 13.1 功能概述

信用档案管理模块支撑社区端建立和维护物业企业信用档案和业委会信用档案，是"信用治理"理念的核心落地。信用档案数据作为物业选聘、业委会换届、评优评先的重要参考依据。

### 13.2 物业信用档案

- **档案内容：**
  - 基础信息：企业名称、资质等级、服务小区、合同期限
  - 履约记录：工单处理数据、考评结果、奖惩记录
  - 违规记录：制度违规、合同违约、行政处罚
  - 信用评分：系统自动计算的综合信用分
- **评分维度：**
  - 履约质量（40%）：工单完成率、满意度、考评得分
  - 合规守约（30%）：合同执行、制度遵守、整改配合
  - 社会责任（15%）：社区贡献、应急响应、公益参与
  - 财务规范（15%）：收费合规、公共收益管理、维修资金使用
- **更新机制：** 按月自动更新 + 重要事件实时更新
- **信用预警：** 信用分降至阈值以下自动预警

### 13.3 业委会信用档案

- **档案内容：**
  - 基础信息：业委会任期、成员构成、议事规则
  - 履职记录：会议出勤、决策参与、工单处理
  - 合规记录：负面清单自查、制度遵守情况
  - 财务记录：公共收益审核、维修资金审批合规性
  - 业主评价：满意度调查结果
- **评分维度：**
  - 履职尽责（30%）：会议出勤、决策参与、工单处理时效
  - 合规守纪（25%）：负面清单、议事规则遵守
  - 财务透明（25%）：公共收益公示、维修资金审批合规
  - 业主满意（20%）：业主满意度调查
- **更新机制：** 按季度更新 + 重大事项实时更新

### 13.4 档案应用

- **信用报告：** 一键生成物业/业委会信用报告（支持导出打印）
- **信用查询：** 授权方可在权限范围内查询信用档案
- **联动应用：**
  - 物业选聘/续聘/解聘的决策参考
  - 业委会换届选举的参考依据
  - 评优评先的资格审查
  - 上级部门检查的资料支撑

## 十四、全区治理态势大屏

### 14.1 功能概述

全区治理态势大屏是社区端的数据驾驶舱，以可视化大屏形式实时展示辖区内各小区的治理全貌，支撑社区领导快速掌握全局态势、发现风险隐患、进行科学决策。

### 14.2 大屏模块

| 模块 | 内容 | 展示形式 |
|:---|:---|:---|
| **工单态势** | 实时工单量、类型分布、处置进度、超时预警 | 数字卡片 + 实时滚动 + 热力图 |
| **矛盾调处** | 三级矛盾数量、调处成功率、热点区域 | 饼图 + 趋势图 + 地图标注 |
| **物业考评** | 各小区物业评分排名、评分趋势 | 排行榜 + 雷达图 |
| **业委会履职** | 各业委会履职评分、出勤率、负面清单 | 排行榜 + 仪表盘 |
| **公共收益** | 各小区公共收益收支总览、异常预警 | 柱状图 + 对比表 |
| **维修资金** | 维修资金使用总览、审批进度 | 数字卡片 + 进度条 |
| **信用评分** | 物业信用排名、业委会信用排名 | 排行榜 + 趋势线 |
| **协同共治指数** | 指数总览、各维度得分、排名变化 | 雷达图 + 排行榜 |
| **风险预警** | 超时工单、异常事件、信用下降等 | 预警列表 + 闪烁标记 |

### 14.3 风险预警

- **预警类型：**
  - 工单超时激增预警
  - 矛盾升级预警（重复投诉/群体事件）
  - 信用评分骤降预警
  - 公共收益异常预警
  - 制度违规预警
  - 群体性事件预警
- **预警级别：** 蓝（关注）/ 黄（注意）/ 橙（预警）/ 红（紧急）
- **预警推送：** 实时推送至大屏 + 社区负责人消息通知
- **处置跟踪：** 预警处置状态跟踪，闭环管理

### 14.4 跨部门监管

- **数据共享：** 按权限向街道/区级部门开放大屏数据
- **监管对接：** 对接住建、城管、消防、环保等部门监管系统
- **报表导出：** 一键导出各类统计报表，支撑向上级汇报

## 十五、生态关系

### 15.1 四端生态全景

```
业主端 ←→ 物业端（报修/投诉/工单处理）
业主端 ←→ 业委会端（投票/考评/监督）
业主端 ←→ 社区端（矛盾调解/吹哨/公告）
物业端 ←→ 业委会端（维修金审批/履约监督）
物业端 ←→ 社区端（派单/整改/考评备案）
业委会端 ←→ 社区端（三方协商/同步监督）
```

### 15.2 与各端详细关系

| 对端 | 关系类型 | 数据流向 | 核心交互 |
|:---|:---|:---|:---|
| **业主端** | 服务-响应 | 社区→业主：公告、通知、制度 | 居民查看公告、参与投票、提交投诉 |
| | | 业主→社区：投诉、建议、评价 | |
| **业委会端** | 指导-被指导 | 社区→业委会：制度、派单、指导 | 业委会接受社区指导、配合派单处理 |
| | | 业委会→社区：履职数据、备案 | 社区监督业委会履职 |
| **物业端** | 监督-被监督 | 社区→物业：制度、派单、考评 | 物业接受监督、配合处置 |
| | | 物业→社区：履约数据、申报 | |
| AI | 能力调用 | AI→社区：智能分派、风险预警、数据分析 | 社区调用AI能力辅助决策和管理 |
| **平台** | 上级监管 | 社区→运营：治理数据、态势报告 | 社区端数据上报平台，形成全区治理视图 |
| | | 运营→社区：监管要求、政策传达 | |

### 15.3 生态闭环

社区端在四端生态中承担"顶层设计+底线守护"的双重角色：

- **向上连接：** 对接街道/区级政府，承接上级治理要求和政策部署
- **向下指导：** 对业委会、物业进行制度供给和治理指导
- **横向协调：** 通过吹哨报到机制协调各职能部门力量
- **数据中枢：** 汇聚各端治理数据，通过态势大屏和协同共治指数呈现治理全貌
- **信用基石：** 建立和维护物业、业委会信用档案，为信用治理提供制度支撑

### 15.4 与业委会端的协同关系

```
社区端（制度供给）────────► 业委会端（制度执行）
社区端（派单督办）◄──────── 业委会端（工单处理）
社区端（考评监督）◄──────── 业委会端（履职数据）
社区端（矛盾调处）◄──────── 业委会端（矛盾上报）
社区端（信用档案）◄──────── 业委会端（信用数据）
```
