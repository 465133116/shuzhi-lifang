# 数治理方 · 业委会端 产品设计文档

> **端口：** 业委会端（PC端）
> **角色：** 业委会主任 / 业委会成员
> **定位：** 四端生态中的决策监督端 —— 代表全体业主行使监督权、决策权与公共事务管理权
> **品牌主题：** "如我在居·共享家"
> **对应政策文件：** 鄞社发〔2026〕6号
> **版本：** V1.0 实装版
> **更新日期：** 2026年7月

---

## 一、端口概述

### 1.1 四端生态定位

业委会端是"数治理方"四端生态中的**决策监督端**，居于业主端（服务使用端）与物业端（服务提供端）之间的治理枢纽位置。业委会端不直接提供物业服务，也不直接消费服务，而是代表全体业主行使以下核心权责：

- **监督权：** 对物业企业履约情况进行持续监督与考评
- **决策权：** 对公共收益使用、维修资金动用、重大事项进行集体决策
- **管理权：** 对小区公共事务进行制度化管理与信息公开

### 1.2 "如我在居·共享家"主题诠释

"如我在居"强调业委会成员以业主视角思考问题、以居住者身份感受服务；"共享家"强调小区治理的共有、共治、共享属性。业委会端的设计始终遵循这一理念，确保每一个功能都以"让小区变得更好"为出发点。

### 1.3 端口关系矩阵

| 功能 | 业主端 | 物业端 | 业委会端 | 社区端 |
|------|:--:|:--:|:--:|:--:|
| 投诉处理 | 提交投诉 | 被投诉方 | 接收+回复 | 同步可查 |
| 物业监督 | — | 被监督方 | 监督+督促 | 考评备案 |
| 维修金审批 | — | 申报方 | 审批方 | 大额备案 |
| 三方协商 | — | 参与方 | 发起+主持 | 参与方 |
| 投票管理 | 参与投票 | — | 发起+管理 | 监督 |
| 党员管理 | 报到参与 | — | 管理+记录 | 数据互通 |
| 公共收益 | 查看公示 | 收支管理 | 审核+监管 | 备案监督 |

### 1.4 设计原则

1. **透明原则：** 所有决策过程留痕、所有财务数据公开、所有投票结果可查
2. **制度原则：** 以制度而非人情驱动治理，关键节点内置合规校验
3. **效率原则：** 线上化替代跑腿、签字、纸质流转，减少业委会行政负担
4. **制衡原则：** 业委会受业主监督、受社区指导、受制度约束，不形成新的权力垄断

## 二、居业物三方协商

### 2.1 功能概述

居业物三方协商机制是本端口核心功能之一，支撑社区（居委会）、业委会、物业企业三方就小区公共事务进行制度化协商。系统提供完整的协商生命周期管理：发起 → 议程确认 → 会议召开 → 纪要签署 → 决议执行 → 跟踪闭环。

### 2.2 协商发起

- **发起权限：** 业委会主任/副主任可发起，经2名以上委员附议后生效
- **协商类型：**
  - 常规协商：季度/月度定期会议
  - 专项协商：针对特定事项（维修资金、公共收益、物业合同续签等）
  - 紧急协商：涉及安全、重大投诉等紧急事项（24h内召集）
- **参会方选择：** 从社区名录中选定居委会代表、从物业名录中选定物业负责人、从业委会内部选定参会委员
- **AI辅助：** 系统根据协商主题自动推荐议程模板，预填上次同类协商的未闭环事项

### 2.3 协商参与

- **议程共享：** 会前自动推送议程给所有参会方，支持在线预览、批注
- **资料签收：** 参会方在线签收会议资料，系统记录签收时间与人员
- **代理机制：** 业委会委员无法参会时可委托他人代理，代理关系在线登记
- **在线会议：** 集成线上会议能力（音视频+屏幕共享+文字聊天）
- **线下会议记录：** 支持会后补录线下会议纪要

### 2.4 协商决议

- **纪要生成：** AI辅助生成会议纪要，经参会各方在线确认/修订后定稿
- **决议表决：** 重大事项附表决环节，记录各方意见与表决结果
- **执行交办：** 决议中涉及物业执行的事项，一键生成交办工单，派往物业端
- **跟踪闭环：** 系统跟踪每项决议的执行进度，超时自动预警并抄送社区端

## 三、投诉/建议处理

### 3.1 功能概述

业委会端接收涉及业委会自身或其职责范围内的投诉件与建议件。工单来源包括：业主端直接提交、社区端转派、AI识别分派、物业端上报。业委会对工单进行研判、回复、处理、闭环。

### 3.2 工单接收与分类

- **工单来源：**
  - 业主投诉业委会不作为/乱作为 → 直接派入
  - 业主对物业不满意、要求业委会介入 → 转派
  - 社区端研判后转派的公共事务类工单
  - AI识别到需业委会介入的诉求 → 自动分派
- **工单分类：**
  - 投诉类：指向明确的不满/举报
  - 建议类：建设性意见/提案
  - 咨询类：政策/制度/决策解释需求
  - 举报类：涉及业委会成员违规行为的举报（加密通道）

### 3.3 工单处理流程

```
工单接收 → 业委会秘书初审 → 主任指派处理人 → 调查/核实 → 拟定回复
  → 主任审核 → 正式回复 → 业主确认 → 闭环归档
```

- **时限管理：** 按社区端配置的SLA标准计时，超时自动预警
- **AI辅助回复：** AI根据工单类型与历史回复数据，生成回复建议草案
- **升级机制：** 业委会超时未处理的工单，系统自动升级抄送社区端
- **不满意升级：** 业主对业委会处理结果不满意可追加反馈，同一工单追加>3次→自动升级至社区端介入

### 3.4 特殊通道

- **匿名举报：** 业主可选择匿名提交举报，系统对举报人身份加密
- **联名建议：** 支持业主联名（≥5人）提交建议，提高处理优先级
- **公开回复：** 对于具有公共参考价值的工单，业委会可选择脱敏后公开发布回复

## 四、业委会履职管理

### 4.1 功能概述

业委会履职管理模块实现业委会成员履职行为的全记录、全评价、全透明。既包括内部自我管理（履职记录、自查），也包括外部监督（业主评价、社区评价），形成完整的履职信用画像。

### 4.2 履职评价体系

- **评价维度：**
  - 出勤率：参加业委会会议、三方协商会议的频次
  - 工单处理：接收处理投诉/建议的时效与质量
  - 决策参与：对重大事项表决的参与度
  - 财务监督：公共收益审核、维修资金审批的参与度
  - 业主满意度：业主对业委会工作的满意度评分
- **评价来源：**
  - 系统自动统计（出勤、工单处理时效等客观数据）
  - 业主端评价（季度满意度调查）
  - 社区端评价（街道/社区对业委会履职的监督评价）
  - 业委会内部互评
- **评价结果应用：**
  - 履职积分排名（社区内/街道内）
  - 履职报告自动生成（年度/季度）
  - 作为换届选举的参考依据

### 4.3 负面清单自查

- **负面清单内容（依据鄞社发〔2026〕6号）：**
  - 擅自决定应由业主大会决定的事项
  - 未按规定公开公共收益收支
  - 未按规定组织业主大会会议
  - 违规使用维修资金
  - 利用职务之便谋取不正当利益
  - 阻挠业主行使权利
  - 其他违反法律法规和议事规则的行为
- **自查机制：**
  - 系统按月推送负面清单自查表
  - 业委会主任逐项勾选确认（是/否/不适用）
  - 自查结果留痕归档，供社区端查阅
  - 对"是"项，系统自动生成整改工单并跟踪

## 五、物业履约监督

### 5.1 功能概述

物业履约监督是业委会最核心的法定职责之一。本模块为业委会提供系统化、数据化、可追溯的物业履约监督工具，变"凭感觉监督"为"凭数据监督"。

### 5.2 监督维度

- **合同履约：** 对照物业服务合同条款，逐项检查履约情况
- **工单处理：** 查看全量工单处理数据（响应时长、完成率、返工率、满意度）
- **服务标准：** 对照服务等级标准（保洁频次、保安巡逻、绿化养护等）检查执行情况
- **财务合规：** 物业费收支、公共收益代收代管、维修资金使用等财务行为的合规性
- **人员资质：** 物业管理人员持证上岗、专业人员资质核查

### 5.3 监督工具

- **履约仪表盘：** 可视化展示物业履约核心指标（雷达图+趋势图）
- **工单全量查看：** 业委会可查看本小区所有工单（不限状态），但不干预物业内部派单
- **超时督办：** 超时工单自动标记"业委会已关注"，推送物业端，抄送社区端
- **预警工单：** 同一工单第3次派往物业时，系统自动向业委会端推送预警
- **履约报告：** 系统按月/季度自动生成物业履约评估报告

### 5.4 考评数据

- **考评来源：**
  - 系统自动统计的工单数据（权重40%）
  - 业主满意度调查（权重30%）
  - 业委会评价（权重20%）
  - 社区端评价（权重10%）
- **考评周期：** 月度评估 + 季度考评 + 年度总评
- **考评结果应用：**
  - 物业信用评分联动
  - 物业合同续签/解聘的决策参考
  - 向全体业主公示

## 六、公共收益监管

### 6.1 功能概述

公共收益监管模块实现小区公共收益（广告位租金、停车费、场地使用费、公共设施经营收入等）的全流程透明化管理。业委会通过本模块对公共收益的收支进行审核、监督、公示。

### 6.2 收益来源管理

- **收益登记：** 物业企业按月上报公共收益收入明细（来源、金额、合同/凭证）
- **合同关联：** 收益项目关联对应经营合同，业委会可在线查看合同条款
- **应收核对：** 系统自动比对合同约定金额与实际到账金额，异常自动预警

### 6.3 支出审核

- **支出申请：** 物业企业/业委会提交公共收益支出申请（用途、金额、依据）
- **审核流程：** 金额依合同约定分级审批——小额由主任审批、中额须业委会半数以上审议、大额须提交业主大会表决。具体阈值以各小区《业主大会议事规则》和《物业服务合同》为准
- **AI辅助审核：** AI自动比对支出申请与预算、历史支出、制度规定，提示异常
- **支出留痕：** 每笔支出完整留痕（申请→审核→审批→支付→凭证归档）

### 6.4 收益公示

- **月度公示：** 系统自动生成月度公共收益收支报表并公示
- **年度公示：** 年度公共收益收支总报表 + 审计报告
- **公示渠道：** 业主端、小区公告栏二维码、社区端同步
- **业主查询：** 业主可在线查看公共收益明细（按时间/类别/金额筛选）
- **异议处理：** 业主对公示内容有异议可在线提交，业委会限时回复

## 七、线上投票管理

### 7.1 功能概述

线上投票管理模块支撑业委会发起并管理各类线上投票，实现从议题提出到结果公示的完整线上化闭环。投票范围包括业委会内部表决和业主大会投票。

### 7.2 议题发起

- **发起权限：**
  - 业委会主任/副主任可发起议题
  - 经20%以上业主联名提议的议题，业委会必须发起投票
  - 社区端可建议发起议题
- **议题类型：**
  - 业委会内部表决（委员投票，简单多数/三分之二多数）
  - 业主大会投票（全体业主投票，双过半/双三分之二）
- **议题内容：** 议题标题、背景说明、方案选项、投票规则、起止时间
- **AI辅助：** 系统根据议题类型自动匹配适用法规条款，提示合规要求

### 7.3 投票管理

- **投票方式：**
  - 线上投票（业主端小程序，默认）
  - 线下投票补录（便于不熟悉智能设备的业主）
  - 代理投票登记（业主委托他人投票）
- **身份核验：** 投票须通过身份认证（业主认证 + 人脸比对），确保一人一票
- **实时统计：** 投票中实时显示参与人数/比例，不显示具体选项分布（防止从众效应）
- **防作弊：** 系统记录投票IP/设备/时间，异常投票自动标记
- **面积加权：** 需要面积+人数双指标的事项，系统自动按专有部分面积加权计算

### 7.4 结果公示

- **结果生成：** 投票结束后系统自动生成投票结果报告
- **公示内容：** 议题、选项、各选项得票数/得票比例/面积比例、是否通过
- **公示时间：** 按规定公示期依合同约定
- **异议期：** 公示期内业主可提出异议，业委会限时处理
- **归档：** 投票全流程数据归档，形成永久可查的投票档案

## 八、维修资金审批

### 8.1 功能概述

维修资金审批模块支撑业委会对住宅专项维修资金使用的审批管理。金额在授权额度内由业委会直接审批，超出授权额度须提交业主大会表决。系统自动校验授权额度，确保维修资金使用合法、合规、合理。

### 8.2 审批分级

| 条件 | 审批路径 | 责任主体 |
|:---|:---|:---|
| 金额≤业委会授权额度 | 物业申报 → 业委会审批 → 备案 | 业委会 |
| 金额>业委会授权额度 | 物业申报 → 业委会初审 → 业主大会表决 → 备案 | 全体业主 |

- **授权额度来源：** 业主大会决议或议事规则中明确规定的业委会可自行审批的维修资金上限，依合同约定
- **授权额度校验：** 系统自动读取授权额度，超额度申报自动路由至业主大会表决流程

### 8.3 审批流程

```
物业申报（方案+预算+合同） → AI额度校验 → 
  ├─ 额度内 → 业委会主任初审 → 业委会审议表决 → 审批通过/驳回
  └─ 超额度 → 业委会主任初审 → 业委会审议 → 发起业主大会投票 → 通过/驳回
```

- **申报材料：** 维修方案、工程预算、施工单位资质、合同草案、维修必要性说明
- **AI辅助审查：**
  - 预算合理性分析（对比同类工程市场价格）
  - 合同条款合规扫描
  - 施工单位信用核查
  - 多方案利弊对比
- **审批时限：** 授权轨15个工作日内完成，大会轨按业主大会召开周期

### 8.4 资金使用跟踪

- **拨付节点：** 按合同约定设置资金拨付节点（预付款→进度款→竣工款→质保金）
- **拨付条件：** 每个节点须满足预设条件（验收通过、业主确认等）
- **使用公示：** 维修资金使用情况实时同步至公共收益公示模块
- **审计对接：** 年度维修资金使用报告自动生成，对接审计

## 九、党员管理

### 9.1 功能概述

党员管理模块支撑业委会对小区内党员的报到登记、活动组织、服务记录等管理功能，落实"党建引领小区治理"要求，与社区端党员管理形成数据互通。

### 9.2 党员报到

- **报到入口：** 业主端提供党员身份标识入口，党员业主可主动报到
- **信息登记：** 党员基本信息（姓名、所属党支部、入党时间、特长/可提供服务类型）
- **信息核验：** 系统对接社区端党员台账进行身份核验
- **党员台账：** 业委会端维护小区党员台账，与社区端同步

### 9.3 服务记录

- **服务发布：** 业委会发布党员志愿服务活动（环境整治、邻里互助、政策宣传等）
- **在线报名：** 党员在线报名参与志愿服务活动
- **服务记录：** 系统记录党员参与活动的时间、内容、时长
- **积分联动：** 党员服务记录与社区端志愿者积分体系联动
- **先锋榜单：** 按季度/年度统计党员服务情况，生成先锋榜单

### 9.4 党建活动

- **主题党日：** 业委会可发起主题党日活动通知
- **学习资料：** 推送党建学习资料，记录学习完成情况
- **组织生活：** 支持在线党小组会议、民主评议等功能

---

## 十、公告管理

### 10.1 功能概述

公告管理模块支撑业委会向全体业主发布各类公告通知，实现公告的起草、审核、发布、查阅、归档全流程线上化。

### 10.2 公告类型

- **决议公告：** 业主大会/业委会会议决议
- **财务公告：** 公共收益收支、维修资金使用、年度财务报告
- **事务公告：** 物业合同续签/变更、重大维修通知、选举通知
- **制度公告：** 议事规则修订、管理规约更新
- **紧急公告：** 安全预警、停水停电通知、疫情防控

### 10.3 公告发布

- **起草：** 业委会成员在线起草公告，支持富文本编辑 + 附件上传
- **AI优化：** AI辅助润色公告文本，确保表述清晰、合规
- **审核：** 公告发布须经业委会主任审批（紧急公告除外）
- **发布渠道：**
  - 业主端小程序首页+消息推送（默认）
  - 小区公告栏二维码（线下）
  - 可选同步推送至社区端
- **已读追踪：** 系统追踪公告已读/未读状态，对未读业主可二次推送
- **评论互动：** 业主可在公告下留言提问，业委会在线回复

### 10.4 公告归档

- **自动归档：** 公告到期后自动归档，形成可检索的公告档案库
- **分类检索：** 按类型、时间、关键词检索历史公告
- **公示证明：** 系统生成公告发布证明（发布时间、渠道、已读数），用于合规证明

## 十一、社区论坛

### 11.1 功能概述

社区论坛为业委会端提供小区内部的话题讨论空间。业委会可在论坛中发布话题、参与讨论、收集民意，同时承担论坛管理职责。

### 11.2 话题管理

- **话题发布：** 业委会可发布讨论话题（如"小区绿化改造方案讨论"）
- **话题分类：** 物业服务、公共设施、社区活动、意见建议等
- **置顶/精华：** 重要话题可置顶，优质内容可设为精华
- **话题关闭：** 讨论结束后可关闭话题，保留内容但禁止新回复

### 11.3 内容管理

- **内容审核：** 业委会对论坛内容进行审核，违规内容可删除/屏蔽
- **违规处理：** 对违规用户可警告、禁言、封禁（需记录违规证据）
- **敏感词过滤：** 系统内置敏感词库，自动过滤违规内容
- **举报处理：** 受理业主举报的违规内容，限时处理并反馈结果

### 11.4 民意收集

- **投票帖：** 支持在论坛内发起简易投票，快速收集民意
- **热门话题：** 系统自动统计热门话题，帮助业委会了解业主关注焦点
- **舆情摘要：** AI自动生成论坛舆情周报/月报

---

## 十二、内部会议

### 12.1 功能概述

内部会议模块支撑业委会成员之间的专属会议管理，区别于三方协商会议（涉及社区和物业），内部会议仅限业委会成员参与，讨论业委会内部事务。

### 12.2 会议类型

- **定期会议：** 按议事规则规定的月度/季度例会
- **临时会议：** 由主任或三分之一以上委员提议召开的临时会议
- **专项会议：** 针对特定事项的专题讨论会

### 12.3 会议管理

- **会议发起：** 主任/副主任发起，选定参会委员，设定会议时间
- **议程管理：** 在线编辑会议议程，支持议程项排序、增加、删除
- **资料共享：** 会前上传会议资料，参会委员在线查阅
- **通知提醒：** 系统自动推送会议通知，临近开始时二次提醒

### 12.4 会议记录

- **在线会议：** 集成音视频会议 + 实时文字记录
- **决议记录：** 对每个议程项的讨论结论进行记录
- **表决记录：** 对需要表决的事项，记录每位委员的表决意见（同意/反对/弃权）
- **纪要生成：** AI辅助生成会议纪要，经参会委员确认后定稿

### 12.5 决议执行

- **交办生成：** 决议中涉及物业执行的事项，一键生成交办工单
- **任务分配：** 对业委会内部执行的事项，指派责任人并设定完成时限
- **跟踪闭环：** 系统跟踪每项决议任务的执行进度，超时预警

---

## 十三、履职信用档案

### 13.1 功能概述

履职信用档案模块为每一位业委会成员建立全生命周期的履职信用记录，是"信用治理"理念在业委会端的核心落地。档案内容涵盖议事规范遵守情况、公共收益动态记录、重大事项决策参与等。

### 13.2 议事规范记录

- **会议出勤：** 系统自动统计每位委员的会议出勤率
- **表决参与：** 记录每位委员对重大事项表决的参与情况
- **议事规则遵守：** 记录是否存在违反议事规则的行为（如利益冲突未回避）
- **发言贡献：** AI辅助分析委员在会议中的发言质量和贡献度

### 13.3 公共收益动态记录

- **审核参与：** 记录每位委员参与公共收益审核的频次和意见
- **异议提出：** 记录委员对公共收益收支提出的异议及处理结果
- **关联交易申报：** 委员与公共收益项目存在关联关系的申报记录

### 13.4 信用评分

- **评分维度：**
  - 履职出勤（权重20%）
  - 决策参与（权重25%）
  - 合规守纪（权重25%）
  - 业主评价（权重20%）
  - 社区评价（权重10%）
- **评分周期：** 季度评分 + 年度总评
- **结果应用：**
  - 在社区端信用档案同步
  - 作为换届选举的重要参考
  - 对外公示（脱敏处理）

## 十四、临时业主大会建议

### 14.1 功能概述

根据鄞社发〔2026〕6号文件精神，当特定条件触发时，系统自动建议业委会召开临时业主大会。本模块实现触发条件的自动监测、建议生成、大会议题准备等全流程支撑。

### 14.2 触发条件

系统自动监测以下触发条件，任一满足即生成临时业主大会建议：

- **人数触发：** 20%以上业主联名提议召开临时业主大会
- **事项触发：** 发生须由业主大会决定的重大事项（如选聘/解聘物业、大额维修资金使用）
- **紧急触发：** 发生危及安全的紧急情况须动用维修资金
- **周期触发：** 距上次业主大会已超过议事规则规定的最长间隔
- **罢免触发：** 20%以上业主联名提议罢免业委会成员

### 14.3 建议生成

- **自动监测：** 系统持续监测触发条件，条件满足时自动生成建议
- **建议内容：** 触发原因、法律依据、建议议题、建议时间、参考流程
- **推送对象：** 业委会全体成员 + 抄送社区端
- **响应时限：** 业委会须在规定时限内响应（启动筹备或说明不启动理由）

### 14.4 大会筹备

- **议题准备：** 系统根据触发原因自动生成建议议题清单
- **通知发布：** 一键生成业主大会通知，包含时间、地点、议题、表决事项
- **业主通知：** 多渠道通知（小程序推送+短信+公告栏），确保通知到位
- **流程指引：** 系统内置业主大会议事流程模板，逐步引导业委会完成筹备

## 十五、众包任务

业委会端可发布面向业主的众包任务，与社区端共享任务池：

- **发布主体**：业委会、社区端
- **任务类型**：小区环境维护、文明劝导、活动协助、邻里互助
- **任务要素**：标题、描述、时间地点、人数上限、积分奖励
- **认领与完成**：居民在业主端认领→完成上传凭证→发布方确认→积分发放
- **积分联动**：众包任务积分纳入居民积分体系

## 十六、生态关系

### 16.1 四端生态全景

```
业主端 ←→ 物业端（报修/投诉/工单处理）
业主端 ←→ 业委会端（投票/考评/监督）
业主端 ←→ 社区端（矛盾调解/吹哨/公告）
物业端 ←→ 业委会端（维修金审批/履约监督）
物业端 ←→ 社区端（派单/整改/考评备案）
业委会端 ←→ 社区端（三方协商/同步监督）
```

### 16.2 与各端详细关系

| 对端 | 关系类型 | 数据流向 | 核心交互 |
|:---|:---|:---|:---|
| **业主端** | 代表-被代表 | 业委会→业主：公示、投票、公告 | 业主查看公示、参与投票、提交投诉 |
| | | 业主→业委会：投诉、建议、评价 | |
| **物业端** | 监督-被监督 | 业委会→物业：考评、交办、督办 | 物业接受监督、提交履约数据、申报审批 |
| | | 物业→业委会：申报、履约数据 | |
| **社区端** | 接受指导-被监督 | 社区→业委会：制度、派单、指导 | 业委会接受社区指导、配合派单处理 |
| | | 业委会→社区：履职数据、备案 | |
| AI | 能力调用 | AI→业委会：合规扫描、文书生成、额度校验 | 业委会调用AI能力辅助决策 |
| **平台** | 数据上报 | 业委会履职数据上报平台 | 平台掌握全区业委会履职态势 |

### 16.3 生态闭环

业委会端在四端生态中承担"承上启下"的枢纽角色：

- **向上承接：** 社区端的制度供给与治理监督、业主端的需求与民意
- **向下传导：** 向物业端发出监督指令与履约要求
- **向内凝聚：** 通过投票、议事、论坛等功能凝聚业主共识
- **向外输出：** 向社区端、平台输出履职数据与治理成效
