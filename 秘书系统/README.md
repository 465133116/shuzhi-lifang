# 数治理方 · 秘书版

> 基于沪房物业〔2026〕36号的业委会秘书数字化操作系统  
> 版本：V1.0-secretary | 2026-07-02

---

## 这是什么

**秘书版**是数治理方平台中以"业委会秘书"角色为核心的独立版本。它围绕36号文第6条"业主委员会可以配备秘书"的政策依据，将秘书定位为**可外聘的专业执行角色**（不必是业主），构建了一套完整的权限体系和工作台。

## 与主版本的关系

| | 数治理方（主版） | 秘书版 |
|------|------|------|
| **定位** | 五端生态平台 | 秘书角色操作系统 |
| **用户** | 业主/物业/业委会/社区/AI | 秘书（主）+ 业委会/物业/居委/街镇/业主 |
| **核心** | 社区治理全链路 | 秘书工作台 + 权限体系 |
| **模式** | 在管/双轨/P1 三种 | 同三种，但以秘书为操作轴心 |
| **权限** | 分散在各端口 | 统一权限矩阵（本版新增） |

## 权限体系核心

### 七角色

| 角色 | 身份 | 政策依据 |
|------|:--:|----------|
| 秘书 | 外部聘请 | 第6条"配备" + 沪住建〔2018〕23号 |
| 业委会主任 | 业主（选举） | 第1/7条 |
| 业委会委员 | 业主（选举） | 第4条"业主担任" |
| 物业人员 | 外部 | 第6条 被监督方 |
| 居委人员 | 监督方 | 第15条 |
| 街镇人员 | 监管方 | 第3/15/17/18条 |
| 业主 | 服务对象 | 第8/16条 |

### 五级权限

`NONE(0) < VIEW(1) < CREATE(2) < EDIT(3) < APPROVE(4) < MANAGE(5)`

上一级自动继承下级权限。

### 核心原则

1. **秘书不决策**：权限上限 CREATE/EDIT，不能审批或管理
2. **政策溯源**：每项权限标注政策依据
3. **模式隔离**：三种模式同一套代码，不同模块开关
4. **多小区隔离**：community_id 数据租户隔离
5. **审批链不可绕过**：印章审批须经保管人→主任

## 快速使用

```javascript
// 引入权限模块
// <script src="config/permissions.js"></script>

var P = window.SGZF_Permissions;

// 检查：秘书能否在P1模式下创建工单？
P.checkPermission('secretary', 'workorder', 'wo_create', 'p1', P.LEVEL.CREATE);
// → true

// 检查：秘书能否审批印章？（不能）
P.checkPermission('secretary', 'seal', 'seal_approve', 'in_charge');
// → false（模块启用但权限级别不足）

// 检查：P1模式下印章模块是否启用？
P.isModuleEnabled('seal', 'p1');
// → false（P1模式印章冻结）

// 获取某角色在P1模式下可访问的模块
P.getAccessibleModules('secretary', 'p1');
// → ['reception', 'workorder', 'collection', 'sms', 'compliance']
```
